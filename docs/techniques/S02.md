# S02 Informative images

An image or icon that tells people something has a text alternative that
says the same thing, in a few words, without the word "image".

Code: [`lib/techniques/s02_informative_images/examples.dart`](../../lib/techniques/s02_informative_images/examples.dart).
Spec: [`docs/specs/S02-informative-images.md`](../specs/S02-informative-images.md).
In the app: `/t/S02`, and each example at `/t/S02/<slug>`.

Images that add nothing are covered by S03 Decorative images, and images
that are a control's whole content by S04 Functional images and
[C01 Button](C01.md).

## Why it matters

A screen reader cannot look at a picture. It reads the text alternative the
developer gave the image, and if there is none it has nothing to say: the
photo, the chart, or the status icon is missing for that person. An icon is
the easy one to forget. When a tick or a warning sign is the only thing that
says an order arrived or is late, that meaning has to be in text too.

A poor alternative is little better than none. A file name, or the words
"image of", spend the listener's time and tell them nothing.

## WCAG 2.2

- [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG22/#non-text-content): non-text content has a text alternative that serves the same purpose.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-image-label` | `Image(semanticLabel: 'Sunrise over green hills')`. The label says what the photo shows. | [iOS: Images](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/Images.md), [iOS: Informative Images](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/InformativeImages.md), [MDN: img](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img) |
| `good-icon-label` | `Icon(semanticLabel: 'Delivered')`, merged with the order's text by `MergeSemantics`, so each row is one element: "Delivered, Order 1042". | [Android Compose: Text Alternatives](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/content/TextAlternatives.md), [Android View: Text Alternatives](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/basics/TextAlternatives.md) |
| `good-group-description` | An icon and "6:35 am" that only make sense together. `Semantics(label: 'Sunrise at 6:35 am')` describes the pair, and `ExcludeSemantics` keeps the parts from being read as well. | Android Compose: Text Alternatives |
| `good-chart` | A chart drawn with `CustomPaint`, wrapped in `Semantics(image: true, label:)` with a short alternative that states its point. The numbers are in text below it. | Android Compose: Text Alternatives |

Write the alternative for someone who cannot see the image: what does it
show, or what does it mean here? Leave out "image of" and "picture of". The
advice not to use a file name is from
[iOS: Accessibility Label](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityLabel.md).

The examples show the photo with `Image.memory`, from a small PNG held in
code, so they need no asset path. `semanticLabel` is the same parameter on
`Image.asset` and `Image.network`.

### Shared code

Used by the examples below.

```dart
/// The example photo at a fixed size. `sunrisePng` is a small PNG held in
/// `example_image.dart`; `semanticLabel` works the same on `Image.asset` and
/// `Image.network`.
Widget _photo({String? semanticLabel}) {
  return Image.memory(
    sunrisePng,
    width: 192,
    height: 128,
    fit: BoxFit.cover,
    filterQuality: FilterQuality.none,
    semanticLabel: semanticLabel,
  );
}

/// One order in a list: a status icon and the order's name, read as one
/// element.
class _OrderRow extends StatelessWidget {
  const _OrderRow({required this.order, required this.icon, this.status});

  final String order;
  final IconData icon;

  /// The text alternative for the icon. Null leaves the icon with none.
  final String? status;

  @override
  Widget build(BuildContext context) {
    return MergeSemantics(
      child: Padding(
        padding: const EdgeInsets.symmetric(vertical: 8),
        child: Row(
          spacing: 12,
          children: [
            Icon(icon, semanticLabel: status),
            Expanded(child: Text(order)),
          ],
        ),
      ),
    );
  }
}
```

### `good-image-label`

```dart
/// `semanticLabel` is the image's text alternative. It says what the picture
/// shows, in a few words, without the word "image".
class GoodImageLabel extends StatelessWidget {
  const GoodImageLabel({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 12,
      children: [
        _photo(semanticLabel: 'Sunrise over green hills'),
        const Text('Taken from the east ridge trail.'),
      ],
    );
  }
}
```

### `good-group-description`

```dart
/// An icon and a short text that only make sense together. One description
/// replaces both: `Semantics(label:)` gives it, and `ExcludeSemantics` keeps
/// the parts from being read as well.
class GoodGroupDescription extends StatelessWidget {
  const GoodGroupDescription({super.key});

  @override
  Widget build(BuildContext context) {
    return Semantics(
      label: 'Sunrise at 6:35 am',
      child: const ExcludeSemantics(
        child: Row(
          mainAxisSize: MainAxisSize.min,
          spacing: 8,
          children: [Icon(Icons.wb_twilight), Text('6:35 am')],
        ),
      ),
    );
  }
}
```

### `good-chart`

```dart
/// A drawn chart is an image: `Semantics(image: true, label:)` gives it a
/// short alternative that states its point. The numbers are in the text
/// below it, for everyone.
class GoodChart extends StatelessWidget {
  const GoodChart({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 12,
      children: [
        Semantics(
          image: true,
          label: 'Bar chart: orders rose every quarter of 2025',
          child: CustomPaint(
            size: const Size(200, 100),
            painter: _BarChart(
              values: const [20, 35, 50, 80],
              color: Theme.of(context).colorScheme.primary,
            ),
          ),
        ),
        const Text('Orders in 2025: Q1 20, Q2 35, Q3 50, Q4 80.'),
      ],
    );
  }
}

class _BarChart extends CustomPainter {
  const _BarChart({required this.values, required this.color});

  final List<double> values;
  final Color color;

  @override
  void paint(Canvas canvas, Size size) {
    final paint = Paint()..color = color;
    final slot = size.width / values.length;
    for (var i = 0; i < values.length; i++) {
      final height = size.height * values[i] / 100;
      canvas.drawRect(
        Rect.fromLTWH(i * slot + 6, size.height - height, slot - 12, height),
        paint,
      );
    }
  }

  @override
  bool shouldRepaint(_BarChart old) =>
      old.color != color || old.values != values;
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `Image(semanticLabel:)` | `role="img"`, `aria-label` | `ImageView` with a description | image element with a label |
| Screen reader | "Sunrise over green hills image" (VoiceOver on macOS) | "Sunrise over green hills", "Image" (TalkBack) | "Sunrise over green hills Image" (VoiceOver) |
| `Semantics(image: true, label:)` on a `CustomPaint` | the same as an `Image` | the same | the same |
| `Icon(semanticLabel:)` | text, not an image | a node with a description, not an `ImageView` | static text, not an image |
| `Image` with no label | `role="img"` with no name | `ImageView` with no description | image element with no label |
| Screen reader, no label | "image" | "Unlabelled. Image" | skipped |
| `Icon` with no label | nothing | nothing | nothing |

Things to know:

- **An unlabelled `Image` is not hidden.** It is still in the tree as an
  image with no name. VoiceOver on macOS stops on it and says "image",
  TalkBack says "Unlabelled. Image" when moved to it, and VoiceOver on iOS
  skips it. An image that should be ignored has to be
  excluded on purpose, which is S03 Decorative images.
- **An `Icon` with a label is read as text.** No platform calls it an image.
  The meaning is conveyed, which is what counts.
- **A merged row keeps a line break between the icon's label and the text**
  ("Delivered", new line, "Order 1042"). The screen readers read it as one
  element.

Platform differences in the bad examples:

- `bad-role-in-label` is heard as a doubled role on all three: "Image of a
  sunrise over green hills image" (VoiceOver on macOS), "Image of a sunrise over green hills", "Image" (TalkBack),
  "Image of a sunrise over green hills Image" (VoiceOver on iOS).
- `bad-no-label` sounds different on each: "image" alone on web,
  "Unlabelled. Image" from TalkBack, and nothing on iOS.

## Flutter limitations

None found for this technique on Flutter 3.47.5.

HTML's `figure` and `figcaption` have no Flutter counterpart: there is no
figure role ([FL-026](../flutter-limitations.md#fl-026)). A caption is text
beside the image.
