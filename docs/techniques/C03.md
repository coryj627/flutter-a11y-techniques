# C03 Stand-alone link

A link on its own has the link role where the platform has one, a name that
says where it goes, and is followed once by a tap, by the keyboard, and by a
screen reader. A picture that is a link has the name on the link.

Code: [`lib/techniques/c03_stand_alone_link/examples.dart`](../../lib/techniques/c03_stand_alone_link/examples.dart).
Spec: [`docs/specs/C03-stand-alone-link.md`](../specs/C03-stand-alone-link.md).
In the app: `/t/C03`, and each example at `/t/C03/<slug>`.

Links inside a sentence are C04 Links inline with text. What a button is,
is [C01 Button](C01.md); picture buttons are [S04 Functional images](S04.md).

## Why it matters

People who use a screen reader often list a screen's links and pick one by
its name, with nothing around it. "Read more" tells them nothing there. The
role matters too: a link says "this takes you somewhere", a button "this
does something here".

Flutter has no link widget, in Material or in Cupertino. A link is made with
`Semantics(link: true, linkUrl:)`, and both parts are needed: without
`linkUrl`, Android reads the link as a button and the web's element is an
`<a>` with no `href`. With it, the web gets a real `<a href>`, and that
brings a second trap: the browser follows it by itself, so the app must not
follow it as well. Android has no link role at all, so there the link says what it is in its double-tap hint.

## WCAG 2.2

- [2.4.4 Link Purpose (In Context)](https://www.w3.org/TR/WCAG22/#link-purpose-in-context): the link's name says where it goes. A stand-alone link has no context to lean on. The criterion excepts a link whose purpose is "ambiguous to users in general": where nothing shown with the link says where it goes, as in `bad-vague-text`, nobody is worse off than anybody else and 2.4.4 is not shown to fail. Such a name does fail 2.4.9 Link Purpose (Link Only), a level AAA criterion, by [F84](https://www.w3.org/WAI/WCAG22/Techniques/failures/F84). 2.4.4 fails when sighted users get the purpose from something near the link that the accessibility tree does not relate to it ([F63](https://www.w3.org/WAI/WCAG22/Techniques/failures/F63)); a picture link with no name is [F89](https://www.w3.org/WAI/WCAG22/Techniques/failures/F89).
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the link has a name and a role that assistive technology can read.

Every good link draws a 3 pixel ring when it has keyboard focus, as in V14,
because `InkWell`'s own focus tint is under 3:1
([FL-430](../flutter-limitations.md#fl-430)).

What `Semantics` gives a link, and what it does not:

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `link: true` | an `<a>` with no `href`: no link role in HTML, though Chromium's own tree calls it a link | a `Button` | a link |
| `link: true` and `linkUrl` | `<a href>`, followed by the browser on a click, on Enter, and in a new tab on Command- or Ctrl-click | a `View`, the address in a `URLSpan`; TalkBack says no role | a link (`linkUrl` is not read) |
| Opening the address | the browser does it | not in the SDK | not in the SDK |

The SDK cannot open an address in the browser app off the web; that takes a
plugin, which this project does not use (D30). `url_launcher`'s `Link`
widget would not give the role off the web anyway: there it adds no
semantics, and its builder's `TextButton` is a button on Android and iOS
(probe fixture p12; source read). So every link here goes to a page of the
app, this technique's own, at `/t/C03`.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect |
| --- | --- |
| `bad-vague-text` | The link says "Read more". |

```dart
/// Where every link in these examples goes: this technique's own page in
/// the app.
const linkRoute = '/t/C03';

/// The link's address, for `Semantics(linkUrl:)`. On the web it becomes the
/// `href` of the link's `<a>` element. The app's web build keeps its route
/// after the `#`, so this address is the technique's page.
final linkAddress = Uri.parse('#$linkRoute');

/// The name of the links. It says where the link goes, on its own.
const linkText = 'Read about stand-alone links';

/// What TalkBack says a double tap does: "Double-tap to open link" in place
/// of "Double-tap to activate". Android has no link role, and TalkBack says
/// none for a Flutter link (docs/flutter-limitations.md, FL-220), so this is
/// what tells a TalkBack user it is a link, as the Android Compose reference
/// does with `onClickLabel`. `onTapHint` is used on Android only: iOS ignores
/// it, and the web engine does not read it.
const linkTapHint = 'open link';

/// What a tap on a link does. Off the web the app follows the link. On the
/// web the browser follows the link's `href` itself, on a click, on Enter,
/// and in a new tab on a Command- or Ctrl-click, so the app must not follow
/// it too: a click or Enter would then leave the screen as it was, and a
/// click with no pointer events would open the page twice
/// (docs/flutter-limitations.md, FL-013, and `bad-app-also-follows`).
void followLink(BuildContext context) {
  if (!kIsWeb) Navigator.of(context).pushNamed(linkRoute);
}

/// On the web, leaves Enter and Space to the browser. A Material `InkWell`
/// takes both keys, and a key it takes never reaches the link's `<a>`.
/// `DoNothingAndStopPropagationIntent` is a key binding that stops the key
/// in Flutter without handling it, so the browser does with it what it does
/// for any link: Enter follows it, Space scrolls the page. Off the web the
/// widget's own keys are left as they are.
class BrowserKeys extends StatelessWidget {
  const BrowserKeys({super.key, required this.child});

  final Widget child;

  @override
  Widget build(BuildContext context) {
    if (!kIsWeb) return child;
    return Shortcuts(
      shortcuts: const {
        SingleActivator(LogicalKeyboardKey.enter):
            DoNothingAndStopPropagationIntent(),
        SingleActivator(LogicalKeyboardKey.numpadEnter):
            DoNothingAndStopPropagationIntent(),
        SingleActivator(LogicalKeyboardKey.space):
            DoNothingAndStopPropagationIntent(),
      },
      child: child,
    );
  }
}

/// The look of link text: the theme's primary colour and an underline, so
/// that it is not told from other text by colour alone.
TextStyle linkStyle(BuildContext context) {
  final colors = Theme.of(context).colorScheme;
  return TextStyle(
    color: colors.primary,
    decoration: TextDecoration.underline,
    decorationColor: colors.primary,
  );
}

/// A 3 pixel ring in the colour of the page's text round [child] while
/// focus is on it or inside it, as in V14: `InkWell`'s own focus tint is
/// under 3:1 (docs/flutter-limitations.md, FL-430). The `Focus` here takes
/// no focus itself; it only hears when the link inside it gains or loses
/// focus.
class FocusRing extends StatefulWidget {
  const FocusRing({super.key, required this.child});

  final Widget child;

  @override
  State<FocusRing> createState() => _FocusRingState();
}

class _FocusRingState extends State<FocusRing> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Focus(
      canRequestFocus: false,
      skipTraversal: true,
      includeSemantics: false,
      onFocusChange: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          borderRadius: BorderRadius.circular(4),
          border: Border.all(
            color: _focused ? colors.onSurface : Colors.transparent,
            width: 3,
          ),
        ),
        child: widget.child,
      ),
    );
  }
}

/// A Material link: `Semantics(link: true, linkUrl:)` round an `InkWell`,
/// at least 48 pixels tall. [onTap] is what a tap does; the good examples
/// pass [followLink].
class MaterialLink extends StatelessWidget {
  const MaterialLink({
    super.key,
    required this.child,
    required this.onTap,
    this.url,
    this.label,
    this.browserKeys = true,
  });

  final Widget child;
  final VoidCallback onTap;
  final Uri? url;
  final String? label;

  /// Whether, on the web, Enter and Space go to the browser ([BrowserKeys]).
  /// Only a link with an address can be followed by the browser.
  final bool browserKeys;

  @override
  Widget build(BuildContext context) {
    final link = FocusRing(
      child: InkWell(
        onTap: onTap,
        child: ConstrainedBox(
          constraints: const BoxConstraints(minHeight: 48),
          child: Padding(
            padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 4),
            child: Align(
              alignment: AlignmentDirectional.centerStart,
              widthFactor: 1,
              heightFactor: 1,
              child: child,
            ),
          ),
        ),
      ),
    );
    return Semantics(
      link: true,
      linkUrl: url,
      label: label,
      onTapHint: linkTapHint,
      child: browserKeys ? BrowserKeys(child: link) : link,
    );
  }
}

/// Makes [child], which takes the taps, a link with keyboard focus:
/// `Semantics` gives the role and the address, and `FocusableActionDetector`
/// the focus and, off the web, Enter and Space. On the web it registers no
/// action for them, so the keys go to the browser, which follows the link
/// on Enter. [FocusRing] shows the focus.
class KeyboardLink extends StatelessWidget {
  const KeyboardLink({super.key, required this.onFollow, required this.child});

  final VoidCallback onFollow;
  final Widget child;

  Object? _follow(Intent intent) {
    onFollow();
    return null;
  }

  @override
  Widget build(BuildContext context) {
    // The ring goes outside the detector: the detector's own focus node is
    // the one that takes focus, and FocusRing hears only focus on itself or
    // below it.
    return FocusRing(
      child: FocusableActionDetector(
        mouseCursor: SystemMouseCursors.click,
        actions: kIsWeb
            ? const <Type, Action<Intent>>{}
            : {
                ActivateIntent: CallbackAction<ActivateIntent>(
                  onInvoke: _follow,
                ),
                ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
                  onInvoke: _follow,
                ),
              },
        child: Semantics(
          link: true,
          linkUrl: linkAddress,
          onTapHint: linkTapHint,
          child: child,
        ),
      ),
    );
  }
}

/// The example photo at the size of a small picture link. `sunrisePng` is
/// the small PNG from S02 (`example_image.dart`).
Widget picture({bool excludeFromSemantics = false, String? semanticLabel}) {
  return Image.memory(
    sunrisePng,
    width: 72,
    height: 48,
    fit: BoxFit.cover,
    filterQuality: FilterQuality.none,
    excludeFromSemantics: excludeFromSemantics,
    semanticLabel: semanticLabel,
  );
}
```

```dart
/// A link that says where it goes. `link: true` gives the link role on iOS.
/// `linkUrl` is needed as well: without it the link is a button on Android
/// and has no `href` on the web (docs/flutter-limitations.md, FL-032). With
/// it, the web has a real `<a href>`, and Android a node with no role, for
/// which `onTapHint` says it is a link (FL-220).

  const GoodMaterial({super.key});

  @override
  Widget build(BuildContext context) {
    return TestId(
      'c03-good-material-link',
      child: MaterialLink(
        url: linkAddress,
        onTap: () => followLink(context),
        child: Text(linkText, style: linkStyle(context)),
      ),
    );
  }
}
```

### `good-cupertino`

```dart
/// Cupertino has no link widget. The row it has for going to another screen
/// is `CupertinoListTile` with a chevron, which has no link role and takes
/// no keyboard focus (docs/flutter-limitations.md, FL-400). [KeyboardLink]
/// gives it both. A `CupertinoButton` would not do: it is always a button,
/// and a link round it is both (`bad-cupertino-button`).
class GoodCupertino extends StatelessWidget {
  const GoodCupertino({super.key});

  @override
  Widget build(BuildContext context) {
    return TestId(
      'c03-good-cupertino-link',
      child: KeyboardLink(
        onFollow: () => followLink(context),
        child: CupertinoListTile(
          // The tile cuts its title to one line with an ellipsis, through a
          // DefaultTextStyle with maxLines: 1. A DefaultTextStyle of the
          // title's own, with no line limit, lets the whole name wrap and
          // the row grow at large text sizes.
          title: Builder(
            builder: (context) {
              final tile = DefaultTextStyle.of(context);
              return DefaultTextStyle(
                style: tile.style,
                textAlign: tile.textAlign,
                child: const Text(linkText),
              );
            },
          ),
          trailing: const CupertinoListTileChevron(),
          onTap: () => followLink(context),
        ),
      ),
    );
  }
}
```

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A good link | `<a href="#/t/C03">`, role link; VoiceOver: "link Read about stand-alone links" | `android.view.View`, the address in a `URLSpan` on the content description, a click action labelled "open link" | link |
| Screen reader on it | "link Read about stand-alone links" | "Read about stand-alone links / Double-tap to open link" | "Read about stand-alone links Link" |
| A tap or click | the browser follows the `href` once; the app does nothing | the app opens the page | the app opens the page |
| Activation by assistive technology | a DOM click with no pointer events, in place of a screen reader: the browser follows it once | `ACTION_CLICK`, what TalkBack's double tap performs: the app opens the page | VoiceOver's double tap: the app opens the page |
| Tab, then Enter | the browser follows it | the app opens the page | the app opens the page |
| Space | nothing, as for any link | follows it in the widget tests (`InkWell` and `KeyboardLink` take it); not pressed on the emulator | as on Android; not pressed on the simulator |
| Command- or Ctrl-click | a new tab, and this one stays | | |
| `link: true`, no `linkUrl` (`bad-no-address`) | `<a>`, no `href`; Playwright finds no link, VoiceOver says "link …" | `Button`; "… / Button / Double-tap to open link" | link |
| A link round a `CupertinoButton` | one `<a href>`, role link | `Button`; "… / Button / Double-tap to activate" | button; "… Button Link" |
| Name on the `Image` inside | a link named from the image inside it | a link with no name and no address round the image; TalkBack reads the picture "… / Image" | "Link", then "… Image" |

Things to know:

- **Give a link `linkUrl`, even an app's own address.** Without it the web
  has no real link and Android a button
  ([FL-032](../flutter-limitations.md#fl-032)).
- **On the web, let the browser follow it.** A widget that also navigates
  on a tap competes with the browser, and the result depends on how the
  link was followed (`bad-app-also-follows`). `InkWell` takes Enter, so
  Enter has to be handed to the browser too (`BrowserKeys`).
- **Android has no link role.** TalkBack says none for a Flutter link, nor
  for a native view of the same shape in the probe
  ([FL-220](../flutter-limitations.md#fl-220)).
  `onTapHint` makes the double-tap hint say "open link", which is the
  Android Compose reference's way; iOS and the web ignore it.
- **Do not build a link from a button.** Flutter has no link widget, and a
  `CupertinoButton` or `TextButton` stays a button inside
  `Semantics(link: true)` ([FL-221](../flutter-limitations.md#fl-221)).
- **Name a picture link on the link**, and exclude the picture, as for a
  picture button in S04 ([FL-030](../flutter-limitations.md#fl-030)).
- **A wrong name passes every automated check.** `bad-vague-text` is a link
  with a name; only a person can tell that "Read more" says nothing.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-220](../flutter-limitations.md#fl-220): on Android a Flutter link says no role.
- [FL-221](../flutter-limitations.md#fl-221): Material and Cupertino have no link widget, and a link round one of their buttons is a button as well.
- [FL-013](../flutter-limitations.md#fl-013): on the web the browser follows a link's `href` as well as the app's `onTap`.
- [FL-032](../flutter-limitations.md#fl-032): `Semantics(link: true)` without `linkUrl` is a link on iOS only.
- [FL-030](../flutter-limitations.md#fl-030): a label on an `Image` inside a link does not name the link on Android and iOS.
- [FL-400](../flutter-limitations.md#fl-400): a `CupertinoListTile` takes no keyboard focus.
- [FL-430](../flutter-limitations.md#fl-430): `InkWell`'s focus tint is under 3:1.

Links are found by their `TestId`; `bad-label-on-image` has none, because
`TestId` merges what it wraps and would join the picture to the link. The
VoiceOver tests compare the whole list of what is spoken after the
"Example" heading, so they also show what is not spoken. On iOS the walk
goes to the end of the screen, where moving on repeats the last element, so
a stop after the link is seen and fails the comparison. TalkBack's check of
`bad-label-on-image` is on the picture only: a check of the unnamed link
round it would have to pass on silence, which a lost capture would also
pass, so nothing is claimed about that stop.
