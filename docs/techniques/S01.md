# S01 Accessible names

Every control has a name that assistive technology can read. The name is the
visible text where there is some, says what the control is for, is different
from the names of other controls, and does not repeat the role.

Code: [`lib/techniques/s01_accessible_names/examples.dart`](../../lib/techniques/s01_accessible_names/examples.dart).
Spec: [`docs/specs/S01-accessible-names.md`](../specs/S01-accessible-names.md).
In the app: `/t/S01`, and each example at `/t/S01/<slug>`.

This technique is about how a control gets its name, shown on checkboxes and
switches. Button names are in [C01 Button](C01.md) and text field labels in
[F01 Text fields and labels](F01.md).

## Why it matters

A screen reader announces a control as its name, its role, and its state:
"Dark mode, switch, off". Without the name it says "switch, off", and the
person has to guess what it switches. Speech input users say the name to
operate a control ("tap Dark mode"), so a control with no name, or a name
that is not the text on screen, cannot be operated by voice.

Text placed next to a control is not its name. A sighted person joins the two
by position; assistive technology needs them joined in the semantics tree.

The ARIA Authoring Practices Guide has the general rules for names, which
apply here too:
[Providing Accessible Names and Descriptions](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/).

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): the link between a control and its label is available programmatically.
- [2.4.6 Headings and Labels](https://www.w3.org/TR/WCAG22/#headings-and-labels): labels describe the purpose of the control.
- [2.5.3 Label in Name](https://www.w3.org/TR/WCAG22/#label-in-name): the name contains the visible text.
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): every control has a name.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-visible-label` | `CheckboxListTile` and `SwitchListTile` take the name from their `title`. The text and the control are one element, and the whole row operates it. | [CVS Compose: Interactive Control Labels](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/interactions/InteractiveControlLabels.md), [Flutter: CheckboxListTile](https://api.flutter.dev/flutter/material/CheckboxListTile-class.html) |
| `good-merged-label` | A control and its text laid out by hand, wrapped in `MergeSemantics`. A `GestureDetector` makes a tap on the text operate the control. | [Flutter: MergeSemantics](https://api.flutter.dev/flutter/widgets/MergeSemantics-class.html), [MDN: label](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/label) |
| `good-specific-names` | Two switches both show "Order updates". `Text(semanticsLabel:)` names them "Order updates, email" and "Order updates, text message": different, and each begins with the visible text. | [CVS iOS: Meaningful Accessible Names](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/MeaningfulAccessibleNames.md) |
| `good-cupertino` | A `CupertinoSwitch` has no label of its own; `MergeSemantics` joins it to the text beside it. | [CVS iOS: Accessibility Label](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityLabel.md) |

Prefer the visible text as the name. Reach for `semanticsLabel` only when the
visible text is not enough on its own, and start the name with the visible
text.

`MergeSemantics` joins the semantics but not the pointer target: without the
`GestureDetector`, a tap on the text does nothing.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unassociated-label` | "I accept the terms" sits beside the checkbox as a separate element. The checkbox has no name. | 1.3.1, 4.1.2 |
| `bad-duplicate-names` | Two switches are both named "Order updates". The headings above them do not help when a screen reader lists the controls or when someone says the name. | 2.4.6 |
| `bad-role-in-name` | The name is "Dark mode switch". The screen reader adds the role, so "switch" is heard twice. | — |
| `bad-slider-name-web` | A slider joined to its text in the same way as `good-merged-label`. On web it has no name (Flutter limitation). On Android and iOS it is named "Volume". | 4.1.2 on web |

### Shared code

Used by the examples below.

```dart
/// Holds the on or off state of the controls in one example, so people and
/// tests can confirm that a control still works after it has been named.
class _Toggles extends StatefulWidget {
  const _Toggles({required this.builder});

  final List<Widget> Function(
    bool Function(String key) isOn,
    void Function(String key) toggle,
  )
  builder;

  @override
  State<_Toggles> createState() => _TogglesState();
}

class _TogglesState extends State<_Toggles> {
  final Set<String> _on = {};

  void _toggle(String key) {
    setState(() => _on.contains(key) ? _on.remove(key) : _on.add(key));
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: widget.builder(_on.contains, _toggle),
    );
  }
}

/// A level 3 heading for a group of controls. The screen title is level 1
/// and the "Example" section is level 2.
class _GroupHeading extends StatelessWidget {
  const _GroupHeading(this.text);

  final String text;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.only(top: 8),
      child: Semantics(
        header: true,
        headingLevel: 3,
        child: Text(text, style: Theme.of(context).textTheme.titleMedium),
      ),
    );
  }
}
```

### `good-visible-label`

```dart
/// The list tile widgets take the control's name from the visible `title`.
/// The text and the control are one element: the name is the text people
/// see, and the whole row operates the control.
class GoodVisibleLabel extends StatelessWidget {
  const GoodVisibleLabel({super.key});

  @override
  Widget build(BuildContext context) {
    return _Toggles(
      builder: (isOn, toggle) => [

          's01-good-visible-label-updates',
          child: CheckboxListTile(
            title: const Text('Email me order updates'),
            value: isOn('updates'),
            onChanged: (_) => toggle('updates'),
          ),
        ),
        TestId(
          's01-good-visible-label-dark',
          child: SwitchListTile(
            title: const Text('Dark mode'),
            value: isOn('dark'),
            onChanged: (_) => toggle('dark'),
          ),
        ),
      ],
    );
  }
}
```

### `good-merged-label`

```dart
/// When a control and its visible text are laid out by hand, `MergeSemantics`
/// joins them into one element, so the text becomes the control's name. The
/// `GestureDetector` makes a tap on the text operate the control, as a tap
/// on an HTML `label` does.
class GoodMergedLabel extends StatelessWidget {
  const GoodMergedLabel({super.key});

  @override
  Widget build(BuildContext context) {
    return _Toggles(
      builder: (isOn, toggle) => [
        TestId(
          's01-good-merged-label-remember',
          child: MergeSemantics(
            child: GestureDetector(
              behavior: HitTestBehavior.opaque,
              onTap: () => toggle('remember'),
              child: Row(
                children: [
                  Checkbox(
                    value: isOn('remember'),
                    onChanged: (_) => toggle('remember'),
                  ),
                  const Expanded(child: Text('Remember this device')),
                ],
              ),
            ),
          ),
        ),
        TestId(
          's01-good-merged-label-wifi',
          child: MergeSemantics(
            child: GestureDetector(
              behavior: HitTestBehavior.opaque,
              onTap: () => toggle('wifi'),
              child: Row(
                children: [
                  const Expanded(child: Text('Wi-Fi')),
                  Switch(value: isOn('wifi'), onChanged: (_) => toggle('wifi')),
                ],
              ),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `bad-slider-name-web`

```dart
/// Flutter limitation FL-028: the slider is joined to its visible text in the
/// same way as the good examples, and is named "Volume" on Android and iOS.
/// On web the name is put on a wrapper element, not on the slider, so the
/// slider has no name there.
class BadSliderNameWeb extends StatefulWidget {
  const BadSliderNameWeb({super.key});

  @override
  State<BadSliderNameWeb> createState() => _BadSliderNameWebState();
}

class _BadSliderNameWebState extends State<BadSliderNameWeb> {
  double _volume = 0.4;

  @override
  Widget build(BuildContext context) {
    return TestId(
      's01-bad-slider-name-web-volume',
      child: MergeSemantics(
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            const Text('Volume'),
            Slider(
              value: _volume,
              // Ten steps, so one step up is 50% on every platform.
              divisions: 10,
              onChanged: (value) => setState(() => _volume = value),
            ),
          ],
        ),
      ),
    );
  }
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Named checkbox | `role="checkbox"`, `aria-label` | `CheckBox`, name in the description | switch element with a label (iOS has no checkbox type) |
| Named switch | `role="switch"`, `aria-label` | `Switch`, name in the description | switch element with a label |
| Screen reader, checkbox | "Email me order updates unchecked checkbox" (VoiceOver on macOS) | "Email me order updates", "Check box" (TalkBack) | "Email me order updates Switch button off" (VoiceOver) |
| Screen reader, switch | "Dark mode off switch" | "off", "Dark mode", "Switch" | "Dark mode Switch button off" |
| Checkbox with no name | "unchecked checkbox" (Chromium) | "Check box" | "Switch button off" |
| Named slider | no name: `aria-label` is on a wrapper, not on `input role="slider"` | `SeekBar`, description "40%, Volume" | label "Volume", value "40%" |
| Screen reader, slider | "Volume group", then "40% dimmed slider" (Chromium) | "40%", "Volume", "Slider" | "Volume 40% adjustable" |

Platform differences in the bad examples:

- `bad-role-in-name` is heard as a doubled role on all three: "Dark mode
  switch off switch" (VoiceOver on macOS), "Dark mode switch", "Switch"
  (TalkBack), and "Dark mode switch Switch button" (VoiceOver on iOS).
- `bad-unassociated-label` sounds fine in one place. With Playwright's
  WebKit build, VoiceOver on macOS reads "I accept the terms unchecked
  checkbox": it takes the text beside the checkbox as a guess at the name.
  In Chromium, on Android, and on iOS the checkbox is read with no name. A
  guess by one screen reader is not a name; the tree has none on any
  platform.
- `bad-slider-name-web` is a defect on web only. In Chromium, VoiceOver
  reads the wrapper as a group called "Volume" and then the slider as "40%
  dimmed slider": the name is a separate stop, not the slider's name, and
  the slider is read as dimmed. With Playwright's WebKit build, VoiceOver's
  cursor did not get past the screen title on this screen.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-028](../flutter-limitations.md#fl-028): a slider has no accessible name
  on web. Flutter puts the name on a wrapper element and not on the element
  with the slider role. No SDK workaround was found.
- [FL-029](../flutter-limitations.md#fl-029): a Material `Slider` adds an
  empty full-screen element on web that blocks a test tool's clicks on the
  rest of the screen. Its effect on people was not tested; the stuck
  VoiceOver cursor in WebKit may be the same thing.
