# F10 Slider

A slider sets a value in a range. It has the visible text beside it as its
name, a value in the words the screen uses, the arrow, Home, and End keys,
and a way to set it with a tap as well as a drag.

Code: [`lib/techniques/f10_slider/examples.dart`](../../lib/techniques/f10_slider/examples.dart).
Spec: [`docs/specs/F10-slider.md`](../specs/F10-slider.md).
In the app: `/t/F10`, and each example at `/t/F10/<slug>`.

How a value is worded in general is [S14 Values and state descriptions](S14.md);
a control's name is [S01 Accessible names](S01.md).

## Custom solutions

**Custom solution: not vetted by a real-world example.** `good-material`,
`good-cupertino`, `good-custom` and `good-value-text` are custom solutions.
Each is tested here in isolation, with screen-reader transcripts, but has
not been built into a real app and tested in a user journey. Do not treat
them as vetted techniques.

What is built by hand:

- `good-material`: Hand-built Home and End keys, a CallbackShortcuts round a
  Material Slider, which has neither (FL-122).
- `good-cupertino`: A keyboard built by hand for a CupertinoSlider, which
  takes no focus (FL-120): FocusableActionDetector with the APG keys, and
  buttons a step down and up.
- `good-custom`: A slider drawn by hand on Semantics(slider: true, value:,
  onIncrease:, onDecrease:), with focus and the APG keys from
  FocusableActionDetector.
- `good-value-text`: The hand-built Home and End keys of good-material
  (FL-122) round a Slider; the value text itself is the Slider's own
  semanticFormatterCallback.

The register of custom solutions, with the examples judged not to be one, is
[custom-solutions.md](../custom-solutions.md#f10-slider).

## Why it matters

A slider is a picture of a number: a track, a thumb, and how far along the
thumb sits. A screen reader user gets the number only if the slider says
what it sets, that it is a slider, and what its value is in words that fit
("4 out of 10", not "40%"). A keyboard user needs to reach it and move it
with the keys a slider is known to have. Anyone who cannot drag, because of
a tremor, a head pointer, or a switch, needs to set it with a single tap.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the slider's name, its role, and its value can be programmatically determined, and the value can be set by assistive technology.
- [2.5.7 Dragging Movements](https://www.w3.org/TR/WCAG22/#dragging-movements): a single pointer can set the slider without dragging.
- [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard): the keyboard reaches the slider and moves it.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unlabelled` | The text "Volume" above a `Slider`, not joined to it. The slider has no name: "40%, slider". | 4.1.2 |
| `bad-indicator-label` | `Slider(label: '4')`, the number shown above the thumb while it moves. `Slider` adds it to the name ([FL-123](../flutter-limitations.md#fl-123)). TalkBack reads "40%", "Volume 4", "Slider", and after a step "50%", "Volume 5": the value twice, once inside the name, and a name that changes at every step. | None by itself: a naming fault. The name still contains the visible label, so 2.5.3 Label in Name is met |
| `bad-percent-value` | A rating from 0 to 10 with no `semanticFormatterCallback`. The screen says "4 out of 10"; a screen reader says "40%". | 4.1.2 |
| `bad-no-keyboard` | `good-custom` without `FocusableActionDetector`. Flutter's focus order goes past it, and the keys never move it. On the web the browser's own Tab order can still land on its `<input>` when nothing follows it, and then Home and End move one step. | 2.1.1 |
| `bad-drag-only` | `good-custom` whose track does not answer a tap. Only a drag moves it. | 2.5.7 |

The keyboard and pointer defects are not heard: a screen reader reads and
adjusts `bad-no-keyboard` and `bad-drag-only` as it does `good-custom`.

/// Lays out one example and reports how many times its value changed, so
/// people and tests can confirm that the control worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('f10-${widget.slug}-count'),
          identifier: 'f10-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The volume as people read it: 0.4 is "40%".
String _percent(double volume) => '${(volume.clamp(0, 1) * 100).round()}%';

/// Home and End for an SDK slider, which has the arrow keys and not these
/// (docs/flutter-limitations.md, FL-122). [to] is called with the first or
/// the last value.
class _HomeAndEnd extends StatelessWidget {
  const _HomeAndEnd({
    required this.first,
    required this.last,
    required this.to,
    required this.child,
  });

  final double first;
  final double last;
  final ValueChanged<double> to;
  final Widget child;

  @override
  Widget build(BuildContext context) {
    return CallbackShortcuts(
      bindings: {
        const SingleActivator(LogicalKeyboardKey.home): () => to(first),
        const SingleActivator(LogicalKeyboardKey.end): () => to(last),
      },
      child: child,
    );
  }
}

/// A move asked for with the keyboard: one step up or down, or to an end.
class _StepIntent extends Intent {
  const _StepIntent(this.by);

  /// 1 or -1 for a step; [_toLast] or [_toFirst] for an end.
  final int by;
}

const _toLast = 1000;
const _toFirst = -1000;

/// The keyboard half of a slider and its focus ring, as the APG slider
/// pattern lays it out: Right and Up a step up, Left and Down a step down,
/// Home the first value, End the last. [onStep] gets 1, -1, [_toLast], or
/// [_toFirst]. It gives the control no role, no name, and no value.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onStep, required this.child});

  final ValueChanged<int> onStep;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      shortcuts: const {
        SingleActivator(LogicalKeyboardKey.arrowRight): _StepIntent(1),
        SingleActivator(LogicalKeyboardKey.arrowUp): _StepIntent(1),
        SingleActivator(LogicalKeyboardKey.arrowLeft): _StepIntent(-1),
        SingleActivator(LogicalKeyboardKey.arrowDown): _StepIntent(-1),
        SingleActivator(LogicalKeyboardKey.home): _StepIntent(_toFirst),
        SingleActivator(LogicalKeyboardKey.end): _StepIntent(_toLast),
      },
      actions: {
        _StepIntent: CallbackAction<_StepIntent>(
          onInvoke: (intent) => widget.onStep(intent.by),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A volume from 0 to 10 tenths, with what a key asks for applied to it.
int _stepped(int tenths, int by) => switch (by) {
  _toLast => 10,
  _toFirst => 0,
  _ => (tenths + by).clamp(0, 10),
};

/// A slider drawn by hand: a track, the part of it up to [tenths] filled,
/// and a thumb. Dragging along it sets the value; with [tapToSet] a tap on
/// the track does too. It has no semantics of its own.
class _DrawnSlider extends StatelessWidget {
  const _DrawnSlider({
    required this.tenths,
    required this.onSet,
    this.tapToSet = true,
  });

  final int tenths;
  final ValueChanged<int> onSet;
  final bool tapToSet;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return LayoutBuilder(
      builder: (context, constraints) {
        final width = constraints.maxWidth;
        int at(Offset position) =>
            (position.dx / width * 10).round().clamp(0, 10);
        return ExcludeSemantics(
          child: GestureDetector(
            behavior: HitTestBehavior.opaque,
            onTapUp: tapToSet ? (d) => onSet(at(d.localPosition)) : null,
            onHorizontalDragUpdate: (d) => onSet(at(d.localPosition)),
            child: SizedBox(
              width: width,
              height: 48,
              child: Stack(
                alignment: Alignment.centerLeft,
                children: [
                  Container(height: 4, color: colors.onSurfaceVariant),
                  FractionallySizedBox(
                    widthFactor: tenths / 10,
                    child: Container(height: 4, color: colors.primary),
                  ),
                  Align(
                    alignment: Alignment(tenths / 5 - 1, 0),
                    child: Container(
                      width: 24,
                      height: 24,
                      decoration: BoxDecoration(
                        shape: BoxShape.circle,
                        color: colors.primary,
                      ),
                    ),
                  ),
                ],
              ),
            ),
          ),
        );
      },
    );
  }
}

/// A volume slider drawn by hand and given its semantics: the slider flag,
/// the visible text as its name, its value, the values one step either
/// side, and the actions that take those steps. [keyboard] wraps it in
/// [_KeyboardOperable]; [tapToSet] is passed to [_DrawnSlider].
class _CustomVolume extends StatefulWidget {
  const _CustomVolume({
    required this.slug,
    this.keyboard = true,
    this.tapToSet = true,
  });

  final String slug;
  final bool keyboard;
  final bool tapToSet;

  @override
  State<_CustomVolume> createState() => _CustomVolumeState();
}

class _CustomVolumeState extends State<_CustomVolume> {
  int _tenths = 4;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: widget.slug,
      builder: (context, changed) {
        void set(int tenths) {
          if (tenths == _tenths) return;
          setState(() => _tenths = tenths);
          changed();
        }

        Widget slider = Semantics(
          slider: true,
          label: 'Volume',
          value: _percent(_tenths / 10),
          increasedValue: _percent(_stepped(_tenths, 1) / 10),
          decreasedValue: _percent(_stepped(_tenths, -1) / 10),
          onIncrease: () => set(_stepped(_tenths, 1)),
          onDecrease: () => set(_stepped(_tenths, -1)),
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.start,
            children: [
              const ExcludeSemantics(child: Text('Volume')),
              _DrawnSlider(
                tenths: _tenths,
                onSet: set,
                tapToSet: widget.tapToSet,
              ),
            ],
          ),
        );
        if (widget.keyboard) {
          slider = _KeyboardOperable(
            onStep: (by) => set(_stepped(_tenths, by)),
            child: slider,
          );
        }
        return [TestId('f10-${widget.slug}-volume', child: slider)];
      },
    );
  }
}

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A slider joined to its text | an element with `aria-label="Volume"` around an `<input type="range" role="slider">` with no name ([FL-028](../flutter-limitations.md#fl-028)), `aria-valuetext="40%"`, and a stand-in range of 0 to 2 ([FL-125](../flutter-limitations.md#fl-125)) | `SeekBar`, description "40%, Volume", no `RangeInfo` | adjustable element (type Other), label "Volume", value "40%" |
| Screen reader on it | "Volume group", "40% dimmed slider", "end of Volume group" (Chromium) | "40%", "Volume", "Slider", "Swipe up or Swipe down to adjust" | "Volume 40% adjustable", then the hint |
| With `semanticFormatterCallback` | `aria-valuetext="4 out of 10"` | "4 out of 10, Rating" | value "4 out of 10" |
| After one step up | `aria-valuetext="50%"`, the stand-in range moved up one | "50%, Volume" (FL-038) | value "50%" |
| A Material `Slider` on the screen | one empty element over the whole page ([FL-029](../flutter-limitations.md#fl-029)) | nothing extra | nothing extra |
| The text not joined (`bad-unlabelled`) | the text, then a slider with no group around it: "Volume", "40% dimmed slider" | "Volume", then "40%", "Slider" | "Volume", then "40% adjustable" |
| `Slider(label:)` (`bad-indicator-label`) | "Volume 4 group" | "40%", "Volume 4", and "Volume 5" after a step | "Volume 4 40% adjustable" |

TalkBack's lines are what it said with focus moved to each node by the
test. The web lines are VoiceOver on macOS in Playwright's Chromium build;
in its WebKit build VoiceOver's cursor left the page on every screen
with a Material `Slider`, reading only the page's web area, and read the Cupertino
and custom sliders as Chromium did.

Things to know:

- **Join the slider to its text.** A `Slider` has no label parameter;
  `MergeSemantics` (here `TestId`) around the text and the slider makes
  the text its name on Android and iOS. On the web nothing reaches the
  slider yet (FL-028): VoiceOver reads the text as a group around it.
- **Give the value words when a percentage is wrong.** `Slider` reports
  its value as a percentage of its range, whatever the range.
  `semanticFormatterCallback` changes that, and on the web the words are
  the only real value there is (FL-125).
- **Keep the value out of the name.** Leave `Slider.label` unset, and put
  a visible value in `ExcludeSemantics` (FL-123).
- **Add Home and End** with `CallbackShortcuts` around a `Slider`
  (FL-122), and give a `CupertinoSlider` or a custom slider the keyboard
  with `FocusableActionDetector` (FL-120).
- **Give a slider that only drags a single-pointer way to set it.** A
  Material `Slider` and the custom one here move to a tapped point; a
  `CupertinoSlider` does not (FL-121), so `good-cupertino` has step
  buttons.
- **"Dimmed" on the web**: VoiceOver says it for every Flutter slider,
  because the engine disables the slider's input for half a second after
  any pointer event (read in the source, and tested), and every VoiceOver
  walk here had pointer events, and every walk that read a slider left
  its input disabled
  ([FL-127](../flutter-limitations.md#fl-127)). The same markup in plain
  HTML, enabled, is read "40% slider", and with a label on the input
  "40% Volume slider".

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-028](../flutter-limitations.md#fl-028): on the web the slider element has no name; the label is on an element around it. No workaround. Flutter 3.50.0's source copies the label onto the slider; not run here.
- [FL-029](../flutter-limitations.md#fl-029): on the web a Material `Slider` adds an empty element over the whole page, which every hit test finds first. Mouse clicks, keys, and screen reader presses still work. No workaround for a Material `Slider`.
- [FL-120](../flutter-limitations.md#fl-120): a `CupertinoSlider` takes no keyboard focus. Workaround: `FocusableActionDetector`, as `good-cupertino` does.
- [FL-121](../flutter-limitations.md#fl-121): a `CupertinoSlider` moves only when its thumb is dragged. Workaround: step buttons, as `good-cupertino` has.
- [FL-122](../flutter-limitations.md#fl-122): a `Slider` has no Home or End, and on the web those keys move it one step. Workaround: `CallbackShortcuts`, as the Material examples do.
- [FL-123](../flutter-limitations.md#fl-123): `Slider.label` is added to the name (`bad-indicator-label`). No workaround but leaving it unset.
- [FL-124](../flutter-limitations.md#fl-124): a disabled slider is not a slider on any platform. No workaround; no example.
- [FL-125](../flutter-limitations.md#fl-125): on the web the slider's minimum, maximum, and current value are stand-ins of 0, 1, and 2; only the value text is real.
- [FL-126](../flutter-limitations.md#fl-126): a `RangeSlider` was probed and not built: two unnamed sliders on the web, one value when merged.
- [FL-127](../flutter-limitations.md#fl-127): on the web the slider's input is disabled for half a second after any pointer event, so VoiceOver calls every slider "dimmed". No workaround.
- [FL-037](../flutter-limitations.md#fl-037) and [FL-038](../flutter-limitations.md#fl-038) were checked for sliders: an enabled slider keeps its value apart from its name on the web, and on Android the value shown straight after an adjustment is right for the SDK's sliders.

## How it is tested

| Layer | Where | Run |
| --- | --- | --- |
| Widget tests | `test/techniques/f10_slider_test.dart` | `flutter test` |
| Web tree | `web_tests/f10_slider.spec.js` | `flutter build web`, then `npx playwright test f10_slider.spec.js` in `web_tests/` |
| Android tree | `android/app/src/androidTest/.../F10SliderTest.kt` | `python3 tool/evidence.py F10 --only android` |
| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py F10` |
| iOS tree | `ios/RunnerUITests/F10SliderUITests.swift` | `python3 tool/evidence.py F10 --only ios` |
| VoiceOver speech (iOS) | same test class, `testVoiceOverSpeech` | `python3 tool/voiceover_ios.py F10` |
| VoiceOver speech (web) | `web_tests/vo/f10_slider_vo.spec.js` | `python3 tool/voiceover_web.py F10`; takes over the screen |

The widget tests also check the SDK's sliders on their own, outside the
examples, so that each limitation above has a test that fails when Flutter
changes it. The keyboard is checked in the widget tests and on the web; on
Android a first try at sending keys with UI Automator did not move
Flutter's focus, and on iOS the keys are not sent.
