# C02 Toggle button

A button that stays pressed or not pressed exposes its name, a role, and
whether it is on, in both states, and its name does not change when its
state does.

Code: [`lib/techniques/c02_toggle_button/examples.dart`](../../lib/techniques/c02_toggle_button/examples.dart).
Spec: [`docs/specs/C02-toggle-button.md`](../specs/C02-toggle-button.md).
In the app: `/t/C02`, and each example at `/t/C02/<slug>`.

A plain button is [C01](C01.md), a switch [F09](F09.md), a checkbox
[F07](F07.md), and a set of buttons of which one is chosen a radio group,
[F08](F08.md). The spec says where the line is.

## Why it matters

A toggle button looks like any other button, and its state is in its
drawing: Bold is filled in while bold is on, Mute is filled in while the
microphone is off. A screen reader user gets only what the code says. If
the code says "button" and nothing more, they cannot tell that pressing it
turns something on, or whether it is on now, without pressing it and
working out what changed.

The name has to stay put, too. A button called "Mute" that turns into
"Unmute" when pressed is a fine plain button; but a toggle button that is
called "Unmute" and is "on" can be read either way, and someone who
learned it by its name, or uses voice control, finds a different name each
time.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the name and role of a toggle button can be programmatically determined, and its state, which the user sets, is exposed to assistive technology and kept up to date.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-icon-button` | `MergeSemantics(child: Semantics(toggled: on, child: IconButton(tooltip: 'Bold', style: ..., icon: ...)))`. `toggled` gives the state; `MergeSemantics` puts it on the button's node, which a Material button keeps apart. The pressed look is drawn with `style`, and `isSelected` is left out. | [APG: Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) (a toggle button tells assistive technology its state, on and off); [Flutter: SemanticsProperties.toggled](https://api.flutter.dev/flutter/semantics/SemanticsProperties/toggled.html); [Flutter: MergeSemantics](https://api.flutter.dev/flutter/widgets/MergeSemantics-class.html) |
| `good-toggle-buttons` | `ToggleButtons(isSelected: [...], onPressed: ..., children: [Icon(..., semanticLabel: 'Bold'), ...])`. Each button has a checked state and its icon's label as its name. | [Flutter: ToggleButtons](https://api.flutter.dev/flutter/material/ToggleButtons-class.html); APG: Button |
| `good-cupertino` | `Semantics(toggled: on, enabled: true, child: CupertinoButton(...))`, with an action for `ButtonActivateIntent` so that Enter works on the web. | APG: Button (Space and Enter); [iOS: Buttons](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/Buttons.md) (button states must be conveyed) |

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-selected-only` | `IconButton(isSelected: on, tooltip: 'Bold', ...)`, the Material toggle as it comes. While it is off it is read "Bold, button", as a button with no state is; while on, "selected", and on the web "current item". | 4.1.2 |
| `bad-no-state` | A toggle drawn by hand and exposed with `Semantics(button: true)`. It is read "Mute, button" whether it is on or off. | 4.1.2 |
| `bad-label-changes` | `good-icon-button` with the name "Mute", then "Unmute". The name changes with the state, and "Unmute" with "on" can be taken either way. | none (APG) |

```dart
/// Lays out one example and reports how many times its controls were
/// operated, so people and tests can confirm that they worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('c02-${widget.slug}-count'),
          identifier: 'c02-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The keyboard half of a custom control and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no state.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A toggle button drawn by hand: a box with a speaker and [text], filled
/// and with the speaker crossed out when [on]. It has no semantics of its
/// own.
class _DrawnToggle extends StatelessWidget {
  const _DrawnToggle({required this.text, required this.on});

  final String text;
  final bool on;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final foreground = on ? colors.onPrimary : colors.primary;
    return Container(
      constraints: const BoxConstraints(minHeight: 48, minWidth: 48),
      padding: const EdgeInsets.symmetric(horizontal: 16),
      decoration: BoxDecoration(
        color: on ? colors.primary : colors.surface,
        border: Border.all(color: colors.primary, width: 2),
      ),
      child: Row(
        mainAxisSize: MainAxisSize.min,
        spacing: 8,
        children: [
          Icon(on ? Icons.volume_off : Icons.volume_up, color: foreground),
          Flexible(
            child: Text(text, style: TextStyle(color: foreground)),
          ),
        ],
      ),
    );
  }
}

/// The look of an icon button that is pressed in: filled with the theme's
/// primary colour. Drawn by hand, not with `IconButton.isSelected`, which
/// would add a selected state (good-icon-button says why).
ButtonStyle _pressedLook(BuildContext context, {required bool on}) {
  final colors = Theme.of(context).colorScheme;
  return IconButton.styleFrom(
    backgroundColor: on ? colors.primary : null,
    foregroundColor: on ? colors.onPrimary : null,
  );
}

const _bold = 'Bold';
const _mute = 'Mute';
```

### `good-icon-button`

```dart
/// A Material icon button that stays pressed. Flutter has no pressed state,
/// so `toggled` gives the state: on or off, said in both states on every
/// platform, with the switch role (docs/flutter-limitations.md, FL-200).
/// `MergeSemantics` puts it on the button's own node, which a Material
/// button keeps apart (FL-040); `TestId` would do it too, but the example
/// must not depend on the test's wrapper. `isSelected` is left out: alone
/// it says nothing while the button is off (bad-selected-only, FL-201),
/// and beside `toggled` TalkBack says "selected. checked. on." So the
/// pressed look is drawn here: the filled icon on the primary colour.
class GoodIconButton extends StatefulWidget {
  const GoodIconButton({super.key});

  @override
  State<GoodIconButton> createState() => _GoodIconButtonState();
}

class _GoodIconButtonState extends State<GoodIconButton> {
  bool _on = false;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-icon-button',
      builder: (context, changed) => [
        TestId(
          'c02-good-icon-button-bold',
          child: MergeSemantics(
            child: Semantics(
              toggled: _on,
              child: IconButton(
                tooltip: _bold,
                style: _pressedLook(context, on: _on),
                icon: Icon(
                  _on ? Icons.format_bold : Icons.format_bold_outlined,
                ),
                onPressed: () {
                  setState(() => _on = !_on);
                  changed();
                },
              ),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `good-toggle-buttons`

```dart
/// A row of Material toggle buttons. `ToggleButtons` gives each button a
/// checked state, so each is a checkbox on Android and the web and a switch
/// on iOS, with its state said on and off (on Android, only when on:
/// FL-045). Each icon's `semanticLabel` is its button's name. The
/// identifiers are on the icons, inside the buttons' own `MergeSemantics`,
/// so that the three stay separate.
class GoodToggleButtons extends StatefulWidget {
  const GoodToggleButtons({super.key});

  @override
  State<GoodToggleButtons> createState() => _GoodToggleButtonsState();
}

class _GoodToggleButtonsState extends State<GoodToggleButtons> {
  final _on = [false, false, false];

  @override
  Widget build(BuildContext context) {
    Widget icon(String name, IconData data) {
      final id = 'c02-good-toggle-buttons-${name.toLowerCase()}';
      return Semantics(
        key: ValueKey<String>(id),
        identifier: id,
        child: Icon(data, semanticLabel: name),
      );
    }

    return _Demo(
      slug: 'good-toggle-buttons',
      builder: (context, changed) => [
        ToggleButtons(
          isSelected: _on,
          onPressed: (index) {
            setState(() => _on[index] = !_on[index]);
            changed();
          },
          children: [
            icon(_bold, Icons.format_bold),
            icon('Italic', Icons.format_italic),
            icon('Underline', Icons.format_underline),
          ],
        ),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// A Cupertino button that stays pressed. Cupertino has no toggle button,
/// so the state is `toggled`, as in good-icon-button; a `CupertinoButton`
/// has no node boundary of its own, so the state lands on its node. It
/// needs `enabled: true` as well: a `CupertinoButton` sets no enabled
/// state (FL-001), and VoiceOver on iOS reads a toggled node without one
/// as dimmed (FL-033). Enter on the web needs an action of its own
/// (FL-002).
class GoodCupertino extends StatefulWidget {
  const GoodCupertino({super.key});

  @override
  State<GoodCupertino> createState() => _GoodCupertinoState();
}

class _GoodCupertinoState extends State<GoodCupertino> {
  bool _on = false;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-cupertino',
      builder: (context, changed) {
        void toggle() {
          setState(() => _on = !_on);
          changed();
        }

        return [
          TestId(
            'c02-good-cupertino-mute',
            child: Semantics(
              toggled: _on,
              enabled: true,
              child: Actions(
                actions: {
                  ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
                    onInvoke: (_) {
                      toggle();
                      return null;
                    },
                  ),
                },
                child: CupertinoButton(
                  color: _on ? CupertinoColors.label : null,
                  onPressed: toggle,
                  child: Row(
                    mainAxisSize: MainAxisSize.min,
                    spacing: 8,
                    children: [
                      Icon(
                        _on
                            ? CupertinoIcons.speaker_slash_fill
                            : CupertinoIcons.speaker_2_fill,
                      ),
                      const Text(_mute),
                    ],
                  ),
                ),
              ),
            ),
          ),
        ];
      },
    );
  }
}
```

```dart
      slug: 'good-custom',

          setState(() => _on = !_on);
          changed();
        }

        return [
          TestId(
            'c02-good-custom-mute',
            child: _KeyboardOperable(
              onActivate: toggle,
              child: Semantics(
                button: true,
                toggled: _on,
                enabled: true,
                label: _mute,

                  onTap: toggle,
                  child: ExcludeSemantics(

                ),
              ),
            ),
          ),
        ];
      },
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `toggled` (`good-icon-button`, `good-cupertino`, `good-custom`) | `role="switch"`, `aria-checked` | `Switch`, checkable, checked or not | switch, value 0 or 1 |
| Screen reader, off | "Bold off switch" | "off. Bold. Switch" | "Bold Switch button off" |
| Screen reader, on | "Bold on switch" | "checked. on. Bold. Switch" | "Bold Switch button on" |
| `ToggleButtons` (`checked`) | `role="checkbox"`, `aria-checked` | `CheckBox`, checkable, checked or not | switch, value 0 or 1 |
| Screen reader, off | "Bold unchecked checkbox" | "Bold, Check box" | "Bold Switch button off" |
| Screen reader, on | "Bold checked checkbox" | "checked. Bold, Check box" | "Bold Switch button on" |
| `IconButton(isSelected:)` (`bad-selected-only`) | `role="button"`, `aria-current` | `Button`, selected or not | button, selected or not |
| Screen reader, off | "Bold button" | "Bold. Button" | "Bold Button" |
| Screen reader, on | "Bold current item button" | "selected. Bold. Button" | "selected Bold Button" |
| No state (`bad-no-state`) | `role="button"` | `Button` | button |
| Screen reader, off and on | "Mute button" | "Mute, Button" | "Mute Button" |

TalkBack's lines are what it said with focus moved to each control by the
test, before and after one change. The iOS test API returns the first 64
characters of an utterance, and every VoiceOver line on iOS also ends
"Double tap to toggle setting." for a switch. The web lines are VoiceOver
on macOS, the same in Chromium and WebKit. Nothing in the table is read
as a toggle button: Flutter has no pressed state.

Things to know:

- **Give a toggle button `toggled`.** It is the one state that every
  platform says when it is off as well as when it is on. The role heard is
  "switch", not "toggle button" ([FL-200](../flutter-limitations.md#fl-200));
  TalkBack reads a native Android toggle button as a switch too, and
  VoiceOver reads a UIKit button with the toggle button trait as a
  "Switch button".
- **Do not rely on `IconButton.isSelected`.** It is the Material toggle,
  and it reaches assistive technology as "selected", which is silent while
  the button is off and is "current item" on the web
  ([FL-201](../flutter-limitations.md#fl-201)). Beside `toggled` it makes
  TalkBack say the state three ways, so draw the pressed look with
  `style` instead.
- **Merge `toggled` with a Material button.** A Material button keeps its
  own node, so a `Semantics` around it is a second node with no name
  unless `MergeSemantics` joins them
  ([FL-040](../flutter-limitations.md#fl-040)), as `good-icon-button`
  does. Around a `CupertinoButton` it joins by itself.
- **Give `enabled: true` to a toggle with no enabled state of its own**:
  a `CupertinoButton` or a control drawn by hand. Without it VoiceOver on
  iOS reads it as dimmed ([FL-033](../flutter-limitations.md#fl-033)).
- **Add Enter to a `CupertinoButton` on the web**
  ([FL-002](../flutter-limitations.md#fl-002)). APG requires both Space
  and Enter for a button.
- **`ToggleButtons` is a checkbox**, and a switch on iOS
  ([FL-035](../flutter-limitations.md#fl-035)). TalkBack does not say
  "not checked" for one that is off
  ([FL-045](../flutter-limitations.md#fl-045)).
- **Keep the name the same in both states.** "Mute" stays "Mute"; the
  state says whether it is on. If the name has to say what the next press
  does ("Play", "Pause"), make it a plain button with no state
  ([C01](C01.md)).
- On the web, HTML's own toggle button is a `button` with
  [`aria-pressed`](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-pressed);
  the VoiceOver transcript has a plain HTML page with one, read for
  comparison (`control-html`).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-200](../flutter-limitations.md#fl-200): Flutter has no pressed state. A toggle button can be a switch, a checkbox, or a button that is selected, never a toggle button. The examples use the switch.
- [FL-201](../flutter-limitations.md#fl-201): `IconButton(isSelected:)` and a multi-select `SegmentedButton` say nothing while off, and are "current item" on the web. `bad-selected-only`.
- [FL-040](../flutter-limitations.md#fl-040): a `Semantics` around a Material button stays on a node of its own unless merged; C02 adds `toggled` to what it affects.
- [FL-033](../flutter-limitations.md#fl-033): a toggled node with no `enabled` flag is read as dimmed on iOS.
- [FL-001](../flutter-limitations.md#fl-001): a `CupertinoButton` sets no enabled state, so `good-cupertino` sets it.
- [FL-002](../flutter-limitations.md#fl-002): Enter does not activate a `CupertinoButton` on the web.
- [FL-035](../flutter-limitations.md#fl-035) and [FL-045](../flutter-limitations.md#fl-045): a checked state is a switch on iOS, and TalkBack says nothing for one that is not checked.
- [FL-100](../flutter-limitations.md#fl-100): TalkBack says "checked" as well as "on" for a toggled node that is on.
