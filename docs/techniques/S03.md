# S03 Decorative images

An image or icon that adds nothing to the text around it is kept out of the
semantics tree, so a screen reader does not stop on it.

Code: [`lib/techniques/s03_decorative_images/examples.dart`](../../lib/techniques/s03_decorative_images/examples.dart).
Spec: [`docs/specs/S03-decorative-images.md`](../specs/S03-decorative-images.md).
In the app: `/t/S03`, and each example at `/t/S03/<slug>`.

Images that tell people something are covered by
[S02 Informative images](S02.md), and images that are a control's whole
content by S04 Functional images and [C01 Button](C01.md).

## Why it matters

A banner, a flourish, or an icon beside the word it illustrates gives a
sighted person nothing to read. A screen reader user should get the same
nothing. If the picture is left in the accessibility tree, the screen reader
may stop on it and say only "image", and the listener cannot tell whether
they are missing something. If the picture is given a label that repeats the
text beside it, they hear everything twice.

In Flutter the trap is `Image`. An `Image` with no `semanticLabel` is not
hidden: it is still in the tree, as an image with no name. HTML's habit of
an empty `alt` does not carry over either, because an empty `semanticLabel`
does the same. The image has to be excluded.

Whether a picture is decorative is a judgement. If it sets a mood that a
listener would otherwise miss, a short description may be the better
choice; see S02.

## WCAG 2.2

- [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG22/#non-text-content): pure decoration is implemented so that assistive technology can ignore it. A decorative image that cannot be ignored is failure [F38](https://www.w3.org/WAI/WCAG22/Techniques/failures/F38).

Which mechanism to use:

| What is decorative | Mechanism |
| --- | --- |
| An `Image` | `excludeFromSemantics: true` |
| An `Icon` | Leave `semanticLabel` off |
| A picture behind or around content | `DecorationImage` |
| Something drawn with `CustomPaint` | Nothing, when the painter has no [`semanticsBuilder`](https://api.flutter.dev/flutter/rendering/CustomPainter/semanticsBuilder.html) and no child with semantics. Otherwise wrap it in `ExcludeSemantics` |
| Any other widget | Wrap it in `ExcludeSemantics` |

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-not-excluded` | The banner has no `semanticLabel` and is not excluded. It is exposed as an image with no name. | 1.1.1 (F38), where a screen reader stops on it |
| `bad-empty-label` | The banner has `semanticLabel: ''`. An empty label does not hide the image: it is exposed exactly as in `bad-not-excluded`. | 1.1.1 (F38), where a screen reader stops on it |
| `bad-redundant-label` | Each icon has a `semanticLabel` that repeats the word beside it: "Shipping, Shipping, Returns, Returns". | — |

### Shared code

Used by the examples below.

```dart
/// A strip of the example photo used as decoration. `sunrisePng` is the
/// small PNG from S02 (`example_image.dart`).
Widget _banner({bool excludeFromSemantics = false, String? semanticLabel}) {
  return Image.memory(
    sunrisePng,
    width: 240,
    height: 48,
    fit: BoxFit.cover,
    filterQuality: FilterQuality.none,
    excludeFromSemantics: excludeFromSemantics,
    semanticLabel: semanticLabel,
  );
}

/// Two lines of text with a decorative banner between them. The banner adds
/// nothing the text does not say.
class _Welcome extends StatelessWidget {
  const _Welcome({required this.banner});

  final Widget banner;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 12,
      children: [
        const Text('Welcome back, Ana.'),
        banner,
        const Text('You have 2 new messages.'),
      ],
    );
  }
}

/// An icon beside the word it illustrates.
class _TopicRow extends StatelessWidget {
  const _TopicRow({required this.icon, required this.text, this.iconLabel});

  final IconData icon;
  final String text;

  /// A text alternative for the icon. Null leaves the icon with none, which
  /// is right when the text beside it says the same thing.
  final String? iconLabel;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.symmetric(vertical: 8),
      child: Row(
        spacing: 12,
        children: [
          Icon(icon, semanticLabel: iconLabel),
          Expanded(child: Text(text)),
        ],
      ),
    );
  }
}

/// Icon rows followed by a line of plain text.
class _Topics extends StatelessWidget {
  const _Topics({required this.labelIcons});

  /// Whether each icon gets a text alternative that repeats its word.
  final bool labelIcons;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        _TopicRow(
          icon: Icons.local_shipping,
          text: 'Shipping',
          iconLabel: labelIcons ? 'Shipping' : null,
        ),
        _TopicRow(
          icon: Icons.replay,
          text: 'Returns',
          iconLabel: labelIcons ? 'Returns' : null,
        ),
        const Text('Delivery takes 2 to 4 days.'),
      ],
    );
  }
}

/// A small picture beside two lines of text, read as one element.
class _GuideRow extends StatelessWidget {
  const _GuideRow({required this.excludeImage});

  final bool excludeImage;

  @override
  Widget build(BuildContext context) {
    return MergeSemantics(
      child: Row(
        spacing: 12,
        children: [
          Image.memory(
            sunrisePng,
            width: 72,
            height: 48,
            fit: BoxFit.cover,
            filterQuality: FilterQuality.none,
            excludeFromSemantics: excludeImage,
          ),
          const Expanded(
            child: Column(
              crossAxisAlignment: CrossAxisAlignment.start,
              children: [Text('Trail guide'), Text('12 routes')],
            ),
          ),
        ],
      ),
    );
  }
}
```

### `good-image-excluded`

```dart
/// `excludeFromSemantics: true` keeps a decorative `Image` out of the
/// semantics tree. Leaving `semanticLabel` off is not enough: the image
/// would still be there, with no name.
class GoodImageExcluded extends StatelessWidget {
  const GoodImageExcluded({super.key});

  @override
  Widget build(BuildContext context) {
    return _Welcome(banner: _banner(excludeFromSemantics: true));

}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `Image(excludeFromSemantics: true)` | nothing | nothing | nothing |
| `Icon` with no label | nothing | nothing | nothing |
| `DecorationImage`, `CircleAvatar(backgroundImage:)` | nothing | nothing | nothing |
| Anything inside `ExcludeSemantics` | nothing | nothing | nothing |
| `Image` with no label, or with `semanticLabel: ''` | `role="img"` with no name | `ImageView` with no description, not focusable | image element with no label |
| Screen reader on that image | "image" (VoiceOver on macOS stops on it) | "Unlabelled. Image" when TalkBack focus is moved to it | skipped by VoiceOver when swiping |
| Unlabelled `Image` inside `MergeSemantics` with text | `role="img"` named by the text | `ImageView` described by the text | image element labelled by the text |
| Screen reader on that row | "Trail guide 12 routes image" | "Trail guide 12 routes", "Image" | "Trail guide 12 routes Image" |
| `Icon(semanticLabel:)` beside the same word | the word twice, as two texts | two nodes | two static texts |
| Screen reader on that pair | two stops; see below | "Shipping" on each node | "Shipping", "Shipping" |

Things to know:

- **An unlabelled `Image` is not hidden, and an empty label does not hide
  it.** Both leave an image with no name in the tree. `alt=""` has no
  counterpart in `semanticLabel`; the counterpart is
  `excludeFromSemantics: true`.
- **The unnamed image is only certain to be heard on web.** VoiceOver on
  macOS stops on it and says "image". VoiceOver on iOS skips it when
  swiping, so `bad-not-excluded` and `bad-empty-label` sound the same as the
  good example there. On Android the node is not focusable; TalkBack says
  "Unlabelled. Image" when focus is moved to it by the test, and whether a
  swipe stops on it was not tested. The image is a defect on all three,
  because it is in the tree with nothing to say.
- **An image flag spreads through `MergeSemantics`.** One unlabelled
  `Image` in a merged row makes the whole row an image, on all three
  platforms. Exclude the picture and the row is plain text again.
- **The doubled word on web is recorded as an extra stop.** VoiceOver on
  macOS makes two stops for each row of `bad-redundant-label`, where the
  good example has one. The capture tool (Guidepup) reports no new phrase
  at the second stop, so the transcript shows it as empty; the tree test
  shows the two elements there have the same text.
- **`Icon(semanticLabel: '')` is not the same as no label on Android.** In
  the probe it left an empty, unfocusable node there, and nothing on web or
  iOS. Leave the parameter off.

## Flutter limitations

None found for this technique on Flutter 3.47.5.

That an unlabelled `Image` stays in the tree is how `Image` is documented to
work ([`excludeFromSemantics`](https://api.flutter.dev/flutter/widgets/Image/excludeFromSemantics.html)),
not a defect, so it is not logged as a limitation. It is the reason this
technique exists.

Elements are found by role and name, since an image has no control to carry
a test identifier. The two VoiceOver tests compare the whole list of what is
spoken in each example, in order and to the end of the screen, so they also
show what is not spoken. Speech alone cannot show the end of a screen, or
tell two elements that read the same from one read twice. On web the test
reads the position of VoiceOver's cursor after every move; two elements in
the same place that read the same would still count as one there, which the
tree test, counting elements, covers. On iOS, where
the API gives only the utterance, the test walks forward until the same
utterance is heard four times, then walks back to the "Example" heading and
takes the example from that walk back.
