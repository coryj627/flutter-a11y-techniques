# C13 Snackbar and transient messages

A short message about what the app has just done is announced when it
appears, without taking keyboard focus; its action can be reached with a
keyboard and a screen reader, and the message can be dismissed with them;
and what it says or offers is not taken away on a timer the user cannot
turn off, adjust, or extend, unless it is also available elsewhere.

Code: [`lib/techniques/c13_snackbar/examples.dart`](../../lib/techniques/c13_snackbar/examples.dart).
Spec: [`docs/specs/C13-snackbar.md`](../specs/C13-snackbar.md).
In the app: `/t/C13`, and each example at `/t/C13/<slug>`.

Platforms: Android, iOS, and the web apply, each with limitations of the
framework's messages. A SnackBar's time is the app's alone: no screen
reader and no setting changes it ([FL-290](../flutter-limitations.md#fl-290)),
so a SnackBar that must not go on a timer is given an action, which makes
it stay, or what it says is put on the page too. Escape closes no message
([FL-291](../flutter-limitations.md#fl-291)), so `good-action` has a Close
button, whose focus shows only as a faint tint that no parameter changes
([FL-294](../flutter-limitations.md#fl-294)): that is `good-action`'s one
qualification, wherever a keyboard is used.

Every example is Flutter's own `SnackBar` or `MaterialBanner`, configured
only through their own parameters, and every one but `bad-inline-banner`
is shown through the `ScaffoldMessenger` (the owner's rule of 2026-11-21): nothing is built to fill what
they cannot do. Cupertino has no widget for a transient message, so there
is no Cupertino example; a widgets-layer one would be built by hand.

## Why it matters

A snack bar says "Message archived" at the bottom of the screen and offers
Undo, then goes after four seconds. A screen reader user hears it only if
it is announced, and must not lose their place to hear it. To use Undo they
have to get there first: a swipe or a Tab at a time, through the rest of
the screen. Someone who reads slowly, magnifies the screen, or uses switch
access may not get there in four seconds at all. And a keyboard user needs
a way to dismiss a message that stays, since it covers part of the page.

`SnackBar` is announced, and a SnackBar with an action stays by default.
What can go wrong is in what the app gives it: an action set to time out,
or news that is shown nowhere else.

## WCAG 2.2

- [4.1.3 Status Messages](https://www.w3.org/TR/WCAG22/#status-messages): the message can be presented by assistive technology without receiving focus. Its words must reach the screen reader by the message's own role or properties: a live region.
- [2.2.1 Timing Adjustable](https://www.w3.org/TR/WCAG22/#timing-adjustable): a time limit set by the content can be turned off, adjusted to ten times, or extended, unless it is real-time, essential, or over 20 hours. [Understanding 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) says that a message that goes sets no time limit when the user can find out the same thing another way, and does when it is the only means.

[Understanding 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)
sets no time a status message must stay. [APG's Alert pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/)
says an alert must not move keyboard focus, and to avoid alerts that
disappear by themselves. The Android Compose reference repository's
[Popup messages](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/components/PopupMessages.md)
says a native Snackbar honours Android's "Time to take action" setting,
that its buttons are hard to reach with TalkBack, and recommends a dialog
for a message with actions. The iOS and Android View reference
repositories have no entry.

| --- | --- | --- |
| `good-action` | `ScaffoldMessenger.showSnackBar(SnackBar(content:, action: SnackBarAction(label: 'Undo'), showCloseIcon: true))`. A SnackBar with an action stays until it is used or closed (`persist` defaults to true with an action); Close is there because Escape closes nothing ([FL-291](../flutter-limitations.md#fl-291)). Qualification: Close shows keyboard focus only by a faint tint that no parameter changes ([FL-294](../flutter-limitations.md#fl-294)), which fails 1.4.11 as [FL-430](../flutter-limitations.md#fl-430) reads it, wherever a keyboard is used; kept, as decided in review by the principal on 2026-11-22 (the owner can overrule it). On the web, in Chromium, VoiceOver reads Close "Close Close" with no role word while its built-in tooltip is shown, as a VoiceOver walk leaves it ([FL-249](../flutter-limitations.md#fl-249)); the tree keeps the role, so it is not a 4.1.2 failure as written, and `SnackBar` has no parameter to leave the tooltip out. | [Flutter: SnackBar.persist](https://api.flutter.dev/flutter/material/SnackBar/persist.html), [Android Compose: Popup messages](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/components/PopupMessages.md) |
| `good-message` | A SnackBar with a message only, "Draft saved", which goes after its default four seconds; the page says the same ("Drafts saved: 1"), so its going sets no time limit. | [Understanding 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html) |
| `good-banner` | `ScaffoldMessenger.showMaterialBanner(MaterialBanner(content:, actions: [TextButton('Go online')]))`: a live region above the page that stays until its action is used. | [Flutter: MaterialBanner](https://api.flutter.dev/flutter/material/MaterialBanner-class.html) |

What makes each of them work:

- **A live region that is the framework's own.** The `ScaffoldMessenger`
  puts every SnackBar and banner in a polite live region named by its
  message, which TalkBack, VoiceOver, and the web announce, without moving
  focus. Do not put a `Semantics(identifier:)` inside the message: it
  takes the words off the live region ([FL-007](../flutter-limitations.md#fl-007)).
- **No timer on anything the user needs.** An action keeps a SnackBar up
  (`persist` defaults to true with one); news that is also on the page can
  go.
- **A way to close it from the keyboard**: Close on the SnackBar, the
  banner's own action.
- **Focus that shows.** A `SnackBarAction`'s and a `TextButton`'s default
  focus tint is under 3:1 ([FL-430](../flutter-limitations.md#fl-430)):
  `good-action` turns the action's colours round through its `textColor`
  and `backgroundColor`, and the buttons get a 2 pixel outline through
  their `style`. Close cannot be given one (FL-294).
- **One message at a time**: each example clears the queue and the
  current message (`clearSnackBars`, `clearMaterialBanners`) before it
  shows a new one, as one that stays holds every later one back
  ([FL-293](../flutter-limitations.md#fl-293)), and `hideCurrentSnackBar`
  alone leaves a replacement queued when presses come while a message is
  going out.
- **A later message keeps its action, and a stale one does nothing.** A
  message outlives its example: it follows Back
  ([FL-291](../flutter-limitations.md#fl-291)). A new message replaces the
  one before; an Undo or a Go online used after its example has gone
  changes nothing and takes away its own message only, so a banner the
  example showed again stays.
- **What an action did is told by the page.** Undo and Go online change
  the page's status line, which is not announced by itself; each example
  with an action has a result line, a live region
  (`Semantics(liveRegion: true)`), which then says "Archive undone.
  Archived: 0" or "You are online." and is announced. It is empty at the
  open and whenever a new message is shown, so the show is announced
  once, by the SnackBar. No second SnackBar is shown: shown from
  `onPressed`, the action hides it when a screen reader is on
  ([FL-296](../flutter-limitations.md#fl-296)), and keeping its order
  right took a mechanism of the project's own, which was taken out.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect |
| --- | --- |
| `bad-action-times-out` | A SnackBar with Undo and `persist: false`: Undo goes with the message after four seconds, with a screen reader on or off, and nothing gives more time ([FL-290](../flutter-limitations.md#fl-290)). |
| `bad-only-in-message` | A SnackBar that is the only place a booking code is shown, "Booked. Code: K7Q2", and goes after four seconds. |
| `bad-inline-banner` | A `MaterialBanner` put in the page by the app, not by the `ScaffoldMessenger`: it is not a live region, and nothing announces it ([FL-295](../flutter-limitations.md#fl-295)). |

What each fails, as the criteria are written: `bad-action-times-out` and
`bad-only-in-message` fail 2.2.1 on Android, iOS, and the web: Undo and the
code are the only way to that function and that information, they go after
four seconds with a screen reader on or off, and nothing lets the user turn
the limit off, adjust it, or extend it; none of the exceptions applies.
Both are announced, so 4.1.3 is met. `bad-inline-banner` fails 4.1.3 on all
three: it is a status message with no live region.

No example takes focus when shown: a SnackBar never does, so that defect
cannot be shown with the framework's widget.

```dart
/// Lays out one example: a button that does something and shows a message
/// about it, and a line of the page that says what the button has done, so
/// that people and tests can confirm it worked. An example whose message
/// has an action has a [result] line too: what that action did, in a live
/// region (`Semantics(liveRegion: true)`), so that the framework announces
/// it. It is empty until the action is used, and emptied again when the
/// button shows a new message, so that it changes, and is announced, each
/// time the action is used.
class _Demo extends StatelessWidget {
  const _Demo({
    required this.slug,
    required this.action,
    required this.line,
    required this.onPressed,
    this.result,
    this.below,
  });

  final String slug;
  final String action;
  final String line;
  final void Function(BuildContext context) onPressed;

  /// What the message's action did, or null for an example with no action.
  final String? result;

  /// What the example shows under its lines, if anything.
  final Widget? below;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 8,
      children: [
        TestId(
          'c13-$slug-show',
          child: OutlinedButton(
            onPressed: () => onPressed(context),
            style: focusRing(Theme.of(context).colorScheme.onSurface),
            child: Text(action),
          ),
        ),
        Semantics(
          key: ValueKey<String>('c13-$slug-count'),
          identifier: 'c13-$slug-count',
          child: Text(line),
        ),
        if (result case final result?)
          Semantics(
            key: ValueKey<String>('c13-$slug-result'),
            identifier: 'c13-$slug-result',
            liveRegion: true,
            child: Text(result),
          ),
        ?below,
      ],
    );
  }
}

/// A 2 pixel outline while a Material button has keyboard focus, through
/// the button's own `style`. Material's own focus tint on a `TextButton` is
/// under 3:1 against what is round it (docs/flutter-limitations.md, FL-430),
/// and the banner's action and the page's button use this.
ButtonStyle focusRing(Color color) => ButtonStyle(
  side: WidgetStateProperty.resolveWith(
    (states) => states.contains(WidgetState.focused)
        ? BorderSide(color: color, width: 2)
        : null,
  ),
);

/// A SnackBar's action, whose colours turn round while it has keyboard
/// focus, through `SnackBarAction`'s own `textColor` and `backgroundColor`,
/// which take a `WidgetStateColor`. Its default focus tint is under 3:1
/// (FL-430).
SnackBarAction undo(BuildContext context, VoidCallback onPressed) {
  final colors = Theme.of(context).colorScheme;
  bool focused(Set<WidgetState> states) => states.contains(WidgetState.focused);
  return SnackBarAction(
    label: 'Undo',
    onPressed: onPressed,
    textColor: WidgetStateColor.resolveWith(
      (states) =>
          focused(states) ? colors.inverseSurface : colors.inversePrimary,
    ),
    backgroundColor: WidgetStateColor.resolveWith(
      (states) => focused(states) ? colors.inversePrimary : Colors.transparent,
    ),
  );
}

/// Shows [bar], first clearing the queue and taking away the message that
/// is shown (`clearSnackBars`), so that a new message replaces the one
/// before and is never queued behind one that stays (FL-293).
void _show(BuildContext context, SnackBar bar) {
  ScaffoldMessenger.of(context)
    ..clearSnackBars()
    ..showSnackBar(bar);
}
```

### `good-action`

```dart
/// A SnackBar with an action. A SnackBar with an action stays until it is
/// used or closed (`persist` defaults to true when there is an action), so
/// the action has no time limit. `showCloseIcon` gives it a Close button,
/// because Escape does not close it (FL-291). It is a live region: shown, it
/// is announced, and focus stays where it was.
/// Good with a qualification: Close shows keyboard focus only by a faint
/// tint, and no parameter changes it (FL-294), which fails 1.4.11 as FL-430
/// reads it, wherever a keyboard is used.
class GoodAction extends StatefulWidget {
  const GoodAction({super.key});

  @override
  State<GoodAction> createState() => _GoodActionState();
}

class _GoodActionState extends State<GoodAction> {
  int _archived = 0;
  String _result = '';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-action',
      action: 'Archive message',
      line: 'Archived: $_archived',
      result: _result,
      onPressed: (context) {
        setState(() {
          _archived++;
          _result = '';
        });
        _show(
          context,
          SnackBar(
            content: Text('Message archived'),
            // What Undo did is told by the result line, a live region. The
            // SnackBar follows Back to other screens (FL-291): there, with
            // this screen gone, Undo changes nothing, and the action takes
            // away its own message only.
            action: undo(context, () {
              if (!mounted) return;
              setState(() {
                _archived--;
                _result = 'Archive undone. Archived: $_archived';
              });
            }),
            showCloseIcon: true,
            // The close icon's default focus tint is under 3:1 (FL-430);
            // a WidgetStateColor here does not change it on focus (FL-294).
            closeIconColor: WidgetStateColor.resolveWith(
              (states) => states.contains(WidgetState.focused)
                  ? Theme.of(context).colorScheme.inversePrimary
                  : Theme.of(context).colorScheme.onInverseSurface,
            ),
          ),
        );
      },
    );
  }
}
```

### `good-banner`

```dart
/// A MaterialBanner, shown through the ScaffoldMessenger, which makes it a
/// live region. It stays until its action is used; it has no time limit.
class GoodBanner extends StatefulWidget {
  const GoodBanner({super.key});

  @override
  State<GoodBanner> createState() => _GoodBannerState();
}

class _GoodBannerState extends State<GoodBanner> {
  bool _offline = false;
  String _result = '';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-banner',
      action: 'Go offline',
      line: _offline ? 'Status: offline' : 'Status: online',
      result: _result,
      onPressed: (context) {
        setState(() {
          _offline = true;
          _result = '';
        });
        final messenger = ScaffoldMessenger.of(context);
        // clearMaterialBanners, as _show does for a SnackBar: a new banner
        // replaces the one before.
        messenger
          ..clearMaterialBanners()
          ..showMaterialBanner(
            MaterialBanner(
              content: Text('You are offline.'),
              actions: [
                TextButton(
                  onPressed: () {
                    // The banner follows Back to other screens (FL-291):
                    // there, with this screen gone, Go online takes away
                    // this banner only, and changes nothing.
                    if (!mounted) {
                      messenger.hideCurrentMaterialBanner();
                      return;
                    }
                    // Going online makes every "You are offline." untrue:
                    // the queue is cleared with it. What it did is told by
                    // the result line, a live region.
                    messenger.clearMaterialBanners();
                    setState(() {
                      _offline = false;
                      _result = 'You are online.';
                    });
                  },
                  style: focusRing(Theme.of(context).colorScheme.onSurface),
                  child: const Text('Go online'),
                ),
              ],
            ),
          );
      },
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5. Screen reader speech is from the transcripts
below and the probe ([evidence/probes/c13](../evidence/probes/c13/README.md));
the rest from the tree tests and the probe.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A SnackBar | a group named by the message, holding its buttons; a message alone is text | a polite live region named by the message, with the dismiss action; its action a `Button` | an element labelled by the message; its action a button |
| When it appears | the message written once to `flt-announcement-polite`; focus stays | TalkBack says the message, not its action | VoiceOver says the message; the cursor stays |
| Its action | the Tab stop after the page's last control; VoiceOver "Message archived group", "Undo button", then Close ("Close button" in WebKit; "Close Close", no role word, in Chromium, in all six recordings, with Close's tooltip shown), "end of Message archived group" | the Tab stop after the page's last control; TalkBack "Undo, Button" | the Tab stop after the page's last control |
| A banner | above the page: a group named by it, read after the title and before the page, as drawn; its action the Tab stop after Back | the same, as a live region | the same |
| Time, no action or `persist: false` | 4.26 s | 4.28 s, with TalkBack too | 4.56 s; 4.28 s with VoiceOver |
| Time, an action and the default | stays | stays | stays |
| Escape | nothing | nothing | not sent |
| Back | pops the screen; the message stays on the one under | the same (widget tests) | the same (widget tests) |

Things to know:

- **On the web the message is the name of a group** holding its buttons:
  VoiceOver reads "Message archived group" on entering it and "end of
  Message archived group" on leaving, and does not stop on the words
  again inside it.
- **Close has a tooltip**, "Close", that the app cannot leave out:
  `SnackBar` has no parameter for it. While it is shown, the web names the
  button "Close Close", still a button
  ([FL-249](../flutter-limitations.md#fl-249)). A VoiceOver walk left it
  shown, and VoiceOver in Chromium then read "Close Close" with no role
  word, twice in two recordings; WebKit read "Close button". Why the role
  word is left out was not measured.
- **A banner comes first.** It is drawn above the page, and read and
  tabbed to there: a screen reader or keyboard user on the button that
  showed it has to go back to reach it.

- **A SnackBar with an action stays for everyone**, by `persist`'s
  default, not because a screen reader is on; with `persist: false` it
  goes after its `duration` with one on too.
- **Nothing gives a user more time**: not TalkBack, not VoiceOver, not
  Android's "Time to take action".
- **Nothing reads the action when the message appears.** A screen reader
  user hears "Message archived", not that Undo is there; it is the next
  stop after the page's last one.
- **A SnackBar follows the user back** to the screen before, and one that
  stays stays there.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-290](../flutter-limitations.md#fl-290): a SnackBar's time limit is the app's alone: a screen reader, Android's accessibility timeout, a pointer resting on it, and keyboard focus on its action do not change it.
- [FL-291](../flutter-limitations.md#fl-291): Escape closes no SnackBar or MaterialBanner; Back pops the screen under it, and the message stays on the screen before.
- [FL-292](../flutter-limitations.md#fl-292): when a SnackBar times out under keyboard focus, focus goes back to the button that showed it on Android and the web, and to no control in widget tests.
- [FL-293](../flutter-limitations.md#fl-293): a message shown while one that stays is up waits, unseen and unannounced, until that one is closed; a delay for everyone, not a 4.1.3 failure as measured.
- [FL-297](../flutter-limitations.md#fl-297): on the web, whether VoiceOver in Chromium said what Undo or Go online did after Enter varied between recordings.
- [FL-296](../flutter-limitations.md#fl-296): a SnackBar shown from a `SnackBarAction`'s `onPressed` after a clear there never appears when a screen reader is on.
- [FL-294](../flutter-limitations.md#fl-294): a SnackBar's Close button shows keyboard focus only by a faint tint, and `closeIconColor` cannot change that.
- [FL-295](../flutter-limitations.md#fl-295): a `MaterialBanner` is a live region only when the `ScaffoldMessenger` shows it.
- [FL-430](../flutter-limitations.md#fl-430): a `SnackBarAction`'s and a `TextButton`'s default focus tint is under 3:1; the examples set colours through their own parameters.
- [FL-249](../flutter-limitations.md#fl-249): while Close's tooltip is shown, the web names it "Close Close", and VoiceOver in Chromium reads it so, with no role word.
- [FL-007](../flutter-limitations.md#fl-007): a `Semantics(identifier:)` inside a SnackBar's message takes the words off its live region.
