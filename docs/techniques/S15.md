# S15 Hints

A hint says what will happen when a control is used, for a control whose
name does not already say it. It is extra: nothing a person needs is in the
hint alone.

Code: [`lib/techniques/s15_hints/examples.dart`](../../lib/techniques/s15_hints/examples.dart).
Spec: [`docs/specs/S15-hints.md`](../specs/S15-hints.md).
In the app: `/t/S15`, and each example at `/t/S15/<slug>`.

A control's name is [S01 Accessible names](S01.md), and its role is
[S13 Roles and traits](S13.md). The label of a tap action (`onTapHint`) is
left to I06 Action labels, instructions for form fields to F02 Input
instructions, and tooltips to C12.

## Why it matters

A row in a list reads "Night Ferry, The Lanterns, button". It is a button,
so something will happen, but what? A sighted person guesses from the
screen around it. A screen reader user has the name and the role, and a
hint adds the missing fact: "Plays the song."

Most controls do not need one. "Save", "Delete", and "Play" already say
what they do, and a hint on them is noise that is read every time. A hint
is also the first thing a screen reader lets its user switch off, so it can
only ever add to what is already there. A rule a person must follow, such
as the format of a username, has to be on the screen as well.

## WCAG 2.2

- [3.3.2 Labels or Instructions](https://www.w3.org/TR/WCAG22/#labels-or-instructions): labels or instructions are provided when content requires user input. A hint can repeat an instruction for a screen reader user; it cannot be the only place the instruction is.

The wording rules below are from the source, not from WCAG. A badly worded
hint is a worse experience, not a failure of a success criterion.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-result` | `MergeSemantics(child: Semantics(hint: 'Adds this item to your favorites.', child: FilledButton.icon(...)))`. The hint is a sentence about the result, starting with a verb in the third person. `MergeSemantics` is needed for a Material button ([FL-040](../flutter-limitations.md#fl-040)). | [iOS: Accessibility Hint](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityHint.md) (its "Favorite" button); [Apple: accessibilityHint](https://developer.apple.com/documentation/uikit/uiaccessibilityelement/accessibilityhint) |
| `good-row` | `Semantics(hint: 'Plays the song.', child: ListTile(onTap: ...))`. The row's name is a title and an artist, which does not say what a tap does. | iOS: Accessibility Hint (its song row) |
| `good-cupertino` | `Semantics(hint: 'Shares the current page.', child: CupertinoButton.filled(...))`. No `MergeSemantics` is needed: `CupertinoButton` is not a semantics container. | iOS: Accessibility Hint |
| `good-custom` | `Semantics(button: true, label: 'Archive', hint: 'Moves this message out of the inbox.', onTap: ...)` on a button drawn by hand. | iOS: Accessibility Hint; [Flutter: SemanticsProperties.hint](https://api.flutter.dev/flutter/semantics/SemanticsProperties/hint.html) |
| `good-field` | `Semantics(hint: rule, child: TextField(...))`, and the same rule as a `Text` under the field. A screen reader user hears the rule with focus on the field; everyone can read it. | iOS: Accessibility Hint (its username field, whose hint repeats "the input requirements that are visible on screen"); [MDN: aria-description](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-description) |

How to word a hint, from the source:

- Say what happens, not how to do it: "Adds this item to your favorites."
- Start with a verb in the third person ("Adds", not "Add"), with a capital
  letter, and end with a period.
- Do not name a gesture. "Double tap" is wrong for a keyboard, a switch, or
  a voice command, and the screen reader says its own.
- Do not repeat the name or say "button" or "link". The screen reader has
  just said both.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-gesture` | The hint is "Double tap to add this item to your favorites." TalkBack then adds its own "Double-tap to activate". | — |
| `bad-repeats-label` | The hint is "Delete" on a button named "Delete". TalkBack reads "Delete, Delete, Button" and VoiceOver on the web "Delete Delete button". VoiceOver on iOS leaves out a hint that is the same as the label, so the defect cannot be heard there. | — |
| `bad-control-type` | The hint is "This button shares the current page.", read just before or after the screen reader says "button". | — |
| `bad-no-hint` | The song row with no hint. It is read as a title, an artist, and "button", and nothing says that a tap plays it. | — |
| `bad-hint-detached` | `Semantics(hint:)` around a `FilledButton` with nothing to merge them. On Android and iOS the hint is an element of its own in front of the button, with no name and no role; on the web it is not in the page. The button has no hint ([FL-040](../flutter-limitations.md#fl-040)). | — |
| `bad-hint-only` | The username rule is the field's hint and is not on the screen. Sighted people never get it, and neither does a screen reader user who has hints off. | 3.3.2 |

```dart
/// Lays out one example and reports how many times its control was
/// operated, so people and tests can confirm that it worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('s15-${widget.slug}-count'),
          identifier: 's15-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The keyboard half of a custom button and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no hint.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A song in a list: its title and the artist. A tap plays it, and nothing
/// in the row's text says so.
class _SongRow extends StatelessWidget {
  const _SongRow({required this.onTap});

  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) {
    return ListTile(
      contentPadding: EdgeInsets.zero,
      title: const Text('Night Ferry'),
      subtitle: const Text('The Lanterns'),
      onTap: onTap,
    );
  }
}
```

### `good-result`

```dart
/// A Material button whose name does not say what it does to the item. The
/// hint says what happens: a sentence in the third person, with no gesture
/// and no control type in it.
///
/// A Material button is a semantics container, so a `Semantics(hint:)`
/// around it lands on a node of its own (see `bad-hint-detached`).
/// `MergeSemantics` puts the hint on the button.
class GoodResult extends StatelessWidget {
  const GoodResult({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-result',
      builder: (context, changed) => [
        TestId(
          's15-good-result-favorite',
          child: MergeSemantics(
            child: Semantics(
              hint: 'Adds this item to your favorites.',
              child: FilledButton.icon(
                onPressed: changed,
                icon: const Icon(Icons.favorite_border),
                label: const Text('Favorite'),
              ),
            ),
          ),
        ),
      ],
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Button with a hint | `role="button"` named "Favorite", `aria-description` "Adds this item to your favorites." | `Button`, description "Favorite, Adds this item to your favorites."; no hint text | button "Favorite"; the hint is not visible to XCUITest |
| Screen reader on it | "Favorite Adds this item to your favorites. button" | "Favorite,", "Adds this item to your favorites.", "Button" | "Favorite Button Adds this item to your favorites." |
| Row with a hint | button "Night Ferry The Lanterns", `aria-description` "Plays the song." | `Button`, "Night Ferry, The Lanterns, Plays the song." | button "Night Ferry, The Lanterns" |
| Screen reader on it | "Night Ferry The Lanterns Plays the song. button" | "Night Ferry The Lanterns,", "Plays the song.", "Button" | "Night Ferry The Lanterns Button Plays the song." |
| Text field with a hint | `<input>` named "Username", `aria-description` the rule | `EditText`, hint text "Username, 3 to 12 letters or numbers." | text field "Username" |
| Screen reader on it | "Username 3 to 12 letters or numbers. edit text" | "Username,", "3 to 12 letters or numbers.", "Edit box" | "Username Text field 3 to 12 letters or numbers. Double tap to ed…" |
| Hint the same as the name | `aria-description` "Delete" | "Delete, Delete" | button "Delete" |
| Screen reader on it | "Delete Delete button" | "Delete,", "Delete", "Button" | "Delete Button" |
| Hint around a Material button, not merged | button "Favorite" with no description; the hint is not in the page | a `View` with the hint as its description, then the `Button` "Favorite" | two elements |
| Screen reader on it | "Favorite button" | "Adds this item to your favorites.", then "Favorite", "Button" | "Adds this item to your favorites.", then "Favorite Button" |

TalkBack's lines are what it said with focus moved to each node by the
test; the commas are TalkBack's own pauses. The iOS test API returns the
first 64 characters of an utterance, so the field's line is cut short. The web lines are VoiceOver on
macOS, the same in Chromium and WebKit: the description is read after the
name and before the role. On a text field VoiceOver follows this at
once with its own help message ("You are currently on a text field…"); the
transcript shows the field's own speech, taken from Guidepup's log.

Things to know:

- **Use a hint only where the name leaves the result unclear.** Most
  buttons need none.
- **Wrap a Material button and its hint in `MergeSemantics`.** Without it
  the hint is a separate element on Android and iOS and is lost on the web
  ([FL-040](../flutter-limitations.md#fl-040)). `CupertinoButton`,
  `ListTile`, `InkWell`, and a hand-built `Semantics` take the hint
  directly.
- **On Android the hint is part of the description**
  ([FL-039](../flutter-limitations.md#fl-039)). It is read straight after
  the name, before the role, every time. Keep it short.
- **A hint is not a name.** On Android and iOS a hint with no label is read
  as if it were the name; on the web it is dropped
  ([FL-041](../flutter-limitations.md#fl-041)).
- **Put nothing essential in a hint alone.** Show the rule on the screen
  and repeat it in the hint, as `good-field` does.
- **`InputDecoration.helperText` and `hintText` are not this.** Helper text
  is a separate element under the field, and hint text is a placeholder.
  Field instructions are F02.
- **`onTapHint` is not this either.** It renames the tap action ("double-tap
  to …") and reaches Android only; see I06.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-039](../flutter-limitations.md#fl-039): on Android a hint is the end of the content description, read as part of the name. No workaround; keep hints short.
- [FL-040](../flutter-limitations.md#fl-040): `Semantics(hint:)` around a Material button stays on a node of its own. Workaround: `MergeSemantics`, as `good-result` does. `bad-hint-detached` shows what happens without it.
- [FL-041](../flutter-limitations.md#fl-041): on web a hint on a node with no label is not rendered.
- [FL-042](../flutter-limitations.md#fl-042): an obscured text field is a plain text field for VoiceOver on iOS. Found in an earlier build of the field examples, which were password fields; it belongs to text fields and no example here shows it.
- [FL-002](../flutter-limitations.md#fl-002): `CupertinoButton` does not answer Enter on web; `good-cupertino` adds the action.
