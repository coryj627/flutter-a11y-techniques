# C06 Disclosure

The control that shows and hides a section is a button whose name says what
it shows, that says whether the section is shown, and that touch, the
keyboard (Enter and Space), and a screen reader each operate. A hidden
section is neither read nor focused; a shown one comes straight after the
control.

Code: [`lib/techniques/c06_disclosure/examples.dart`](../../lib/techniques/c06_disclosure/examples.dart).
Spec: [`docs/specs/C06-disclosure.md`](../specs/C06-disclosure.md).
In the app: `/t/C06`, and each example at `/t/C06/<slug>`.

A set of such sections, each with its header, is [C05 Accordion](C05.md).
What a button is, is [C01 Button](C01.md).

**A Flutter limitation on every platform.** None of Flutter's widgets for
a disclosure that were measured says whether it is open as a state: not `aria-expanded` on the
web, not an expanded state on Android, not on iOS
([FL-264](../flutter-limitations.md#fl-264)). The good example,
Material's `ExpansionTile`, says "Collapsed" or "Expanded" only in words,
which the owner decided does not meet 4.1.2. It is a button on Android and
iOS only with `internalAddSemanticForOnTap: true`, a parameter its
documentation calls "a temporary flag". It is the closest the SDK comes,
used through its own parameters, with nothing built round it.

## Why it matters

A screen reader user meets a control that hides content and needs to know
two things before using it: that it is a control, and whether the content
is shown now. Without the role, it sounds like plain text; without the
state, the user has to open it, or move past it, to find out. A keyboard
user must be able to reach it and open it with Enter or Space.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the control has a name and a button role, and a state, expanded or collapsed, that assistive technology can read and is told of when it changes.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-material` | `ExpansionTile(internalAddSemanticForOnTap: true)` with a `Text` title: a button named "Details" on every platform; Enter and Space open and close it; its panel is built only while open, straight after it. The state is only words: "Details, Collapsed" on Android, the hint "Collapsed double tap to expand" on iOS, the description on the web; the change is announced: "Expanded" on opening by TalkBack, VoiceOver on iOS, and the web's announcement element, and "Collapsed" on closing where that was listened for (TalkBack in the probe, the web). The parameter is "a temporary flag", its documentation says. Its focus indicator is `ListTile`'s tint, under 3:1 ([FL-430](../flutter-limitations.md#fl-430)). Not a custom solution ([register](../custom-solutions.md#c06-disclosure)) | [APG Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), [MDN `details`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details), [MDN `summary`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/summary), [ExpansionTile](https://api.flutter.dev/flutter/material/ExpansionTile-class.html) |

No Cupertino good example: `CupertinoExpansionTile` takes no keyboard
focus ([FL-265](../flutter-limitations.md#fl-265)). No widgets-layer one:
`Expansible` takes its header from a builder the app supplies (source
read), and a header built by hand would be a custom solution.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-expansion-tile` | `ExpansionTile` as it comes: on Android and iOS the control is not a button ([FL-264](../flutter-limitations.md#fl-264)). On the web it is one | 4.1.2 (Android, iOS) |
| `bad-expand-icon` | `ExpandIcon` beside its label, merged as its documentation says: nothing says whether the section is open, not even in words ([FL-267](../flutter-limitations.md#fl-267)); on Android 17 its click label stays "Expand" once open ([FL-280](../flutter-limitations.md#fl-280)) | 4.1.2 |
| `bad-cupertino-expansion-tile` | `CupertinoExpansionTile` as it comes: a keyboard cannot reach the control, so it opens nothing ([FL-265](../flutter-limitations.md#fl-265)) | 2.1.1 |

Every example, the good one included, fails 4.1.2 for the state on every
platform, by the owner's ruling (the spec, section 5).

### Shared code

Used by the examples below.

```dart
/// What the control is named, and what its panel holds.
const disclosureTitle = 'Details';
const panelText = 'Orders ship in two days.';
const panelAction = 'Change address';

/// Lays out one example: the disclosure, and under it a count of the
/// presses of the panel's button, so that people and tests can tell that a
/// key reached the button once the panel is open.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final Widget Function(BuildContext context, VoidCallback press) builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _presses = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        widget.builder(context, () => setState(() => _presses++)),
        Padding(
          padding: const EdgeInsets.fromLTRB(16, 16, 16, 0),
          child: Semantics(
            key: ValueKey<String>('c06-${widget.slug}-count'),
            identifier: 'c06-${widget.slug}-count',
            child: Text('Presses: $_presses'),
          ),
        ),
      ],
    );
  }
}

/// The panel: a line of text and a button, at the start of the line.
/// [onPressed] null leaves the button out (`bad-cupertino-expansion-tile`).
class _Panel extends StatelessWidget {
  const _Panel({this.onPressed});

  final VoidCallback? onPressed;

  @override
  Widget build(BuildContext context) {
    final press = onPressed;
    return Padding(
      padding: const EdgeInsets.fromLTRB(16, 4, 16, 12),
      child: Align(
        alignment: AlignmentDirectional.centerStart,
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            const Text(panelText),
            if (press != null)
              TextButton(onPressed: press, child: const Text(panelAction)),
          ],
        ),
      ),
    );
  }
}
```

### `good-material`

```dart
/// Material's `ExpansionTile` with `internalAddSemanticForOnTap: true`, a
/// documented parameter that makes its header a button on Android and iOS
/// (without it the header is a button on the web only, FL-264). The
/// documentation calls that parameter "a temporary flag to help changing
/// the behavior of ListTile onTap semantics", so it may change or go.
/// The tile's own panel is built only while it is open (`maintainState`
/// false, its default).
///
/// Good with a limitation, on every platform: the tile exposes no expanded
/// state. It says "Collapsed" or "Expanded" only as text: at the end of
/// the name on Android, as a hint on iOS, and as the accessible description
/// on the web (FL-264); that text is not counted as meeting 4.1.2. Its
/// focus tint is ListTile's, under 3:1 (FL-430).
class GoodMaterial extends StatelessWidget {
  const GoodMaterial({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-material',
      builder: (context, press) => ExpansionTile(
        internalAddSemanticForOnTap: true,
        title: const Text(disclosureTitle),
        children: [_Panel(onPressed: press)],
      ),
    );
  }
}
```

class BadExpansionTile extends StatelessWidget {

      // Defect: `ExpansionTile` as it comes. `internalAddSemanticForOnTap`

### `bad-expand-icon`

```dart
class BadExpandIcon extends StatefulWidget {
  const BadExpandIcon({super.key});

  @override
  State<BadExpandIcon> createState() => _BadExpandIconState();
}

class _BadExpandIconState extends State<BadExpandIcon> {
  bool _open = false;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'bad-expand-icon',
      // Defect: Material's `ExpandIcon`, combined with its label in a
      // `MergeSemantics` as its documentation says. The button is named by
      // the label, and nothing says whether the panel is open, not even in
      // words: `ExpandIcon` sets no state and no hint, only a tap hint,
      // "Expand" or "Collapse" (FL-267). Only the icon takes pointer input:
      // a tap on the label opens nothing, except on the web, where a click
      // there is taken by the button's element (FL-411).
      builder: (context, press) => Column(
        crossAxisAlignment: CrossAxisAlignment.stretch,
        children: [
          MergeSemantics(
            child: Row(
              children: [
                const SizedBox(width: 16),
                const Expanded(child: Text(disclosureTitle)),
                ExpandIcon(
                  isExpanded: _open,
                  onPressed: (wasOpen) => setState(() => _open = !wasOpen),
                ),
              ],
            ),
          ),
          if (_open) _Panel(onPressed: press),
        ],
      ),
    );
  }
}
```

class BadCupertinoExpansionTile extends StatelessWidget {
  const BadCupertinoExpansionTile({super.key});

  Widget build(BuildContext context) {
    return _Demo(
      slug: 'bad-cupertino-expansion-tile',

}

## What each platform exposes

Measured on Flutter 3.47.5. Screen reader speech is from the transcripts
below; the rest from the tree tests and the probe
([evidence/probes/c06](../evidence/probes/c06/README.md)).

| | Web (Chromium) | Android (17) | iOS (27.0) |
| --- | --- | --- | --- |
| `good-material` | `role="button"` "Details", no `aria-expanded`, description "Collapsed double tap to expand" on macOS, "Collapsed" on Linux and Windows | `Button` "Details, Collapsed", expanded state "undefined", click label "Expand for more details" | button, no value |
| Screen reader on it, closed | VoiceOver on macOS: "Details Collapsed double tap to expand button" | "Details, / Collapsed / Button / Double-tap to Expand for more details" | "Details Button Collapsed double tap to expand" |
| Screen reader on it, open | "Details Expanded double tap to collapse button" | "Details, / Expanded / Button / Double-tap to Collapse" | "Details Button Expanded double tap to collapse" |
| On a change | "Expanded" or "Collapsed" written to `flt-announcement-polite` | TalkBack: "Expanded" (the tile's live region), on the click action | VoiceOver: "Expanded", after XCUITest's double tap at the control (not VoiceOver's own activation) |
| Tab, then Enter or Space | opens and closes it; focus stays | the same | opens and closes it (two Tabs, the first on Back; focus cannot be read) |
| A closed panel | not in the page | not in the tree | not on screen |
| `bad-expansion-tile` | as `good-material` | a `View`, "Details, Collapsed" | static text |
| `bad-expand-icon` | a button "Details", no state, no description | a `Button` "Details", click label "Expand", also once open | a button "Details", no value |
| `bad-cupertino-expansion-tile` | a button with no `tabindex`; open, one button with the panel's text | a `View`, no focus, no state | static text, no focus |

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-264](../flutter-limitations.md#fl-264): `ExpansionTile` has no expanded state, and is a button on Android and iOS only with `internalAddSemanticForOnTap`, "a temporary flag".
- [FL-260](../flutter-limitations.md#fl-260): on iOS `expanded` has no effect, so `Semantics(expanded:)` gives iOS no state either.
- [FL-265](../flutter-limitations.md#fl-265): `CupertinoExpansionTile` takes no keyboard focus and has no role or state.
- [FL-267](../flutter-limitations.md#fl-267): `ExpandIcon` has no state in any words.
- [FL-280](../flutter-limitations.md#fl-280): on Android an `ExpandIcon` merged with its label keeps the click label "Expand" once open.
- [FL-263](../flutter-limitations.md#fl-263): `CupertinoExpansionTile` keeps a closed panel `Offstage`, where its controls keep keyboard focus.
- [FL-029](../flutter-limitations.md#fl-029): once opened, a `CupertinoExpansionTile` leaves an empty element over the page on the web.
- [FL-430](../flutter-limitations.md#fl-430): a `ListTile`'s and an `IconButton`'s focus tint is under 3:1.
- [FL-039](../flutter-limitations.md#fl-039): on Android a hint is the end of the content description.
- [FL-006](../flutter-limitations.md#fl-006): any tappable node is `role="button"` on the web.
