# F08 Radio group

Radio buttons offer one choice from several. Each button and its label are
one control that says whether it is the one chosen, and the buttons are a
group named by the question they answer.

Code: [`lib/techniques/f08_radio_group/examples.dart`](../../lib/techniques/f08_radio_group/examples.dart).
Spec: [`docs/specs/F08-radio-group.md`](../specs/F08-radio-group.md).
In the app: `/t/F08`, and each example at `/t/F08/<slug>`.

A checkbox is [F07 Checkbox](F07.md) and a switch is F09. A control's name
is [S01 Accessible names](S01.md) and its role is
[S13 Roles and traits](S13.md).

## Why it matters

Three circles and three words, one circle filled. A sighted person reads
that at a glance: one question, three answers, this one chosen, and picking
another will unpick it. A screen reader user gets the same only if each
part is in the code: the words joined to their circles, the circles marked
as exclusive choices, the chosen one marked as chosen, and the question
attached to the set.

Leave out the role and the options sound like buttons that do something
unknown. Use the checkbox role and the user is told they may pick several,
and is not told when their earlier pick disappears. Leave out the question
and "Yes" and "No" are answers to nothing.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the name and role of each radio button can be programmatically determined, and which one is chosen is available to assistive technology and kept up to date.
- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a label belongs to its button, the buttons belong together, and the question belongs to the set. Those relationships are in the code, not only in the layout.

What `RadioGroup` does with the keyboard, which is the APG pattern:

- Tab moves into the group, to the chosen button, and Tab again moves out.
- The arrow keys move focus and the choice to the next or previous button,
  and wrap at the ends.
- Space chooses the focused button. This is from the SDK's documentation
  and is not exercised by the tests here: with an option already chosen,
  focus is always on it.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unlabelled` | `Radio` buttons with `Text` beside them in `Row`s. The buttons have no names, and a tap on the text does nothing. The texts are read as one lump, apart from the buttons. | 4.1.2, 1.3.1 |
| `bad-group-unlabelled` | The question is a `Text` above the group, outside the `RadioGroup`, and is tied to nothing. The radio group has no name. One line lower, inside the group, it would be the name. | 1.3.1 |
| `bad-no-state` | Hand-drawn radio buttons exposed with `Semantics(button: true)`. Each is read as a button, and nothing says which is chosen. | 4.1.2 |
| `bad-checkbox-role` | Hand-drawn radio buttons exposed with `Semantics(checked: ...)` and no exclusive-group flag. They are read as checkboxes (switches on iOS), which says several can be chosen. | 4.1.2 |
| `bad-checked-only` | Hand-drawn radio buttons with `checked` and `inMutuallyExclusiveGroup` only. Android and the web read them correctly. On iOS VoiceOver says "Express, Button" for the chosen one, with no state ([FL-047](../flutter-limitations.md#fl-047)). | 4.1.2 on iOS |

class _Demo extends StatefulWidget {

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [

/// The keyboard half of a custom control and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no state.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A radio button drawn by hand: a ring, filled when [selected]. It has no
/// semantics of its own.
class _DrawnRadio extends StatelessWidget {
  const _DrawnRadio({required this.selected});

  final bool selected;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Container(
      width: 24,
      height: 24,
      padding: const EdgeInsets.all(4),
      decoration: BoxDecoration(
        shape: BoxShape.circle,
        border: Border.all(color: colors.onSurface, width: 2),
      ),
      child: selected
          ? DecoratedBox(
              decoration: BoxDecoration(
                shape: BoxShape.circle,
                color: colors.primary,
              ),
            )
          : null,
    );
  }
}

/// A drawn radio button and its text in a row at least 48 high.
class _DrawnRow extends StatelessWidget {
  const _DrawnRow({required this.selected, required this.text});

  final bool selected;
  final String text;

  @override
  Widget build(BuildContext context) {
    return ConstrainedBox(
      constraints: const BoxConstraints(minHeight: 48),
      child: Row(
        mainAxisSize: MainAxisSize.min,
        children: [
          _DrawnRadio(selected: selected),
          const SizedBox(width: 12),
          Flexible(child: Text(text)),
        ],
      ),
    );
  }
}

const _question = 'Delivery speed';
const _speeds = ['Standard', 'Express', 'Next day'];

/// The id segment for an option: "Next day" is "next-day".
String _slugOf(String option) => option.toLowerCase().replaceAll(' ', '-');

/// The question printed above a group of options.
class _Question extends StatelessWidget {
  const _Question(this.text);

  final String text;

  @override
  Widget build(BuildContext context) =>
      Text(text, style: Theme.of(context).textTheme.titleMedium);
}

/// Three hand-built options, one chosen at a time, each wrapped by
/// [semantics]. Used by the examples that build radio buttons from
/// `Semantics` alone.
class _HandBuilt extends StatefulWidget {
  const _HandBuilt({required this.slug, required this.semantics});

  final String slug;
  final Widget Function(
    String option,
    bool selected,
    VoidCallback select,
    Widget child,
  )
  semantics;

  @override
  State<_HandBuilt> createState() => _HandBuiltState();
}

class _HandBuiltState extends State<_HandBuilt> {
  String _speed = 'Express';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: widget.slug,
      builder: (context, changed) => [
        const _Question(_question),
        for (final option in _speeds)
          TestId(
            'f08-${widget.slug}-${_slugOf(option)}',
            child: Builder(
              builder: (context) {
                void select() {
                  if (_speed == option) return;
                  setState(() => _speed = option);
                  changed();
                }

                return _KeyboardOperable(
                  onActivate: select,
                  child: widget.semantics(
                    option,
                    _speed == option,
                    select,
                    GestureDetector(
                      behavior: HitTestBehavior.opaque,
                      onTap: select,
                      child: ExcludeSemantics(
                        child: _DrawnRow(
                          selected: _speed == option,
                          text: option,
                        ),
                      ),
                    ),
                  ),
                );
              },
            ),
          ),
      ],
    );
  }
}

### `good-group`

```dart
/// Three Material radio buttons under one question. `RadioGroup` holds the
/// choice and gives the group its role and its arrow keys. `RadioListTile`
/// makes each button and its text one control.
///
/// The question is a `Text` inside the `RadioGroup`. Text in the group that
/// belongs to no radio button becomes the group's name, so the visible
/// question names the group and is read once. `RadioGroup` has no label
/// parameter, and a label put around it misses it
/// (docs/flutter-limitations.md, FL-046).
class GoodGroup extends StatefulWidget {
  const GoodGroup({super.key});

  @override
  State<GoodGroup> createState() => _GoodGroupState();
}

class _GoodGroupState extends State<GoodGroup> {
  String? _speed = 'Express';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-group',
      builder: (context, changed) => [
        RadioGroup<String>(
          groupValue: _speed,
          onChanged: (value) {
            setState(() => _speed = value);
            changed();
          },
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.start,
            children: [
              const _Question(_question),
              for (final option in _speeds)
                TestId(
                  'f08-good-group-${_slugOf(option)}',
                  child: RadioListTile<String>(
                    contentPadding: EdgeInsets.zero,
                    value: option,
                    title: Text(option),
                  ),
                ),
            ],
          ),
        ),
      ],
    );
  }
}
```

/// `CupertinoRadio` are built on. `RawRadio` supplies the semantics for
/// every platform (on iOS that is a selected state and a "Not selected"
/// hint, not a checked state) and joins the `RadioGroup` above it, which
/// supplies the arrow keys.
class GoodCustom extends StatefulWidget {

  @override
  State<GoodCustom> createState() => _GoodCustomState();
}

class _GoodCustomState extends State<GoodCustom> {
  String? _speed = 'Express';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-custom',
      builder: (context, changed) => [
        RadioGroup<String>(
          groupValue: _speed,
          onChanged: (value) {
            // A tap on the text of the chosen option arrives here too.
            if (value == _speed) return;
            setState(() => _speed = value);
            changed();
          },
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.start,
            children: [
              const _Question(_question),
              for (final option in _speeds)
                TestId(
                  'f08-good-custom-${_slugOf(option)}',
                  child: _RawRadioRow(option: option),
                ),
            ],
          ),
        ),
      ],
    );
  }
}

/// One option: a `RawRadio` that draws a ring, and its text. A tap on the
/// text chooses the option through the group.
class _RawRadioRow extends StatefulWidget {
  const _RawRadioRow({required this.option});

  final String option;

  @override
  State<_RawRadioRow> createState() => _RawRadioRowState();
}

class _RawRadioRowState extends State<_RawRadioRow> {
  final FocusNode _focusNode = FocusNode();

  @override
  void initState() {
    super.initState();
    _focusNode.addListener(_repaint);
  }

  void _repaint() => setState(() {});

  @override
  void dispose() {
    _focusNode.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final group = RadioGroup.maybeOf<String>(context);
    return GestureDetector(
      behavior: HitTestBehavior.opaque,
      onTap: () => group?.onChanged(widget.option),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focusNode.hasFocus ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(
          padding: const EdgeInsets.all(5),
          child: ConstrainedBox(
            constraints: const BoxConstraints(minHeight: 48),
            child: Row(
              mainAxisSize: MainAxisSize.min,
              children: [
                RawRadio<String>(
                  value: widget.option,
                  groupRegistry: group,
                  mouseCursor: const WidgetStatePropertyAll<MouseCursor>(
                    SystemMouseCursors.click,
                  ),
                  toggleable: false,
                  focusNode: _focusNode,
                  autofocus: false,
                  enabled: true,
                  builder: (context, state) =>
                      _DrawnRadio(selected: state.value ?? false),
                ),
                const SizedBox(width: 12),
                Flexible(child: Text(widget.option)),
              ],
            ),
          ),
        ),
      ),
    );
  }
}

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Radio button, not chosen | `role="radio"`, `aria-checked="false"`, named by its label | `RadioButton`, checkable, not checked | button, not selected |
| Screen reader on it | "Standard Not selected radio button, 1 of 3" | "Standard", "Radio button" (no state) | "Standard Button Not selected" |
| Radio button, chosen | `aria-checked="true"` | checked | button, selected |
| Screen reader on it | "Express selected radio button, 2 of 3" | "checked", "Express", "Radio button" | "selected Express Button" |
| The group, with the question inside it | `role="radiogroup"` named "Delivery speed" | `RadioGroup` with the description "Delivery speed" | an element with the question, before the buttons |
| Screen reader on it | "Delivery speed radio group" before the buttons and "end of Delivery speed radio group" after them | "Delivery speed" | "Delivery speed" |
| The group, with the question outside it | `role="radiogroup"` with no name, and the question as text before it | `RadioGroup` with no description, and a `View` before it | static text, then the buttons |
| Built from `checked` and `inMutuallyExclusiveGroup` only | `role="radio"` with `aria-checked`, no group | `RadioButton`, checked or not | button with no state |
| Screen reader on the chosen one | "Express selected radio button" | "checked", "Express", "Radio button" | "Express Button" |

TalkBack's lines are what it said with focus moved to each node by the
test. The web lines are VoiceOver on macOS, the same in Chromium and
WebKit.

Things to know:

- **Use `RadioGroup` with `RadioListTile`.** It is one widget for the
  choice, the group role, and the keyboard.
- **Name the group by putting the question inside it**
  ([FL-046](../flutter-limitations.md#fl-046)). `RadioGroup` has no label
  parameter. Text inside the group that belongs to no radio button
  becomes the group's name, so the visible question does the job when it
  is a child of the `RadioGroup` and not a sibling above it. A
  `Semantics(label:)` around the group misses it.
- **Keep other loose text out of the group.** Anything in there that is
  not part of a radio button is added to the group's name.
- **Build custom radio buttons on `RawRadio`, not on `Semantics` alone**
  ([FL-047](../flutter-limitations.md#fl-047)). `checked` and
  `inMutuallyExclusiveGroup` are enough for Android and the web and give
  nothing on iOS.
- **On iOS a radio button is a button.** VoiceOver says "selected" for the
  chosen one and "Not selected" as a hint for the others. A user who has
  turned hints off hears "Standard, Button" for an option that is not
  chosen, which is also how a plain button sounds.
- **On Android an option that is not chosen is read with no state**
  ([FL-045](../flutter-limitations.md#fl-045)).
- **In a browser on an Apple device** the options that are not chosen
  carry the description "Not selected", and VoiceOver reads it as well as
  the state.
- **The question is read in order on Android and iOS**, before the
  buttons, and not again on each one. Where an answer makes no sense
  alone, put the question in its name (`good-context`).
- **`MergeSemantics` joins the name but not the target.** A tap on the
  text needs a handler of its own (`good-cupertino`).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-046](../flutter-limitations.md#fl-046): `RadioGroup` has no label parameter. It takes its name from text inside it, and a label around it misses. Workaround: put the visible question inside the group, as every good example here does.
- [FL-047](../flutter-limitations.md#fl-047): a radio button is a button for VoiceOver on iOS. The SDK's radio widgets announce the choice through a selected state and a hint; a radio button built from `Semantics` flags alone has no state there. Workaround for custom controls: `RawRadio`. No workaround for the role.
- [FL-045](../flutter-limitations.md#fl-045): TalkBack says no state for a radio button that is not chosen. No workaround.
- [FL-035](../flutter-limitations.md#fl-035): a checkbox is a switch on iOS, which is what `bad-checkbox-role` sounds like there.

the Linux machine CI runs on.
