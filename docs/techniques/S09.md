# S09 Content grouping

Content that belongs together is exposed as one unit or as a named group:
a label and its value are read as one stop, a set of related controls is a
group named by its visible question, and an icon and its text that do one
thing are one control named by the text. Controls that do different
things are never merged into one.

Code: [`lib/techniques/s09_content_grouping/examples.dart`](../../lib/techniques/s09_content_grouping/examples.dart).
Spec: [`docs/specs/S09-content-grouping.md`](../specs/S09-content-grouping.md).
In the app: `/t/S09`, and each example at `/t/S09/<slug>`.

Platforms: the web applies. Android and iOS are a limitation: a merged
label and value, and an icon and text as one button, work there, but
Flutter has no group that TalkBack or VoiceOver names. A group's name is a
stop of its own before its controls, and a control is read without it
([FL-320](../flutter-limitations.md#fl-320)). Natively both platforms have
such a group, and their screen readers say its name on the way in
(TalkBack: "On. Button. In Kitchen light"; VoiceOver: "Kitchen light On
Button"); Flutter has no parameter for either, and there is no
workaround. No good example is a custom solution
([custom-solutions.md](../custom-solutions.md#s09-content-grouping));
`good-named-group` is borderline, as the named groups of F07 and F09 are,
and is a complete named group on the web only.

## Why it matters

Someone who sees a small table takes in "City" over "Boston" at a glance,
and a question with two buttons under it as one choice. A screen reader
user hears the parts one at a time, in the order they are exposed. If a
label and its value are separate stops, the table takes twice the swipes;
if the table is built row by row, they hear both labels and then both
values, and have to pair them up from memory. If two buttons are not tied
to their question, "On" heard on its own, after a tap lands on it, does not
say what it turns on. And merged too far, a whole question and its
buttons become one button that a screen reader can press only one way.

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a label shown over its value, and a question shown over the buttons that answer it, are relationships shown by layout, which must be programmatically determined or in the text. [H71](https://www.w3.org/WAI/WCAG22/Techniques/html/H71) (`fieldset` and `legend`) is the sufficient technique for a group of controls in HTML.

The sources: the reference repositories' content grouping entries,
[Android View](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/grouping/ContentGrouping.md)
and [Android Compose](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/content/ContentGrouping.md)
(group labels with their values), Android View's
[Tap Target Grouping](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/grouping/TapTargetGrouping.md),
and the iOS reference's
[Combining Focus](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/CombiningFocus.md)
and [Grouping Controls](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/GroupingControls.md)
("VoiceOver users need to hear the group label text spoken when they first
focus on a control in a group"); and HTML's
[`fieldset`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/fieldset),
a `group` captioned by its `legend`.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-merged-facts` | `MergeSemantics` round each label and its value: "City" over "Boston" is one element, read as one stop, and so is "Founded" over "1630". | Android View and Android Compose Content Grouping |
| `good-cupertino` | The same facts as rows of a `CupertinoListSection`. A `CupertinoListTile` keeps its title and its subtitle as two elements, so each tile is put in `MergeSemantics`. | iOS Combining Focus |
| `good-named-group` | Two `OutlinedButton`s, "On" and "Off", under the question "Kitchen light", with `Semantics(container: true, explicitChildNodes: true, label:)` round them and the visible question in `ExcludeSemantics`. On the web a `group` named by the question; on Android and iOS the question is a stop before the buttons and is not said with them ([FL-320](../flutter-limitations.md#fl-320)), where a native group is named on the way in, so it is not a complete named group there. It stays a good example by the principal's decision (spec, section 5). | iOS Grouping Controls, MDN fieldset |
| `good-tap-target` | `TextButton.icon`: the info icon and the words "App information" are one button named by the words, and a tap on either opens it. | Android View Tap Target Grouping |

What makes them work:

- **`MergeSemantics` round text only.** It makes one node of everything
  under it. Round a label and a value that is right; round controls it
  makes one control of them (`bad-merged-group`).
- **A Material `ListTile` merges its title and subtitle; a
  `CupertinoListTile` does not.** In the probe a `ListTile` with no `onTap`
  was one stop per row, and a `CupertinoListTile` two, with a subtitle or
  with additional information (widget tests).
- **The question is the group's label, and is excluded where it is
  drawn**, or it is read twice: on the web as the group's name and again as
  text inside it (probe s14).
- **A focus outline** from the buttons' own `style`: Material's focus tint
  on an `OutlinedButton` or a `TextButton` is under 3:1
  ([FL-430](../flutter-limitations.md#fl-430)).

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-split-facts` | The same table built row by row, labels in one row and values in the next, nothing grouped: "City", "Founded", "Boston", "1630" | 1.3.1, on every platform |
| `bad-merged-group` | `MergeSemantics` round the question and its buttons: one button "Kitchen light On Off", whose action is On's; Off is no element of its own ([FL-243](../flutter-limitations.md#fl-243)) | 4.1.2, on every platform |

The keyboard still reaches Off in `bad-merged-group`: Tab stops on the
merged button twice, and Enter on the second stop turns the light off, so
2.1.1 is not claimed. A group with its question as plain text is F07's bad
example of an unlabelled group, and is not repeated here.

### Shared code

Used by the examples below.

```dart
/// The facts the text examples show: a label and its value, twice.
const facts = [('City', 'Boston'), ('Founded', '1630')];

/// The question the group of buttons answers, and its buttons.
const groupName = 'Kitchen light';

/// The one action of the tap target examples.
const targetName = 'App information';

/// A label over its value, as the text examples draw each fact.
class FactLabel extends StatelessWidget {
  const FactLabel(this.text, {super.key});

  final String text;

  @override
  Widget build(BuildContext context) =>
      Text(text, style: Theme.of(context).textTheme.labelLarge);
}

/// A fact's value, drawn larger than its label.
class FactValue extends StatelessWidget {
  const FactValue(this.text, {super.key});

  final String text;

  @override
  Widget build(BuildContext context) =>
      Text(text, style: Theme.of(context).textTheme.titleLarge);
}

/// A 2 pixel outline in the page's text colour while a Material button has
/// keyboard focus, through the button's own `style`, as in C18: Material's
/// own focus tint on an `OutlinedButton` or a `TextButton` is under 3:1
/// against the page (docs/flutter-limitations.md, FL-430).
ButtonStyle focusRing(ColorScheme colors) => ButtonStyle(
  side: WidgetStateProperty.resolveWith(
    (states) => states.contains(WidgetState.focused)
        ? BorderSide(color: colors.onSurface, width: 2)
        : null,
  ),
);

/// A line under an example that says what its controls did, so that
/// people and tests can confirm it: "Light: on". [id] is its test
/// identifier.
class Status extends StatelessWidget {
  const Status({super.key, required this.id, required this.text});

  final String id;
  final String text;

  @override
  Widget build(BuildContext context) {
    return Semantics(
      key: ValueKey<String>(id),
      identifier: id,
      liveRegion: true,
      child: Text(text),
    );
  }
}

/// The two buttons of the group examples, "On" and "Off", and the status
/// line under them. [builder] places the question and the buttons. Each
/// button has its test identifier, unless [buttonIds] is false: `TestId`
/// is a `MergeSemantics`, and inside a merged node its identifier would be
/// merged too.
class LightDemo extends StatefulWidget {
  const LightDemo({
    super.key,
    required this.slug,
    required this.builder,
    this.buttonIds = true,
  });

  final String slug;
  final bool buttonIds;
  final Widget Function(BuildContext context, Widget question, Widget buttons)
  builder;

  @override
  State<LightDemo> createState() => _LightDemoState();
}

class _LightDemoState extends State<LightDemo> {
  bool? _on;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final slug = widget.slug;
    Widget button(String name, bool on) {
      final button = OutlinedButton(
        style: focusRing(colors),
        onPressed: () => setState(() => _on = on),
        child: Text(name),
      );
      return widget.buttonIds
          ? TestId('s09-$slug-${name.toLowerCase()}', child: button)
          : button;
    }

    final question = Text(
      groupName,
      style: Theme.of(context).textTheme.titleMedium,
    );
    final buttons = Row(
      spacing: 8,
      children: [button('On', true), button('Off', false)],
    );
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 12,
      children: [
        widget.builder(context, question, buttons),
        Status(
          id: 's09-$slug-status',
          text: switch (_on) {
            null => 'Light: not set',
            true => 'Light: on',
            false => 'Light: off',
          },
        ),
      ],
    );
  }
}
```

### `good-merged-facts`

```dart
/// Two facts, each a label over its value. `MergeSemantics` round each
/// pair makes it one element, read as one stop: "City, Boston". The pairs
/// sit side by side, as the columns of a small table, and wrap onto a line
/// of their own where the screen is too narrow.
class GoodMergedFacts extends StatelessWidget {
  const GoodMergedFacts({super.key});

  @override
  Widget build(BuildContext context) {
    return Wrap(
      spacing: 32,
      runSpacing: 12,
      children: [
        for (final (label, value) in facts)
          MergeSemantics(
            child: Column(
              crossAxisAlignment: CrossAxisAlignment.start,
              children: [FactLabel(label), FactValue(value)],
            ),
          ),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// The same facts as rows of a Cupertino list, each its label over its
/// value. A `CupertinoListTile` keeps its title and its subtitle as two
/// elements (measured in the widget tests), so each row is put in
/// `MergeSemantics`, which makes it one: "City, Boston".
class GoodCupertino extends StatelessWidget {
  const GoodCupertino({super.key});

  @override
  Widget build(BuildContext context) {
    return CupertinoListSection.insetGrouped(
      margin: EdgeInsets.zero,
      children: [
        for (final (label, value) in facts)
          MergeSemantics(
            child: CupertinoListTile(title: Text(label), subtitle: Text(value)),
          ),
      ],
    );
  }
}
```

### `good-named-group`

```dart
/// Two buttons that answer one question. The question is the label of a
/// node round the buttons. On the web that node is a group named by the
/// question, as `fieldset` and `legend` make one in HTML. On Android and
/// iOS Flutter has no such group: the question is read as a stop of its
/// own before the buttons, and not with them, where a native group's name
/// is said on the way in (docs/flutter-limitations.md, FL-320). So this is
/// a complete named group on the web only. The visible question is left
/// out of the semantics, or it would be read twice.
class GoodNamedGroup extends StatelessWidget {
  const GoodNamedGroup({super.key});

  @override
  Widget build(BuildContext context) {
    return LightDemo(
      slug: 'good-named-group',
      builder: (context, question, buttons) => Semantics(
        container: true,
        explicitChildNodes: true,
        label: groupName,
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          spacing: 8,
          children: [
            ExcludeSemantics(child: question),
            buttons,
          ],
        ),
      ),
    );
  }
}
```

### `good-tap-target`

```dart
/// An icon and its text that do one thing are one target:
/// `TextButton.icon` makes one button named by the text, and a tap on the
/// icon or on the words does the same. The icon has no name of its own.
class GoodTapTarget extends StatefulWidget {
  const GoodTapTarget({super.key});

  @override
  State<GoodTapTarget> createState() => _GoodTapTargetState();
}

class _GoodTapTargetState extends State<GoodTapTarget> {
  int _opens = 0;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 12,
      children: [
        TestId(
          's09-good-tap-target-info',
          child: TextButton.icon(
            style: focusRing(colors),
            onPressed: () => setState(() => _opens++),
            icon: const Icon(Icons.info_outline),
            label: const Text(targetName),
          ),
        ),
        Status(id: 's09-good-tap-target-opens', text: 'Opens: $_opens'),
      ],
    );
  }
}
```

### `bad-split-facts`

```dart
/// The same table built row by row: the labels in one row and the values
/// in the next, nothing grouped. It looks the same, but it is read as
/// "City", "Founded", "Boston", "1630": the values come apart from what
/// they are.
class BadSplitFacts extends StatelessWidget {
  const BadSplitFacts({super.key});

  @override
  Widget build(BuildContext context) {
    Widget row(List<Widget> cells) =>
        Row(children: [for (final cell in cells) Expanded(child: cell)]);
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 4,
      children: [
        row([for (final (label, _) in facts) FactLabel(label)]),
        row([for (final (_, value) in facts) FactValue(value)]),
      ],
    );
  }
}
```

### `bad-merged-group`

```dart
/// The question and its buttons merged into one element with
/// `MergeSemantics`: one button named "Kitchen light On Off", whose action
/// is the first button's. "Off" is no element of its own: TalkBack's
/// double tap on Android, and a click from assistive technology on the
/// web, turn the light on (VoiceOver's own activation on iOS was not
/// measured). The keyboard still reaches Off.
class BadMergedGroup extends StatelessWidget {
  const BadMergedGroup({super.key});

  @override
  Widget build(BuildContext context) {
    return LightDemo(
      slug: 'bad-merged-group',
      buttonIds: false,
      builder: (context, question, buttons) => MergeSemantics(
        child: Semantics(
          identifier: 's09-bad-merged-group-light',
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.start,
            spacing: 8,
            children: [question, buttons],
          ),
        ),
      ),
    );
  }
}
```

| | Web | Android | iOS |
| --- | --- | --- | --- |

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-320](../flutter-limitations.md#fl-320): off the web Flutter has no named group; a group's name is read as text of its own before its controls, and a control inside is read without it.
- [FL-243](../flutter-limitations.md#fl-243), extended: `MergeSemantics` round controls makes one control with the first one's action; measured here with two buttons.
- [FL-430](../flutter-limitations.md#fl-430): Material's focus tint on an `OutlinedButton` or a `TextButton` is under 3:1.
- [FL-421](../flutter-limitations.md#fl-421): on the web, Tab past Flutter's last control goes on into the page.
