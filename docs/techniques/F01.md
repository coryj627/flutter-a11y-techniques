# F01 Text fields and labels

Every text field has a visible label that stays visible while the field is
filled in, and that label is the name assistive technology announces.

Code: [`lib/techniques/f01_text_fields/examples.dart`](../../lib/techniques/f01_text_fields/examples.dart).
Spec: [`docs/specs/F01-text-fields.md`](../specs/F01-text-fields.md).
In the app: `/t/F01`, and each example at `/t/F01/<slug>`.

## Why it matters

A screen reader user lands on a field and hears its name: "Email, text
field". Without a name they hear only "text field" and have to guess. A voice
control user says the label to move to the field, which only works if the
name matches what is on screen.

A placeholder is not a label. It disappears as soon as something is typed, so
anyone who looks away, uses autofill, or comes back to review the form can no
longer tell what each field is for. The tests here show the same thing
happens to the accessible name.

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): the label is tied to its field.
- [2.5.3 Label in Name](https://www.w3.org/TR/WCAG22/#label-in-name): the name contains the visible label.
- [3.3.2 Labels or Instructions](https://www.w3.org/TR/WCAG22/#labels-or-instructions): a label is provided and stays available.
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): name, role, and value are exposed.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-label` | `TextField(decoration: InputDecoration(labelText: 'Email'))`. The label is the visible label and the name, and it moves above the text instead of disappearing. Works the same for a multi-line field. | [CVS Compose: TextField Controls](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/components/TextFieldControls.md), [MDN: input](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input), [MDN: textarea](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/textarea) |
| `good-label-above` | A label drawn above the field. The field gets the same text with `Semantics(label: 'Full name', child: TextField(…))`, and the visible label is wrapped in `ExcludeSemantics` so it is not read twice. | [CVS View: Input Field Labels](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/basics/InputFieldLabels.md), [MDN: label](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/label) |
| `good-cupertino` | In a `CupertinoFormRow` the `prefix` is the visible label. The `CupertinoTextField` is named with `Semantics(label:)` and the prefix is excluded, as above. | [CVS iOS: Text Fields](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/TextFields.md) |

When the label is drawn separately from the field, keep the two strings the
same. `bad-name-mismatch` shows what happens when they drift.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-placeholder-only` | `hintText` is the only label. Once text is typed there is no visible label and no accessible name. | 3.3.2, 4.1.2 |
| `bad-unassociated-label` | A `Text` above the field. It looks like a label but nothing ties it to the field, so the field has no name. | 1.3.1, 4.1.2 |
| `bad-no-label` | Only a search icon. | 3.3.2, 4.1.2 |
| `bad-name-mismatch` | The visible label says "Email"; the accessible name is "Contact address". | 2.5.3 |
| `bad-cupertino-placeholder` | `CupertinoTextField(placeholder: 'Email')` and nothing else. | 3.3.2, 4.1.2 |
| `bad-cupertino-prefix` | A `CupertinoFormRow` prefix left as the only label (Flutter limitation). | 1.3.1, 4.1.2 |

### `good-label`

```dart
/// `labelText` is the visible label and the field's accessible name. It
/// moves above the text when the field has a value, so it never disappears.
class GoodLabelledFields extends StatelessWidget {
  const GoodLabelledFields({super.key});

  @override
  Widget build(BuildContext context) {
    return const _Fields(
      children: [
        TestId(
          'f01-good-label-email',
          child: TextField(
            keyboardType: TextInputType.emailAddress,
            decoration: InputDecoration(
              labelText: 'Email',
              border: OutlineInputBorder(),
            ),
          ),
        ),
        TestId(
          'f01-good-label-message',
          child: TextField(
            maxLines: 4,
            decoration: InputDecoration(
              labelText: 'Message',
              alignLabelWithHint: true,
              border: OutlineInputBorder(),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `good-label-above`

```dart
/// A label drawn above the field, as many designs do. The field is given
/// the same text as its accessible name, and the visible label is hidden
/// from assistive technology so it is not read twice.
class GoodLabelAbove extends StatelessWidget {
  const GoodLabelAbove({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        ExcludeSemantics(
          child: Padding(
            padding: const EdgeInsets.only(bottom: 4),
            child: Text(
              'Full name',
              style: Theme.of(context).textTheme.labelLarge,
            ),
          ),
        ),
        TestId(
          'f01-good-label-above-name',
          child: Semantics(
            label: 'Full name',
            child: const TextField(
              decoration: InputDecoration(border: OutlineInputBorder()),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// A Cupertino field has no label of its own. In a form row the prefix is
/// the visible label, and the field is given the same text as its name.
class GoodCupertinoField extends StatelessWidget {
  const GoodCupertinoField({super.key});

  @override
  Widget build(BuildContext context) {
    return CupertinoFormSection.insetGrouped(
      children: [
        CupertinoFormRow(
          prefix: const ExcludeSemantics(child: Text('Email')),
          child: TestId(
            'f01-good-cupertino-email',
            child: Semantics(
              label: 'Email',
              child: const CupertinoTextField.borderless(
                keyboardType: TextInputType.emailAddress,
              ),
            ),
          ),
        ),
      ],
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Role | `<input>` or `<textarea>`, role `textbox` | class `android.widget.EditText` | text field |
| Name | `aria-label` | hint text | label |
| Screen reader, empty | "Email edit text" (VoiceOver on macOS) | "Email", "Edit box" (TalkBack) | "Email Text field" (VoiceOver) |
| Screen reader, filled | "abc … Email edit text" | "abc", "Edit box"; the label is not spoken | "Email abc Text field" |
| Placeholder only, filled | "abc … edit text" | "abc", "Edit box" | "abc Text field" |

Platform differences in the bad examples:

- `bad-placeholder-only` sounds fine while the field is empty on every
  platform, which is why it passes a quick check. The defect appears once the
  field has a value.
- `bad-unassociated-label` in WebKit: VoiceOver says "Email edit text",
  guessing a name from the text beside the field. In Chromium it says "edit
  text blank". The field has no name in either; do not rely on the guess.
- `bad-no-label` in Chromium: VoiceOver passes over the empty unnamed field in
  silence. In WebKit it says "edit text blank".

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md). Because of FL-015 the catalog
marks this technique as a Flutter limitation on Android.

- [FL-015](../flutter-limitations.md#fl-015): on Android, TalkBack stops
  speaking a field's label once the field has a value. This affects the good
  examples too; no workaround was found within the SDK.
- [FL-016](../flutter-limitations.md#fl-016): Cupertino fields have no label.
  `CupertinoTextField` only offers a placeholder, and a `CupertinoFormRow`
  prefix is not associated with its field.
