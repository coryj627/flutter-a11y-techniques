# I04 Keyboard actions and shortcuts

A custom control answers the keys its kind of control uses, a text
field's Enter does what its keyboard action key says, and a shortcut made
of one character key works only while its control has focus, or can be
turned off, or can be changed to include a key such as Control.

Code: [`lib/techniques/i04_keyboard_actions/examples.dart`](../../lib/techniques/i04_keyboard_actions/examples.dart).
Spec: [`docs/specs/I04-keyboard-actions.md`](../specs/I04-keyboard-actions.md).
In the app: `/t/I04`, and each example at `/t/I04/<slug>`.

Whether a control takes focus and answers Enter and Space is
[I01](I01.md); the order Tab moves in is [I02](I02.md). Moving focus from
code, Escape and keyboard traps, how focus looks, and which on-screen
keyboard a field shows each have an entry of their own (I03, I08, V14,
and F03). The spec's first section lists what is left to each.

## Why it matters

Someone who uses a keyboard, a switch, or speech that types keys can only
do what the keys do. A control that is built by hand, such as a strip of
photos with one stop in the Tab order, is unusable unless it answers the
keys people expect: the arrows to move along it, Home and End to jump to
its ends.

Shortcuts help keyboard users, and a shortcut of one letter is the
quickest of all. It is also the easiest to set off by mistake: by a
stray key, by a speech program that turns words into keys, or by typing.
In Flutter a shortcut placed above a text field takes its letter before
the field can type it, on the web and on iOS: with an F shortcut on the
whole screen, an f typed into the note sets off the shortcut and never
appears; only a capital, a paste, or an on-screen keyboard gets one in.

And a text field's Enter key should do what its keyboard says: save,
search, go to the next field. On a hardware keyboard Flutter gives Enter
the field's action, which is the right thing, and then takes focus out
of the field, which leaves a keyboard user at the top of the screen.

## WCAG 2.2

- [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard): every photo can be shown, and a note saved, from the keyboard. The strip is one Tab stop, so its arrow keys are what reach the other photos.
- [2.1.4 Character Key Shortcuts](https://www.w3.org/TR/WCAG22/#character-key-shortcuts): a shortcut that uses only a letter, number, punctuation, or symbol key must be possible to turn off, or to remap to include a key such as Control or Alt, or must work only while the component it belongs to has focus. Each good example takes one of the three ways. Access keys, which use modifiers, are outside it ([Understanding 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html)).

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-on-focus` | `Shortcuts` maps Left, Right, Home, End, and `CharacterActivator('f')` to intents, and `Actions` carries them out, around the strip only. F works while a thumbnail has focus, and nowhere else, so it never meets the note field. | [Understanding 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html) (active only on focus); [Flutter: Using Actions and Shortcuts](https://docs.flutter.dev/ui/interactivity/actions-and-shortcuts) |
| `good-turn-off` | A `CallbackShortcuts` around the example binds F while a "Single-key shortcuts" `CupertinoSwitch` is on. The strip's keys are in `Focus.onKeyEvent`. The `CupertinoTextField` sits in a `Shortcuts` that maps F to `DoNothingAndStopPropagationIntent`, so the letter is typed. | [Understanding 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html) (turn off); [Flutter API: Focus.onKeyEvent](https://api.flutter.dev/flutter/widgets/Focus/onKeyEvent.html) |
| `good-remap` | The same, with a "Use Control+F for favourites" `SwitchListTile` that rebinds the shortcut to `SingleActivator(keyF, control: true)`. The strip's keys are a `CallbackShortcuts`. | [Understanding 2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html) (remap); [Flutter API: CallbackShortcuts](https://api.flutter.dev/flutter/widgets/CallbackShortcuts-class.html) |

In all three, only the thumbnail of the photo shown is in the Tab order
(the others have `skipTraversal`), and the strip's keys move focus along
it, as a toolbar does ([APG: Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/);
[MDN: Keyboard-navigable JavaScript widgets](https://developer.mozilla.org/en-US/docs/Web/Accessibility/Guides/Keyboard-navigable_JavaScript_widgets)).
The note field has `textInputAction: TextInputAction.done` and
`onSubmitted`, which runs for the on-screen keyboard's Done key and for
Enter on a hardware keyboard ([Android Compose: Keyboard Actions](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/interactions/KeyboardActions.md)).
A favourite button does what F does, so the shortcut is only ever a
second way.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-page-shortcut` | `good-on-focus` with F moved into a `CallbackShortcuts` around the whole example. F acts wherever focus is, and nothing turns it off or changes it. As a result, on the web and iOS typing "Leafy" in the note gives "Leay" and adds a favourite ([FL-460](../flutter-limitations.md#fl-460)); on Android it depended on the device. Shift+F, a paste, and an on-screen keyboard still put an f in. | 2.1.4 |
| `bad-no-arrow-keys` | `good-on-focus` without the arrow keys, Home, and End. Tab reaches only the thumbnail of the photo shown, and the arrows do nothing there, so the other photos cannot be shown from the keyboard. A tap or a screen reader still reaches them. | 2.1.1 |

```dart
/// What every example keeps: the photo shown, the favourites, and how many
/// notes were saved. People and tests read all three in the example.
class _Album extends ChangeNotifier {
  int _shown = 0;
  final Set<int> _favourites = {};
  int _notes = 0;

  int get shown => _shown;
  bool get isFavourite => _favourites.contains(_shown);

  void show(int index) {
    final next = index.clamp(0, _photos.length - 1);
    if (next == _shown) return;
    _shown = next;
    notifyListeners();
  }

  void toggleFavourite() {
    if (!_favourites.remove(_shown)) _favourites.add(_shown);
    notifyListeners();
  }

  /// Saves [text] as a note on the photo shown; blank text is not saved.
  void saveNote(String text) {
    if (text.trim().isEmpty) return;
    _notes++;
    notifyListeners();
  }
}

/// What the strip's keys do: each shows a photo and moves focus to its
/// thumbnail.
class _Moves {
  _Moves(this._album, this._focus);

  final _Album _album;
  final void Function(int index) _focus;

  void show(int index) {
    _album.show(index);
    _focus(_album.shown);
  }

  void previous() => show(_album.shown - 1);
  void next() => show(_album.shown + 1);
  void first() => show(0);
  void last() => show(_photos.length - 1);
}

/// A thumbnail of each photo, a button that shows it. The strip is one
/// stop in the Tab order: only the thumbnail of the photo shown can be
/// reached with Tab, and the others are reached with keys that [keys]
/// adds around the strip, as in a toolbar (the roving tab stop of MDN's
/// "Keyboard-navigable JavaScript widgets"). Without them, the keyboard
/// reaches one thumbnail only. A screen reader, a tap, and a click reach
/// every one.
class _Strip extends StatefulWidget {
  const _Strip({required this.slug, required this.album, required this.keys});

  final String slug;
  final _Album album;
  final Widget Function(_Moves moves, Widget strip) keys;

  @override
  State<_Strip> createState() => _StripState();
}

class _StripState extends State<_Strip> {
  final _nodes = [for (final photo in _photos) FocusNode(debugLabel: photo)];
  late final _moves = _Moves(widget.album, _focus);

  /// Moves focus to the thumbnail [index] and scrolls it into view.
  /// `requestFocus` does not scroll, as Tab and the arrow keys' own focus
  /// moves do, so on a short screen the thumbnail that has focus could be
  /// out of sight.
  void _focus(int index) {
    final forward = index > _nodes.indexWhere((node) => node.hasFocus);
    _nodes[index].requestFocus();
    WidgetsBinding.instance.addPostFrameCallback((_) {
      final context = _nodes[index].context;
      if (context == null || !context.mounted) return;
      Scrollable.ensureVisible(
        context,
        alignmentPolicy: forward
            ? ScrollPositionAlignmentPolicy.keepVisibleAtEnd
            : ScrollPositionAlignmentPolicy.keepVisibleAtStart,
      );
    });
  }

  @override
  void dispose() {
    for (final node in _nodes) {
      node.dispose();
    }
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final shown = widget.album.shown;
    for (var i = 0; i < _photos.length; i++) {
      _nodes[i].skipTraversal = i != shown;
    }
    final strip = Wrap(
      spacing: 8,
      runSpacing: 8,
      children: [
        for (var i = 0; i < _photos.length; i++)
          TestId(
            'i04-${widget.slug}-${_photos[i].toLowerCase()}',
            child: Semantics(
              selected: i == shown,
              child: OutlinedButton(
                focusNode: _nodes[i],
                onPressed: () => _moves.show(i),
                style: i == shown
                    ? OutlinedButton.styleFrom(
                        backgroundColor: colors.secondaryContainer,
                        foregroundColor: colors.onSecondaryContainer,
                        side: BorderSide(color: colors.onSurface, width: 2),
                      )
                    : null,
                child: Text(_photos[i]),
              ),
            ),
          ),
      ],
    );
    return widget.keys(_moves, strip);
  }
}

/// Keeps a single-key shortcut out of a text field: while [active], F does
/// nothing as a shortcut inside [child] and goes on to the field as the
/// letter. A shortcut above a text field otherwise takes the key before the
/// field can type it, on the web and on iOS (docs/flutter-limitations.md,
/// FL-460).
class _TypeF extends StatelessWidget {
  const _TypeF({this.active = true, required this.child});

  final bool active;
  final Widget child;

  @override
  Widget build(BuildContext context) => Shortcuts(
    shortcuts: {
      if (active)
        const CharacterActivator('f'):
            const DoNothingAndStopPropagationIntent(),
    },
    child: child,
  );
}

/// A move along the strip: one of the [_Moves].
class _MoveIntent extends Intent {
  const _MoveIntent(this.move);

  final void Function(_Moves moves) move;
}

class _FavouriteIntent extends Intent {
  const _FavouriteIntent();
}

void _previous(_Moves moves) => moves.previous();
void _next(_Moves moves) => moves.next();
void _first(_Moves moves) => moves.first();
void _last(_Moves moves) => moves.last();

/// The strip's own keys as shortcuts: Left and Right for the previous and
/// next photo, Home and End for the first and last.
const _stripKeys = <ShortcutActivator, Intent>{
  SingleActivator(LogicalKeyboardKey.arrowLeft): _MoveIntent(_previous),
  SingleActivator(LogicalKeyboardKey.arrowRight): _MoveIntent(_next),
  SingleActivator(LogicalKeyboardKey.home): _MoveIntent(_first),
  SingleActivator(LogicalKeyboardKey.end): _MoveIntent(_last),
};

/// [strip] with [shortcuts] and the actions for their intents. The
/// shortcuts act only while a thumbnail has focus.
Widget _withShortcuts(
  _Album album,
  _Moves moves,
  Map<ShortcutActivator, Intent> shortcuts,
  Widget strip,
) => Shortcuts(
  shortcuts: shortcuts,
  child: Actions(
    actions: {
      _MoveIntent: CallbackAction<_MoveIntent>(
        onInvoke: (intent) => intent.move(moves),
      ),
      _FavouriteIntent: CallbackAction<_FavouriteIntent>(
        onInvoke: (_) => album.toggleFavourite(),
      ),
    },
    child: strip,
  ),
);
```

### `good-turn-off`

```dart
/// F works wherever focus is in the example, and a switch turns it off.
/// The strip's own keys are handled in `Focus.onKeyEvent`, and the note
/// field is a `CupertinoTextField` that keeps F for typing.
class GoodTurnOff extends StatefulWidget {
  const GoodTurnOff({super.key});

  @override
  State<GoodTurnOff> createState() => _GoodTurnOffState();
}

class _GoodTurnOffState extends State<GoodTurnOff> {
  bool _shortcuts = true;
  final _note = TextEditingController();

  @override
  void dispose() {
    _note.dispose();
    super.dispose();
  }

  /// The strip's own keys. Down and repeat both act, so holding an arrow
  /// goes on along the strip; any other key is left for the shortcuts
  /// above and for Tab.
  KeyEventResult _stripKey(_Moves moves, KeyEvent event) {
    if (event is KeyUpEvent) return KeyEventResult.ignored;
    final move = switch (event.logicalKey) {
      LogicalKeyboardKey.arrowLeft => moves.previous,
      LogicalKeyboardKey.arrowRight => moves.next,
      LogicalKeyboardKey.home => moves.first,
      LogicalKeyboardKey.end => moves.last,
      _ => null,
    };
    if (move == null) return KeyEventResult.ignored;
    move();
    return KeyEventResult.handled;
  }

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-turn-off',
      builder: (context, album) => CallbackShortcuts(
        bindings: {
          if (_shortcuts) const CharacterActivator('f'): album.toggleFavourite,
        },
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          spacing: 12,
          children: [
            _KeysHint(
              'In the photos: Left and Right arrows for the previous and '
              'next photo, Home and End for the first and last. '
              '${_shortcuts ? 'Anywhere here: F to add or remove a favourite.' : 'Single-key shortcuts are off.'}',
            ),
            _Strip(
              slug: 'good-turn-off',
              album: album,
              // A focus node of its own that takes no focus: it hears the
              // keys pressed on any thumbnail inside it.
              keys: (moves, strip) => Focus(
                canRequestFocus: false,
                skipTraversal: true,
                onKeyEvent: (_, event) => _stripKey(moves, event),
                child: strip,
              ),
            ),
            _FavouriteButton(slug: 'good-turn-off', album: album),
            TestId(
              'i04-good-turn-off-setting',
              child: MergeSemantics(
                child: ConstrainedBox(
                  constraints: const BoxConstraints(minHeight: 48),
                  child: CupertinoListTile(
                    padding: EdgeInsets.zero,
                    title: const Text('Single-key shortcuts'),
                    trailing: CupertinoSwitch(
                      value: _shortcuts,
                      onChanged: (value) => setState(() => _shortcuts = value),
                    ),
                    onTap: () => setState(() => _shortcuts = !_shortcuts),
                  ),
                ),
              ),
            ),
            CupertinoFormRow(
              padding: EdgeInsets.zero,
              prefix: const ExcludeSemantics(child: Text('Note  ')),
              child: TestId(
                'i04-good-turn-off-note',
                child: Semantics(
                  label: 'Note',
                  child: _TypeF(
                    active: _shortcuts,
                    child: CupertinoTextField(
                      controller: _note,
                      textInputAction: TextInputAction.done,
                      onSubmitted: (text) {
                        album.saveNote(text);
                        _note.clear();
                      },
                    ),
                  ),
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A thumbnail | a button, `aria-current="true"` for the photo shown | `Button`, `isSelected` | button, `isSelected` |
| F typed in a field under a page-wide shortcut | taken by the shortcut ([FL-460](../flutter-limitations.md#fl-460)); Shift+F and a paste still go in | typed on the local emulator, where the input method had the letter keys first; taken on CI's emulator | taken by the shortcut, with VoiceOver on or off; Shift+F, a paste with Command+V, and `typeText` (as an on-screen keyboard sends text) still go in |
| Enter in a single-line field | its action: `onSubmitted` | the same | the same |
| After the done action | no control has focus; the next Tab goes to Back ([FL-461](../flutter-limitations.md#fl-461)) | the same | the same |
| An arrow key a control leaves alone | scrolls the page | moves focus by position | moves focus by position |
| Home and End a control leaves alone | scroll the page to its end and top | nothing | not verified: XCUITest cannot send them |

Things to know:

- **Put a single-key shortcut on its control.** A `Shortcuts` or
  `CallbackShortcuts` around a component only hears keys while focus is
  inside it, which is 2.1.4's "active only on focus", and it never sits
  above a text field.
- **A page-wide shortcut needs a guard on every text field**: a
  `Shortcuts` mapping the same key to `DoNothingAndStopPropagationIntent`
  around the field. Without it the web and iOS lose the letter, and an
  Android device may or may not: testing on one Android device does not
  show it.
- **Handle the keys where focus is.** A key a control leaves alone goes on
  to Flutter's defaults (`WidgetsApp.defaultShortcuts`): the arrows move
  focus away on Android and iOS and scroll the page on the web.
- **Scroll what you focus.** `FocusNode.requestFocus` does not scroll;
  a control that moves focus itself, as the strip does, should call
  `Scrollable.ensureVisible` too, or on a short screen focus goes out of
  sight.
- **A shortcut is a second way.** Keep a button for whatever it does.
- **Give plain text inside a shortcut a node of its own**
  (`Semantics(container: true)`): otherwise the shortcut's own node takes
  the text as its name and the controls as its children
  ([FL-464](../flutter-limitations.md#fl-464)).
- **Test Enter on a hardware keyboard, not only the action key.** In a
  single-line field Flutter turns Enter into the field's action on every
  platform; a widget test cannot show it, since `sendKeyEvent` reaches the
  framework only, so it sends the action with `receiveAction`, as the
  `onSubmitted` documentation says.

The keys are not heard: TalkBack and VoiceOver read the two bad examples
as they read the good ones, and activate any thumbnail with their own
gestures.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-460](../flutter-limitations.md#fl-460): a shortcut above a text field takes its key before the field can type it, on the web and on iOS. `good-turn-off` and `good-remap` guard their note fields.
- [FL-461](../flutter-limitations.md#fl-461): a text field's done, go, search, or send action leaves no control with focus, so the next Tab starts from the top. The examples keep the default; I03 owns where focus goes.
- [FL-028](../flutter-limitations.md#fl-028): an adjustable control has no name on the web, which is why the strip is buttons.
- [FL-463](../flutter-limitations.md#fl-463): a `PageView` takes no keyboard focus and has no keys.
- [FL-464](../flutter-limitations.md#fl-464): a `Shortcuts`, `CallbackShortcuts`, or `Focus` around plain text makes the text the name of a node holding the controls inside it; on the web the example became a group named by its line of keys. The examples give that line a node of its own.

Transcripts: [TalkBack](../evidence/I04/talkback-android.md),
[VoiceOver on iOS](../evidence/I04/voiceover-ios.md),
[VoiceOver on web](../evidence/I04/voiceover-web.md). The web VoiceOver

Every test that says a key does nothing presses that key alone and then,
in the same launch, shows that keys arrive and act: F on the strip, the
arrow moving the caret in the note, or the switch turned back on. Where
focus is, is read stop by stop: by the node whose semantics say it has
focus, by `document.activeElement` on the web, and on iOS, where XCUITest
cannot see focus, by what a key does there. The probe's findings and raw
output are in [evidence/probes/i04](../evidence/probes/i04/README.md).
