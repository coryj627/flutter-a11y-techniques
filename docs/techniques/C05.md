# C05 Accordion

Each header of an accordion is a button whose name is its section's title,
that says whether its section is open or closed, and that is the heading of
its section. Touch, the keyboard (Enter and Space), and a screen reader each
open and close it. A closed section's panel is neither read nor focused; an
open one comes straight after its header.

Code: [`lib/techniques/c05_accordion/examples.dart`](../../lib/techniques/c05_accordion/examples.dart).
Spec: [`docs/specs/C05-accordion.md`](../specs/C05-accordion.md).
In the app: `/t/C05`, and each example at `/t/C05/<slug>`.

> **Custom solution: not vetted by a real-world example. It is tested here in isolation, with screen-reader transcripts, but has not been built into a real app and tested in a user journey. Do not treat it as a vetted technique.** This applies to the three good examples,
> `good-material`, `good-cupertino`, and `good-custom`. They are built by
> hand because no Flutter accordion widget meets the requirements through
> its own parameters ([FL-264](../flutter-limitations.md#fl-264),
> [FL-265](../flutter-limitations.md#fl-265),
> [FL-267](../flutter-limitations.md#fl-267)). What is hand-built, the gap
> each piece fills, and its source are in "What is hand-built" below and
> in the spec's section "Custom solutions". Two pieces have no source at
> all: the iOS spoken value "collapsed" or "expanded" (`iosStateValue`),
> and setting `controlsNodes` only while the panel is open.

A single region shown and hidden outside an accordion is C06 Disclosure.
What a button is, is [C01 Button](C01.md); headings are [S05 Headings](S05.md).

## Why it matters

Someone who cannot see the screen needs three things from a section header:
that it is a button, whether its section is open, and that it starts a
section, so that they can jump from header to header. If the state is only
drawn, as an arrow, they press a header and cannot tell whether anything
opened. And a closed section must really be gone: a keyboard user should
not land on buttons they cannot see.

Flutter's own accordions get this wrong. Material's `ExpansionTile` has no
expanded state and, on Android and iOS, no button role; Cupertino's
`CupertinoExpansionTile` cannot be reached from the keyboard. The good
examples here are built by hand from a list tile and `Semantics(button:
true, expanded:)` (a custom solution, see the note above), and needed more
on two platforms: Flutter does not pass the
expanded state to iOS at all, and passes it to Android only from Android 16.
On the web a heading and a button cannot be one node, so there the heading
holds the button, as in HTML.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): each header has a name, the button role, and an expanded or collapsed state that assistive technology can read and is told of when it changes.
- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a header drawn as a section heading is a heading, and a panel comes straight after its header.

What `HeaderSemantics` gives each header, and why:

| | What it is for |
| --- | --- |
| `button: true`, the title as the name | The role and the name (R1, R4) |
| `expanded: open` | The state: `aria-expanded` on the web; on Android 16 and later the node's expanded state, which TalkBack reads "collapsed" and, on a change, "fully expanded" ([FL-261](../flutter-limitations.md#fl-261) for earlier Android) |
| `value: 'collapsed'` or `'expanded'`, on iOS only | The state for VoiceOver on iOS, where Flutter does not pass `expanded` ([FL-260](../flutter-limitations.md#fl-260)). Not elsewhere: Android and the web would read it beside the state |
| `onTapHint: 'expand'` or `'collapse'` | TalkBack says "Double-tap to expand" or "to collapse" (heard on Android 17; the engine gives the click label on every version, source read), as the Android Compose reference does with `onClickLabel` |
| `onExpand` while closed, `onCollapse` while open | Android's expand and collapse actions, which both Android references give a header; on Android 16 and later only (FL-261). TalkBack then adds "Actions available" |
| `headingLevel: 3` | The heading. On Android and iOS on the button's own node; on the web a heading node of its own that holds the button, as APG's `<h3><button>`, because a heading node there is never a button ([FL-262](../flutter-limitations.md#fl-262)) |
| `controlsNodes`, while open | `aria-controls` on the web, naming the open panel ([FL-266](../flutter-limitations.md#fl-266)) |

A panel is built only while its section is open (`if (open) panel`), so a
closed one is in neither the semantics tree nor the focus order, and an open
one is the next thing after its header. Every good header draws a 3 pixel
ring when it has keyboard focus, as in V14: a `ListTile`'s own focus tint is
under 3:1 ([FL-430](../flutter-limitations.md#fl-430)) and a
`CupertinoListTile` has none.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect |
| --- | --- |
| `bad-no-state` | The headers are buttons and headings with no expanded state. Only the arrow, which assistive technology does not see, shows whether a section is open. |
| `bad-heading-on-button` | The heading is on the button's own node on the web too. There the header is an `<h3>` only: no button role and no `aria-expanded` ([FL-262](../flutter-limitations.md#fl-262)). On Android and iOS it reads as the good examples do. |
| `bad-no-heading` | The headers are drawn in the title style, as section headings, but are not headings. |
| `bad-hidden-panel` | A closed panel is kept, hidden with `Offstage`, as `Expansible` does by default. It is out of the semantics tree, but its button keeps keyboard focus: Tab goes to buttons that are not drawn, and Enter presses one ([FL-263](../flutter-limitations.md#fl-263)). |
| `bad-expansion-tile` | Material's `ExpansionTile` as it comes: on Android and iOS its headers are not buttons ([FL-264](../flutter-limitations.md#fl-264)). It also has no expanded state, which is not its named defect (see below). |
| `bad-cupertino-expansion-tile` | Cupertino's `CupertinoExpansionTile` as it comes: its headers take no keyboard focus, so a keyboard opens nothing ([FL-265](../flutter-limitations.md#fl-265)). It has other shortcomings too, which are not its named defect (see below). |

The two SDK tiles are shown as they come, each with one named defect.
Their other measured shortcomings, which are not their named defects and
are not judged in the table below:

- `bad-expansion-tile`: no expanded state on any platform; "Collapsed" or
  "Expanded" is only text, at the end of the name on Android ("Shipping,
  Collapsed"), a hint on iOS, and the accessible description on the web;
  on Android a live region announces the change (FL-264). On the web the
  description depends on the platform Flutter's engine finds from the
  browser's `navigator.platform`: "Collapsed double tap to expand" on
  macOS, "Collapsed" alone on Linux and Windows (the tile adds the touch
  instruction only where `defaultTargetPlatform` is iOS or macOS; source
  read, and measured in the web tests).
- `bad-cupertino-expansion-tile`: no button role on Android (`View`) and
  iOS (static text); no expanded state. The state is hint text on iOS,
  and on the web the accessible description only where Flutter's engine
  finds macOS ("Collapsed double tap to expand"); on Linux and Windows the
  header has no description, so its state is in no attribute and no text,
  and on Android nothing says it either (the tile adds the hint only where
  `defaultTargetPlatform` is iOS or macOS; source read, and measured in
  the web tests). Once open, the panel's text joins the header's name
  (FL-265).

On the web, VoiceOver on macOS reads both tiles' closed headers "Shipping
Collapsed double tap to expand button", in Chromium and WebKit
(`docs/evidence/probes/c05/voiceover-web-round1-fail.md.txt`, and the
passing transcript, [`voiceover-web.md`](../evidence/C05/voiceover-web.md)): the tiles do
give the state in words there, through the hint text, phrased as a touch
instruction on a desktop browser. VoiceOver on macOS hears only a browser
on macOS; on Linux and Windows the tree tests show `bad-expansion-tile`'s
description as "Collapsed" alone and `bad-cupertino-expansion-tile` with
none. What that means for the web, as the criteria are written: the named
defects' verdicts below do not change, on any of those platforms
(`bad-expansion-tile` has none on the web, where it is a button on each;
`bad-cupertino-expansion-tile` fails 2.1.1, as its header takes no focus
on each). For the state, which is not a named defect: where it is text in
the accessible description and not `aria-expanded` (both tiles on macOS,
`bad-expansion-tile` on Linux and Windows too), 4.1.2 is not settled, as
the criterion as written does not decide whether text in a description is
the state being programmatically determined; where nothing gives it
(`bad-cupertino-expansion-tile` on Linux and Windows, as on Android), 4.1.2
fails as written. Nothing more is claimed.

What each fails, by platform, as the criteria are written:

| Example | Android | iOS | Web |
| --- | --- | --- | --- |
| `bad-no-state` | 4.1.2: no state (on Android 16 and later; before 16 the good examples have none either, FL-261) | 4.1.2: no state | 4.1.2: no `aria-expanded` |
| `bad-heading-on-button` | none: a heading button with its state | none: as the good examples | 4.1.2: a heading, with no button role and no state (FL-262) |
| `bad-no-heading` | 1.3.1: drawn as a heading, not one | 1.3.1 | 1.3.1 |
| `bad-hidden-panel` | 4.1.2: Tab puts keyboard focus on a button that has no node, and Enter presses it | 4.1.2: four Tabs and Enter press a button that is not on screen | 4.1.2: as on Android; the page's focus stays on the last header |
| `bad-expansion-tile` | 4.1.2: not a button (`View`) | 4.1.2: static text | none: a button ([FL-006](../flutter-limitations.md#fl-006)) |
| `bad-cupertino-expansion-tile` | 2.1.1: the header takes no keyboard focus, so no key reaches it | 2.1.1 | 2.1.1 |

For `bad-hidden-panel`, 2.4.7 Focus Visible and 2.4.3 Focus Order are
not claimed: the tests show keyboard focus on a control with no node, not
that no focus indicator is visible (that nothing is drawn is from the
source, `RenderOffstage` paints nothing, and no screenshot was taken), and
the visible stops keep their order.

2.1.1 Keyboard, outside the entry's two criteria, is claimed for
`bad-cupertino-expansion-tile` because it fails as written and the tests
show that no keyboard path opens a section: the header has no focus state
at all in the semantics tree (widget tests) and no `tabindex` on the web,
so no key can reach it; Tab stops only on Back, where Enter and Space
leave the example (widget tests, the web, Android); and on iOS one, two,
or three Tabs and then Enter or Space never open a section. A section
opens only by a pointer or a screen reader's tap action. 2.1.1's exception
(input that depends on the path of the user's movement) does not apply.

"Not settled" means the evidence and the criterion as written do not decide
it either way; nothing is claimed.

### Shared code

```dart
/// One section of an accordion: the header's title, and what its panel
/// holds, a line of text and a button.
typedef Section = ({String key, String title, String text, String action});

/// The two sections of every example. Both start collapsed.
const sections = <Section>[
  (
    key: 'shipping',
    title: 'Shipping',
    text: 'Orders ship in two days.',
    action: 'Track a parcel',
  ),
  (
    key: 'returns',
    title: 'Returns',
    text: 'Return items within 30 days.',
    action: 'Start a return',
  ),
];

/// The heading level of a header: the example screen's "Example" heading is
/// level 2.
const headerLevel = 3;

/// What a header looks like, and what a tap and the keys call. [open] is
/// the section's state; [toggle] opens or closes it.
typedef HeaderBuilder = Widget Function(
  BuildContext context,
  Section section,
  bool open,
  VoidCallback toggle,
);

/// Lays out an accordion of [sections], with the header [header] builds
/// for each and, while a section is open, its panel straight after it. A
/// closed panel is not built, so it is in neither the semantics tree nor
/// the focus order. The count after the accordion says how often a panel
/// button was pressed, so people and tests can tell that a key reached one.
class Accordion extends StatefulWidget {
  const Accordion({
    super.key,
    required this.slug,
    required this.header,
    this.panels,
  });

  final String slug;
  final HeaderBuilder header;

  /// Builds the panels in place of the default: `bad-hidden-panel` keeps
  /// closed ones, and the two SDK tiles build none, as each tile has its
  /// own.
  final Widget Function(
    BuildContext context,
    Section section,
    bool open,
    Widget panel,
  )?
  panels;

  @override
  State<Accordion> createState() => _AccordionState();
}

class _AccordionState extends State<Accordion> {
  final _open = <String>{};
  int _presses = 0;

  void _toggle(String key) =>
      setState(() => _open.contains(key) ? _open.remove(key) : _open.add(key));

  /// A panel is a node of its own, with an identifier ([panelId]) that its
  /// header's `controlsNodes` names. Its text is a node of its own too: left
  /// to merge, it would become the panel's name, and on the web the panel a
  /// group named by it.
  Widget _panel(Section section) => Semantics(
    identifier: panelId(headerId(widget.slug, section)),
    container: true,
    child: Padding(
      padding: const EdgeInsets.fromLTRB(16, 4, 16, 12),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Semantics(container: true, child: Text(section.text)),
          TextButton(
            onPressed: () => setState(() => _presses++),
            child: Text(section.action),
          ),
        ],
      ),
    ),
  );

  @override
  Widget build(BuildContext context) {
    final panels = widget.panels;
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        for (final s in sections) ...[
          widget.header(
            context,
            s,
            _open.contains(s.key),
            () => _toggle(s.key),
          ),
          if (panels != null)
            panels(context, s, _open.contains(s.key), _panel(s))
          else if (_open.contains(s.key))
            _panel(s),
        ],
        Padding(
          padding: const EdgeInsets.only(top: 16),
          child: Semantics(
            key: ValueKey<String>('c05-${widget.slug}-count'),
            identifier: 'c05-${widget.slug}-count',
            child: Text('Presses: $_presses'),
          ),
        ),
      ],
    );
  }
}

/// The test identifier of a header: `c05-good-material-shipping`.
String headerId(String slug, Section section) => 'c05-$slug-${section.key}';

/// The identifier of the panel of the header [header]:
/// `c05-good-material-shipping-panel`.
String panelId(String header) => '$header-panel';

/// Setting it only while open has no source: it is of this project's own
/// design, measured but not taken from APG, the reference repositories, or
/// Flutter's documentation. `aria-controls` itself is APG's.
///
/// What a header controls: its panel, while it is open. On the web this is
/// `aria-controls`. The web engine writes it only if the panel's node is
/// there when the header's `controlsNodes` is set, so it is set when the
/// panel opens and taken away when it closes (FL-266). Android and iOS do
/// not read it.
Set<String>? controls(String header, bool open) =>
    open ? {panelId(header)} : null;

/// No source: this is of this project's own design, measured but not taken
/// from APG, the reference repositories, or Flutter's documentation.
///
/// What VoiceOver on iOS is given for the state. The iOS engine does not
/// pass `expanded` to iOS (docs/flutter-limitations.md, FL-260), so on iOS
/// the state goes in the header's value as well, which VoiceOver reads after
/// the name. Elsewhere `expanded` alone carries it: on Android and the web a
/// value would be read as part of the name, beside the state.
String? iosStateValue(bool open) =>
    !kIsWeb && defaultTargetPlatform == TargetPlatform.iOS
    ? (open ? 'expanded' : 'collapsed')
    : null;

/// Part of the custom solution of the good examples (not vetted by a
/// real-world example; docs/specs/C05-accordion.md, "Custom solutions").
///
/// What a header is to assistive technology: one node that is a button,
/// with the section's title as its name, an expanded state, and the heading
/// of its section.
///
/// - `expanded` gives the state: `aria-expanded` on the web, and on Android
///   16 and later the node's expanded state (FL-261 for earlier versions).
/// - `onTapHint` makes TalkBack say "Double-tap to expand" or "to
///   collapse", as the Android Compose reference does with `onClickLabel`.
/// - `onExpand` while closed and `onCollapse` while open: Android's expand
///   and collapse actions, which both Android references give a header.
///   The engine passes them on Android 16 and later only (FL-261).
/// - On iOS the state is also the value ([iosStateValue]).
/// - `controlsNodes` names the open panel ([controls]).
/// - The heading: on Android and iOS on the button's own node. On the web a
///   heading node is never a button (FL-262), so there the heading is a node
///   of its own that holds the button, as in APG's `<h3><button>`.
///
/// [TestId] merges [child], which takes the taps and the keys, into the
/// node.
class HeaderSemantics extends StatelessWidget {
  const HeaderSemantics({
    super.key,
    required this.id,
    required this.open,
    required this.toggle,
    required this.child,
  });

  final String id;
  final bool open;

  /// Opens or closes the section, for the expand and collapse actions.
  final VoidCallback toggle;
  final Widget child;

  @override
  Widget build(BuildContext context) {
    final header = TestId(
      id,
      child: Semantics(
        button: true,
        expanded: open,
        headingLevel: kIsWeb ? null : headerLevel,
        value: iosStateValue(open),
        onTapHint: open ? 'collapse' : 'expand',
        onExpand: open ? null : toggle,
        onCollapse: open ? toggle : null,
        controlsNodes: controls(id, open),
        child: child,
      ),
    );
    if (!kIsWeb) return header;
    return Semantics(container: true, headingLevel: headerLevel, child: header);
  }
}

/// The look of a header's title: the theme's title style, as section
/// headings have.
TextStyle? titleStyle(BuildContext context) =>
    Theme.of(context).textTheme.titleMedium;

/// A title for a Cupertino list tile, which cuts its title to one line with
/// an ellipsis (a `DefaultTextStyle` with `maxLines: 1`, as C03 found). A
/// `DefaultTextStyle` of the title's own, with no line limit, lets it wrap
/// at large text sizes.
/// With [headingStyle] false the tile's own text style is kept.
Widget wrappingTitle(String title, {bool headingStyle = true}) => Builder(
  builder: (context) {
    final tile = DefaultTextStyle.of(context);
    return DefaultTextStyle(
      style: tile.style,
      textAlign: tile.textAlign,
      child: Text(title, style: headingStyle ? titleStyle(context) : null),
    );
  },
);

/// A 3 pixel ring in the colour of the page's text round [child] while
/// focus is on it or inside it, as in V14 and C03: the Material and
/// Cupertino list tiles' own focus look is under 3:1 or none at all
/// (docs/flutter-limitations.md, FL-430 and FL-400). The `Focus` here takes
/// no focus itself; it only hears when the header inside it gains or loses
/// focus.
class FocusRing extends StatefulWidget {
  const FocusRing({super.key, required this.child});

  final Widget child;

  @override
  State<FocusRing> createState() => _FocusRingState();
}

class _FocusRingState extends State<FocusRing> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Focus(
      canRequestFocus: false,
      skipTraversal: true,
      includeSemantics: false,
      onFocusChange: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          borderRadius: BorderRadius.circular(4),
          border: Border.all(
            color: _focused ? colors.onSurface : Colors.transparent,
            width: 3,
          ),
        ),
        child: widget.child,
      ),
    );
  }
}

/// Gives [child], which takes the taps, keyboard focus: Enter and Space
/// call [onActivate], on every platform. It gives no role, name, or state;
/// [HeaderSemantics] does.
class KeyboardHeader extends StatelessWidget {
  const KeyboardHeader({
    super.key,
    required this.onActivate,
    required this.child,
  });

  final VoidCallback onActivate;
  final Widget child;

  Object? _activate(Intent intent) {
    onActivate();
    return null;
  }

  @override
  Widget build(BuildContext context) {
    // The ring goes outside the detector, whose own node takes the focus.
    return FocusRing(
      child: FocusableActionDetector(
        mouseCursor: SystemMouseCursors.click,
        actions: {
          ActivateIntent: CallbackAction<ActivateIntent>(onInvoke: _activate),
          ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
            onInvoke: _activate,
          ),
        },
        child: child,
      ),
    );
  }
}

/// A header built from the widgets layer: [KeyboardHeader] round a
/// `GestureDetector`, the title, and an arrow that points down while closed
/// and up while open. The arrow has no semantics of its own: the state is
/// the header's.
Widget plainHeader(
  BuildContext context,
  Section section,
  bool open,
  VoidCallback toggle,
) {
  return KeyboardHeader(
    onActivate: toggle,
    child: GestureDetector(
      behavior: HitTestBehavior.opaque,
      onTap: toggle,
      child: Container(
        constraints: const BoxConstraints(minHeight: 48),
        padding: const EdgeInsets.symmetric(horizontal: 16, vertical: 8),
        child: Row(
          children: [
            Expanded(child: Text(section.title, style: titleStyle(context))),
            Icon(open ? Icons.expand_less : Icons.expand_more),
          ],
        ),
      ),
    ),
  );
}
```

class BadExpansionTile extends StatelessWidget {
  const BadExpansionTile({super.key});

  @override
  Widget build(BuildContext context) {
    return Accordion(
      slug: 'bad-expansion-tile',
      // Defect: Material's ExpansionTile, as it comes. On Android and iOS
      // its header is not a button (FL-264). It has other shortcomings,
      // which the spec lists: no expanded state, only "Expanded" or
      // "Collapsed" as a hint. The tile has its own panel, so the
      // accordion's is not used.
      // No TestId: its MergeSemantics would take the tile's panel into the
      // header. The headers are found by their text.
      // The title keeps the tile's own text style: drawn as a section
      // heading, it would fail for not being one as well.
      header: (context, section, open, toggle) => ExpansionTile(
        title: Text(section.title),
        children: [_TilePanel(section: section)],
      ),
      panels: (context, section, open, panel) => const SizedBox.shrink(),
    );
  }

/// The panel of `bad-expansion-tile` and `bad-cupertino-expansion-tile`:
/// the same text as the others, and no button, so that a closed panel has
/// nothing that could take keyboard focus.
class _TilePanel extends StatelessWidget {
  const _TilePanel({required this.section});

  final Section section;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.fromLTRB(16, 4, 16, 12),
      child: Align(
        alignment: AlignmentDirectional.centerStart,
        child: Text(section.text),
      ),
    );
  }
}

## What each platform exposes

Measured on Flutter 3.47.5. Screen reader speech is from the transcripts
below; the rest from the tree tests and the probe
([evidence/probes/c05](../evidence/probes/c05/README.md)).

| | Web | Android (17) | iOS |
| --- | --- | --- | --- |
| A good header | `<h3>` holding `role="button"` with `aria-expanded`, and `aria-controls` while open | `Button`, a heading, expanded state "collapsed" or "full", click label "expand" or "collapse", expand or collapse action | button, value "collapsed" or "expanded" |
| Screen reader on it, closed | VoiceOver on macOS: "heading level 3 Shipping collapsed button" | "collapsed. / Shipping / Button. Heading / Double-tap to expand", and "Actions available" | "Shipping collapsed Button Heading" |
| Activated by the screen reader | a DOM click, in place of one: opens it | `ACTION_CLICK`: opens it; TalkBack says "fully expanded" | not measured: XCUITest's double tap at the header, with VoiceOver on, opens it, but that is a tap at its place and not VoiceOver's activation (C04 probe round 3); nothing more was said in the next three seconds |
| Tab, then Enter or Space | opens and closes it; focus stays | the same | the same (two Tabs, the first on Back) |
| A closed panel | not in the page | not in the tree | not on screen |
| An open panel | straight after its header | the same | the same |
| `Semantics(expanded:)` alone | `aria-expanded` | a state from Android 16 ([FL-261](../flutter-limitations.md#fl-261)) | nothing ([FL-260](../flutter-limitations.md#fl-260)) |
| A heading on the button's own node | a heading only ([FL-262](../flutter-limitations.md#fl-262)) | a heading button | a heading button |
| `ExpansionTile` | a button, the state in its description: "Collapsed double tap to expand" on macOS, "Collapsed" on Linux and Windows; VoiceOver on macOS: "Shipping Collapsed double tap to expand button" | a `View`, "Shipping, Collapsed" | static text, "Collapsed double tap to expand" as a hint |
| `CupertinoExpansionTile` | a button with no `tabindex`; the state in its description on macOS, and nowhere on Linux and Windows; VoiceOver on macOS as for `ExpansionTile` | a `View`, no state, no focus | static text, the state as a hint, no focus |

What was measured, in short:

- **`ExpansionTile`, `ExpansionPanelList`, and `CupertinoExpansionTile`,
  as they come,** give no expanded state; `ExpansionTile` is not a button
  on Android and iOS ([FL-264](../flutter-limitations.md#fl-264));
  `ExpansionPanelList`'s buttons are all named "Expand"
  ([FL-267](../flutter-limitations.md#fl-267));
  `CupertinoExpansionTile` takes no keyboard focus
  ([FL-265](../flutter-limitations.md#fl-265)).
- **`expanded` alone reaches neither iOS nor Android before 16**
  ([FL-260](../flutter-limitations.md#fl-260),
  [FL-261](../flutter-limitations.md#fl-261); Android before 16 from the
  source, not measured).
- **On the web a heading node is never a button**; a heading node round
  the button's node reads as APG's markup
  ([FL-262](../flutter-limitations.md#fl-262)).
- **A closed panel kept with `Offstage`**, as `Expansible`'s default
  `maintainState: true` keeps it, is gone for a screen reader but not for
  Tab ([FL-263](../flutter-limitations.md#fl-263)).
- **`controlsNodes` set all along never becomes `aria-controls`**; set
  only while the panel is open, it did, in this project's own workaround,
  which no source describes
  ([FL-266](../flutter-limitations.md#fl-266)).

The good examples' answers to these are the custom solution flagged at the
top of this page, not a vetted technique.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-260](../flutter-limitations.md#fl-260): on iOS `expanded` has no effect.
- [FL-261](../flutter-limitations.md#fl-261): on Android the expanded state reaches only Android 16 and later.
- [FL-262](../flutter-limitations.md#fl-262): on the web a heading is never a button.
- [FL-263](../flutter-limitations.md#fl-263): a panel hidden with `Offstage` keeps keyboard focus.
- [FL-264](../flutter-limitations.md#fl-264): `ExpansionTile`'s header has no expanded state, and on Android and iOS no button role.
- [FL-265](../flutter-limitations.md#fl-265): `CupertinoExpansionTile`'s header takes no keyboard focus and has no role or state.
- [FL-266](../flutter-limitations.md#fl-266): `aria-controls` is written only if the panel is there when `controlsNodes` is set.
- [FL-267](../flutter-limitations.md#fl-267): `ExpansionPanelList`'s buttons are all named "Expand" and have no state (probe only).
- [FL-029](../flutter-limitations.md#fl-029): once opened, a `CupertinoExpansionTile` leaves an empty element over the page on the web that takes pointer events (extended in C05).
- [FL-400](../flutter-limitations.md#fl-400): a `CupertinoListTile` takes no keyboard focus.
- [FL-430](../flutter-limitations.md#fl-430): a `ListTile`'s focus tint is under 3:1.
- [FL-039](../flutter-limitations.md#fl-039): on Android a hint is the end of the content description.
