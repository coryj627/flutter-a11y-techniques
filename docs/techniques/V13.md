# V13 Minimum touch target size

Every control takes taps over at least 24 by 24 pixels, or is far enough
from the next one that the gap makes up for it; aim for the platforms'
48 by 48 dp on Android and 44 by 44 pt on iOS. What counts is the area
that takes the tap, not what is drawn and not what the accessibility tree
reports.

Code: [`lib/techniques/v13_touch_target_size/examples.dart`](../../lib/techniques/v13_touch_target_size/examples.dart).
Spec: [`docs/specs/V13-touch-target-size.md`](../specs/V13-touch-target-size.md).
In the app: `/t/V13`, and each example at `/t/V13/<slug>`.

Whether a control acts at all, from the keyboard, and on release is
[I01 Focusable and clickable controls](I01.md). Text size and spacing are
V05 and V06, other gestures I05 and I13, links C03 and C04, and how focus
looks V14; none of those is built yet.

## Custom solutions

**Custom solution: not vetted by a real-world example.** `good-cupertino`,
`good-custom` and `good-inline-link` are custom solutions. Each is tested
here in isolation, with screen-reader transcripts, but has not been built
into a real app and tested in a user journey. Do not treat them as vetted
techniques.

What is built by hand:

- `good-cupertino`: An Actions built by hand round each CupertinoButton so
  that Enter works on the web (FL-002); the size itself is the button's own
  minimumSize.
- `good-custom`: A button drawn by hand: an opaque 48 by 48 GestureDetector
  in Semantics(button: true), with focus and keys from
  FocusableActionDetector.
- `good-inline-link`: An inline link built by hand: Semantics(link: true)
  and a GestureDetector in a WidgetSpan, with FocusableActionDetector and a
  sort key to keep it in its sentence (FL-413).

The register of custom solutions, with the examples judged not to be one, is
[custom-solutions.md](../custom-solutions.md#v13-minimum-touch-target-size).

## Why it matters

A small control is hard to hit for anyone whose hand shakes, who uses a
phone on the move, or who has large fingers, and when small controls sit
close together a miss lands on the wrong one. In Flutter the size that
counts is easy to get wrong in three ways. A Material button is padded to
48 by 48 on a phone, but not in a desktop browser. A `GestureDetector`
takes taps only where its child does, so a small icon inside a large box
can still be the whole target. And the accessibility tree, and the checks
in `flutter_test` that read it, can report a bigger control than the one
that takes taps.

## WCAG 2.2

- [2.5.8 Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum) (AA): the target, "the region of the display that will accept a pointer action", is at least 24 by 24 CSS pixels, unless an exception applies. The ones that matter here: spacing (a circle 24 across, centred on an undersized target, meets no other target and no other undersized target's circle), and inline (the target is in a sentence). The 48 and 44 of the platforms, and of Flutter's own guidelines, are stricter than the criterion; 2.5.5 (44 by 44) is AAA and not claimed. How the size and the circle are measured is in [WCAG: Understanding Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Bad examples

Each has one defect, and the tests assert that the defect is present. Each
makes the three buttons 18 by 18, 4 pixels apart, so their 24 pixel circles
meet and the spacing exception does not save them.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-shrinkwrap` | `IconButton.filledTonal` with no padding, no minimum size, an 18 pixel icon, and `MaterialTapTargetSize.shrinkWrap`, which takes away the 48 pixel padding. | 2.5.8 |
| `bad-zero-padding-web` | The same with the theme's tap target size. On Android and iOS the theme still pads each button to 48 by 48; in a desktop browser it does not, and each is 18 by 18 ([FL-412](../flutter-limitations.md#fl-412)). | 2.5.8 (web, desktop browser) |
| `bad-cupertino-small` | `CupertinoButton.tinted` with `minimumSize: Size.square(18)`. | 2.5.8 |
| `bad-custom-small` | The `GestureDetector` around the 18 pixel icon only. | 2.5.8 |

```dart
/// Lays out one example: its controls, then how many times any of them was
/// pressed, so people and tests can see whether a tap landed.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final Widget Function(BuildContext context, VoidCallback press) builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('v13-${widget.slug}-count'),
          identifier: 'v13-${widget.slug}-count',
          liveRegion: true,
          child: Text('Presses: $_count'),
        ),
      ],
    );
  }
}

/// The three controls of a player bar: their test id, name, and icons.
const _controls = [
  (
    'previous',
    'Previous',
    Icons.skip_previous,
    CupertinoIcons.backward_end_fill,
  ),
  ('play', 'Play', Icons.play_arrow, CupertinoIcons.play_fill),
  ('next', 'Next', Icons.skip_next, CupertinoIcons.forward_end_fill),
];

/// Makes Enter activate a `CupertinoButton` on the web, where Enter is
/// `ButtonActivateIntent` and the button handles only `ActivateIntent`
/// (docs/flutter-limitations.md, FL-002).
class _EnterToo extends StatelessWidget {
  const _EnterToo({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  Widget build(BuildContext context) {
    return Actions(
      actions: {
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) {
            onActivate();
            return null;
          },
        ),
      },
      child: child,
    );
  }
}

/// What makes a hand-made control reachable and usable from the keyboard: a
/// focus node in the Tab order, and Enter and Space mapped to [onActivate]
/// (both activate intents, as in I01). The builder is told whether to show
/// the focus ring. It adds no role, name, or size.
class _Keyboard extends StatefulWidget {
  const _Keyboard({required this.onActivate, required this.builder});

  final VoidCallback onActivate;
  final Widget Function(bool focused) builder;

  @override
  State<_Keyboard> createState() => _KeyboardState();
}

class _KeyboardState extends State<_Keyboard> {
  bool _focused = false;

  Object? _activate(Intent intent) {
    widget.onActivate();
    return null;
  }

  @override
  Widget build(BuildContext context) {
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(onInvoke: _activate),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: _activate,
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: widget.builder(_focused),
    );
  }
}

/// A ring around [child] while [focused].
Widget _ring(BuildContext context, bool focused, Widget child) => DecoratedBox(
  position: DecorationPosition.foreground,
  decoration: BoxDecoration(
    border: Border.all(
      color: focused
          ? Theme.of(context).colorScheme.onSurface
          : Colors.transparent,
      width: 2,
    ),
    borderRadius: BorderRadius.circular(8),
  ),
  child: child,
);
```

```dart
/// Material buttons are padded to a 48 by 48 target on Android and iOS
```

```dart
/// A hand-made button: a 24 pixel icon in a 48 by 48 box. The box takes
/// taps everywhere because the `GestureDetector` is

          for (final (id, name, icon, _) in _controls)

                builder: (focused) => Semantics(
                  button: true,
                  label: name,
                  child: GestureDetector(
                    behavior: HitTestBehavior.opaque,

                      context,
                      focused,
                      SizedBox.square(
                        dimension: 48,
                        child: Center(child: Icon(icon)),

                    ),
                  ),
                ),
              ),
            ),
        ],
      ),

  }
```

### `good-inline-link`

_Custom solution: not vetted by a real-world example. See "Custom solutions" near the top of this page._

```dart
/// A link in a sentence is exempt from the minimum size: it is as tall as
/// the line of text it sits in. Flutter's tap target guidelines skip links.
///
/// It is a `WidgetSpan`, so that it can take keyboard focus, which a
/// `TextSpan` with a recognizer cannot. Two things keep it in its place in
/// the sentence for screen readers (docs/flutter-limitations.md, FL-413):
/// a `semanticsIdentifier` on the text before it, which makes the paragraph
/// give each run of text a node of its own, in order, rather than one label
/// without the link; and a sort key between the ones the paragraph gives
/// those runs (0 and 1), so that the link's node is read between them.
class GoodInlineLink extends StatelessWidget {
  const GoodInlineLink({super.key});

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return _Demo(
      slug: 'good-inline-link',
      builder: (context, press) => Text.rich(
        TextSpan(
          children: [
            const TextSpan(
              text: 'Read the ',
              semanticsIdentifier: 'v13-good-inline-link-sentence',
            ),
            WidgetSpan(
              alignment: PlaceholderAlignment.baseline,
              baseline: TextBaseline.alphabetic,
              // Not TestId: its MergeSemantics would drop the sort key. The
              // identifier goes on the same node instead.
              child: Semantics(
                key: const ValueKey<String>('v13-good-inline-link-rules'),
                container: true,
                identifier: 'v13-good-inline-link-rules',
                sortKey: const OrdinalSortKey(0.5),
                child: _Keyboard(
                  onActivate: press,
                  builder: (focused) => Semantics(
                    link: true,
                    child: GestureDetector(
                      behavior: HitTestBehavior.opaque,
                      onTap: press,
                      child: _ring(
                        context,
                        focused,
                        Text(
                          'trail rules',
                          style: TextStyle(
                            color: colors.primary,
                            decoration: TextDecoration.underline,
                          ),
                        ),
                      ),
                    ),
                  ),
                ),
              ),
            ),
            const TextSpan(text: ' before you set off.'),
          ],
        ),
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5: the Android emulator at density 2.625 (sizes in
dp, the bounds divided by the density), the iOS simulator (points), and
Chromium on macOS (CSS pixels).

| | Web (desktop browser) | Android | iOS |
| --- | --- | --- | --- |
| `good-material` | 40 by 40, no padding | 48 by 48: a 40 dp circle and its padding | 48 by 48, as Android |
| `good-cupertino`, `good-custom` | 48 by 48 | 48 by 48 | 48 by 48 |
| `good-inline-link` | an `<a>` 20 high; a link in Chromium's tree | a `Button` under 24 dp high | a link, under 24 pt high |
| `bad-zero-padding-web` | 18 by 18, 4 apart | 48 by 48 | 48 by 48 |
| The other bad examples | 18 by 18, 4 apart | 18 by 18, 4 apart | 18 by 18, 4 apart |
| What the tree reports | the node's element box | the node's bounds | the node's frame |
| Where a tap is taken | the node's element, and its label text where that runs out of it ([FL-411](../flutter-limitations.md#fl-411)) | Flutter's hit test | Flutter's hit test |

Things to know:

- **Measure where the taps land, not the node.** On Android and iOS a node
  can be bigger than the area that takes taps: padding outside a
  `GestureDetector`, a `GestureDetector` with the default
  `HitTestBehavior.deferToChild` around empty space, a text link's 4 extra
  pixels on each side. `androidTapTargetGuideline` and
  `iOSTapTargetGuideline` read the node, and skip links
  ([FL-410](../flutter-limitations.md#fl-410)). The V13 tests tap at
  points 2 pixels inside and outside each edge.
- **The 48 pixel padding of Material controls depends on the platform.**
  `MaterialTapTargetSize.shrinkWrap` removes it everywhere, and in a
  desktop browser the theme does not add it
  ([FL-412](../flutter-limitations.md#fl-412)). A control that relies on
  it, with its own padding and minimum size taken away, is the size of its
  icon there. Give small controls a minimum size of their own, or set
  `materialTapTargetSize: MaterialTapTargetSize.padded` in the theme.
- **Compact density takes 8 pixels off** and, in the probe, left no
  Material control under 32.
- **A `CupertinoButton` is as big as its `minimumSize`**, 44 by 44 by
  default, and takes taps over all of it.
- **At 200% text** icon buttons keep their size, and text buttons and links
  grow with the text.
- **Size is not heard.** TalkBack and VoiceOver read the 18 pixel buttons
  as the 48 pixel ones.
- **A link in a `WidgetSpan` is read after its sentence**, and the sentence
  without it, unless the paragraph is made to split its text and the link
  is given a sort key between the runs, as `good-inline-link` does
  ([FL-413](../flutter-limitations.md#fl-413)). A `TextSpan` with a
  recognizer keeps its place but takes no keyboard focus. Links in text
  in general are C04's subject.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-410](../flutter-limitations.md#fl-410): a control's semantics node can be bigger than the area that takes taps, and the tap target guidelines read the node.
- [FL-411](../flutter-limitations.md#fl-411): on the web a click is taken by the node's element, and by its label text where that runs out of the element.
- [FL-412](../flutter-limitations.md#fl-412): in a desktop browser the Material theme does not pad controls to 48 by 48, and is compact. `bad-zero-padding-web` fails only there.
- [FL-002](../flutter-limitations.md#fl-002): Enter does not activate a `CupertinoButton` on the web; `good-cupertino` and `bad-cupertino-small` add it.
- [FL-413](../flutter-limitations.md#fl-413): the text around a `WidgetSpan` is read without it, and the widget after it. `good-inline-link` uses the workaround.
- [FL-032](../flutter-limitations.md#fl-032): `Semantics(link: true)` without `linkUrl`, as in `good-inline-link`, is an `<a>` with no `href` on the web and a button on Android.

| Layer | Where | Run |
| --- | --- | --- |

| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py V13` |

Every layer measures each control's size from its own accessibility tree,
in its own unit, and applies the same 2.5.8 check (an undersized target
passes only if its 24 pixel circle meets no other target or undersized
target's circle). Every layer then taps at points worked out in that unit:
the centre and 2 pixels inside the bottom edge must press the control, 2
pixels below it and 2 pixels right of the last one must not, and each tap
that must do nothing is followed, in the same launch, by a tap at the
centre that must press it. The widget tests also run the examples as
macOS, Linux, and Windows, the platforms a desktop browser gives.

Transcripts: [TalkBack](../evidence/V13/talkback-android.md),
[VoiceOver on iOS](../evidence/V13/voiceover-ios.md),
[VoiceOver on web](../evidence/V13/voiceover-web.md).

Not yet covered: a phone's own browser (only imitated in Chromium),
Safari and Firefox, and the desktop apps; touches on the web; the
examples at the device's own font size; whether a label that runs over a
neighbour on the web takes its clicks; and whether dp and pt are close to
WCAG's CSS pixel on a given screen.
