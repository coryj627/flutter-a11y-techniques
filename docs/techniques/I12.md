# I12 Announcements and live regions

When a status message appears or changes without taking focus, assistive
technology announces it.

Code: [`lib/techniques/i12_announcements/examples.dart`](../../lib/techniques/i12_announcements/examples.dart).
Spec: [`docs/specs/I12-announcements.md`](../specs/I12-announcements.md).
In the app: `/t/I12`, and each example at `/t/I12/<slug>`.

## Why it matters

"Added to cart", "Saved", "3 results", "Could not connect": sighted people
see these appear and carry on. A screen reader user's focus is still on the
button they pressed. Unless the message is announced, they do not know
whether anything happened, and have to go looking.

Moving focus to the message is not the answer; it loses the user's place. The
message has to be announced where they are.

Too much is also a failure. A region that announces every second leaves no
room to hear anything else.

## WCAG 2.2

- [4.1.3 Status Messages](https://www.w3.org/TR/WCAG22/#status-messages): status messages are available to assistive technology without receiving focus.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-live-region` | `Semantics(liveRegion: true, child: Text(message))`. When the text changes it is announced; focus stays on the button. | [CVS View: UX Change Announcements](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/dynamicbehaviors/UXChangeAnnouncements.md), [CVS Compose: UX Change Announcements](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/interactions/UXChangeAnnouncements.md), [MDN: live regions](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions), [MDN: output](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/output) |
| `good-announce` | `SemanticsService.sendAnnouncement(View.of(context), message, direction)`, sent only when `MediaQuery.supportsAnnounceOf(context)` is true. Where it is false, the visible confirmation is made a live region instead. Never both, or the message is read twice. | [CVS iOS: Accessibility Notifications](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityNotifications.md) |
| `good-snackbar` | `ScaffoldMessenger.of(context).showSnackBar(…)`. The SnackBar is a live region already. | [APG: Alert](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) |

Use a live region as the default. It is the one mechanism verified on both
Android and web.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-silent-update` | The message changes on screen and nothing is announced. | 4.1.3 |
| `bad-chatty-live-region` | A live region that changes every second, each change announced. | 4.1.3 |
| `bad-status-role-only` | `Semantics(role: SemanticsRole.status)` and nothing else. Announced on web, silent on Android (Flutter limitation). | 4.1.3 |
| `bad-alert-role-only` | `Semantics(role: SemanticsRole.alert)` and nothing else. An error shown this way is silent on Android (Flutter limitation). | 4.1.3 |

### `good-live-region`

```dart
/// A status message in a live region: when its text changes, assistive
/// technology reads the new text without moving focus.
class GoodLiveRegion extends StatelessWidget {
  const GoodLiveRegion({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-live-region',
      action: 'Add to cart',
      initial: 'Cart is empty',
      message: _cart,
      statusBuilder: (context, text) => Semantics(
        identifier: 'i12-good-live-region-status',
        liveRegion: true,
        child: text,
      ),
    );
  }
}
```

### `good-announce`

```dart
/// A change announced from code, for platforms that support it, with a live
/// region for the ones that do not (Android).
class GoodAnnouncement extends StatefulWidget {
  const GoodAnnouncement({super.key});

  @override
  State<GoodAnnouncement> createState() => _GoodAnnouncementState();
}

class _GoodAnnouncementState extends State<GoodAnnouncement> {
  static const _confirmation = 'Link copied';
  String _message = '';

  void _copy(bool canAnnounce) {
    if (canAnnounce) {
      setState(() => _message = _confirmation);
      SemanticsService.sendAnnouncement(
        View.of(context),
        _confirmation,
        Directionality.of(context),
      );
      return;
    }
    // A live region is announced when its text changes. Pressing the button
    // a second time would leave the same text in place and say nothing, so
    // the message is cleared and set again in the next frame: every press is
    // a change, and every press is announced.
    setState(() => _message = '');
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (mounted) setState(() => _message = _confirmation);
    });
  }

  @override
  Widget build(BuildContext context) {
    // False on Android, which has deprecated announcements sent from code.
    final canAnnounce = MediaQuery.supportsAnnounceOf(context);
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        TestId(
          'i12-good-announce-action',
          child: FilledButton(
            onPressed: () => _copy(canAnnounce),
            child: const Text('Copy link'),
          ),
        ),
        ConstrainedBox(
          constraints: const BoxConstraints(minHeight: 24),
          // Where code cannot announce, the visible confirmation is a live
          // region instead. Never both, or the message would be read twice.
          child: Semantics(
            identifier: 'i12-good-announce-status',
            liveRegion: !canAnnounce,
            child: Text(_message, style: Theme.of(context).textTheme.bodyLarge),
          ),
        ),
      ],
    );
  }
}
```

### `bad-chatty-live-region`

```dart
class BadChattyLiveRegion extends StatefulWidget {
  const BadChattyLiveRegion({super.key});

  @override
  State<BadChattyLiveRegion> createState() => _BadChattyLiveRegionState();
}

class _BadChattyLiveRegionState extends State<BadChattyLiveRegion> {
  Timer? _timer;
  int _seconds = 0;

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        TestId(
          'i12-bad-chatty-live-region-action',
          child: FilledButton(
            onPressed: () {
              _timer?.cancel();
              setState(() => _seconds = 0);
              _timer = Timer.periodic(
                const Duration(seconds: 1),
                (_) => setState(() => _seconds++),
              );
            },
            child: const Text('Start upload'),
          ),
        ),
        // Defect: a live region that changes every second. Each change is
        // announced, so the screen reader never stops talking.
        Semantics(
          identifier: 'i12-bad-chatty-live-region-status',
          liveRegion: true,
          child: Text(
            _timer == null ? 'Not started' : 'Uploading: $_seconds seconds',
            style: Theme.of(context).textTheme.bodyLarge,
          ),
        ),
      ],
    );
  }
}
```

## What each platform does

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Live region in the tree | text copied to a shared `aria-live="polite"` element | `liveRegion` polite | not readable from XCUITest |
| Live region, screen reader | "1 item in cart" (VoiceOver, Chromium) | "1 item in cart" (TalkBack) | "1 item in cart" (VoiceOver) |
| Announcement from code | "Link copied" | not sent: `supportsAnnounce` is false, so the fallback live region speaks | "Link copied" |
| SnackBar | "Message archived" | "Message archived" | "Message archived" |
| Status or alert role alone | announced, read twice | silent | silent |

Platform differences in the bad examples:

- `bad-status-role-only` and `bad-alert-role-only` are announced on web,
  because browsers treat those roles as live regions. They are bad examples
  because the same code says nothing on Android or iOS.
- `bad-silent-update` is silent everywhere it could be checked.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-017](../flutter-limitations.md#fl-017): the status and alert roles are
  announced on web only, and cannot be combined with `liveRegion` on one node.
- [FL-018](../flutter-limitations.md#fl-018): announcements sent from code are
  reported as unsupported on Android, and assertive announcements exist only
  on web. There is no way to make an urgent message interrupt on Android.
- [FL-010](../flutter-limitations.md#fl-010): a live region announces its
  first content when the screen opens.
- [FL-012](../flutter-limitations.md#fl-012): on web, one announcement can
  erase another made within 300 ms.

## How it is tested

| Layer | Where | Run |
| --- | --- | --- |
| Widget tests | `test/techniques/i12_announcements_test.dart` | `flutter test` |
| Web tree | `web_tests/i12_announcements.spec.js` | `flutter build web`, then `npx playwright test i12_announcements.spec.js` in `web_tests/` |
| Android tree | `android/app/src/androidTest/.../I12AnnouncementsTest.kt` | `flutter build apk --debug` once, then `./gradlew app:connectedDebugAndroidTest` in `android/` |
| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py I12` |
| iOS tree | `ios/RunnerUITests/I12AnnouncementsUITests.swift` | `xcodebuild test` on the `Runner` scheme |
| VoiceOver speech (iOS) | same file, `testVoiceOverSpeech` | `python3 tool/voiceover_ios.py I12`; needs Xcode 27 and an iOS 27 simulator |
| VoiceOver speech (web, Chromium) | `web_tests/vo/i12_announcements_vo.spec.js` | `python3 tool/voiceover_web.py I12`; needs Guidepup setup, takes over the screen |

The web VoiceOver check presses the button with the keyboard and then polls
VoiceOver's last phrase over AppleScript, because Guidepup does not record
announcements. It runs in Chromium only: Playwright's WebKit build passes no
live region changes to VoiceOver, even for plain HTML.

The iOS VoiceOver check puts the VoiceOver cursor on the button, activates it
with a double tap, and reads `XCUIVoiceOverService.currentSpeech()`. A single
tap would only move the cursor: with VoiceOver on, it does not press the
button. The test also checks that the message is on screen, and that one step
back and one forward lands on the button again, so the message was announced
and not read because the cursor moved onto it.
