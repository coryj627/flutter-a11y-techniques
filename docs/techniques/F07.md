# F07 Checkbox

A checkbox and its label are one control with a name, the checkbox role,
and a state that is checked, not checked, or mixed. Checkboxes that answer
one question are grouped under that question.

Code: [`lib/techniques/f07_checkbox/examples.dart`](../../lib/techniques/f07_checkbox/examples.dart).
Spec: [`docs/specs/F07-checkbox.md`](../specs/F07-checkbox.md).
In the app: `/t/F07`, and each example at `/t/F07/<slug>`.

A switch is F09 and radio buttons are F08. A control's name is
[S01 Accessible names](S01.md), its role is [S13 Roles and traits](S13.md),
and rewording a state is [S14 Values and state descriptions](S14.md).

## Why it matters

A checkbox is a small square and some text beside it. To a sighted person
they are obviously one thing. To a screen reader they are one thing only if
the code says so: otherwise it reads "checkbox, not checked" with no name,
and then some unrelated text. The text is also most of the target. A box
drawn at 18 pixels with a label that cannot be tapped is hard to hit for
anyone with a tremor or a large finger.

The state has to be told as well as shown, including the third state. A
"Select all" box with a dash in it means "some of these". If assistive
technology is told "not checked", that is a different and false answer.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the name and role of a checkbox can be programmatically determined, and its state is available to assistive technology and kept up to date.
- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a label belongs to its box, and a question belongs to the boxes under it. Those relationships are in the code, not only in the layout.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-tile` | `CheckboxListTile(value: ..., onChanged: ..., title: Text('Email me product updates'))`. The box and the text are one control, and the whole row is the target. | [Android Compose: Checkbox Controls](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/components/CheckboxControls.md) (a row that takes over the checkbox's role and toggling); [iOS: Checkboxes](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/Checkboxes.md); [MDN: input type=checkbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/checkbox); [Flutter: CheckboxListTile](https://api.flutter.dev/flutter/material/CheckboxListTile-class.html) |
| `good-cupertino` | `MergeSemantics` around a `GestureDetector`, a `CupertinoCheckbox`, and a `Text`. Cupertino has no list tile for a checkbox, so the row is built by hand: merged for the name, with a tap handler so the text is part of the target. | Android Compose: Checkbox Controls (the same construction) |
| `good-custom` | `Semantics(checked: on, enabled: true, label: ..., onTap: ...)` on a box drawn by hand, with Space and Enter through `FocusableActionDetector`. | [APG: Checkbox](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/) (role, `aria-checked`, Space); [Flutter: SemanticsProperties.checked](https://api.flutter.dev/flutter/semantics/SemanticsProperties/checked.html) |
| `good-mixed` | `CheckboxListTile(tristate: true, value: null)` for "Select all" while one of the two boxes under it is checked. Activating it from mixed checks both. | APG: Checkbox ("When partially checked, it has state `aria-checked` set to `mixed`"); [Flutter: SemanticsProperties.mixed](https://api.flutter.dev/flutter/semantics/SemanticsProperties/mixed.html) |
| `good-group` | `Semantics(container: true, explicitChildNodes: true, label: 'Contact me by', child: ...)` around the boxes, with the visible question inside `ExcludeSemantics` so it is read once. | iOS: Checkboxes ("Checkbox groups need an accessibility label for the group which matches the visible group label text"); APG: Checkbox (role `group` with a label) |

`good-mixed` is the right code and does not give the right result on any
platform yet: see [Flutter limitations](#flutter-limitations).

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unlabelled` | A `Checkbox` with a `Text` beside it in a `Row`. The box has no name, the text is read as a separate element, and a tap on the text does nothing. | 4.1.2, 1.3.1 |
| `bad-no-state` | A hand-drawn checkbox exposed with `Semantics(button: true)`. It is read as a button, and nothing says whether it is checked, before or after it is used. | 4.1.2 |
| `bad-mixed-as-unchecked` | "Select all" as a two-state checkbox. With one of the two boxes under it checked it is exposed as not checked. | 4.1.2 |
| `bad-group-unlabelled` | The question "Contact me by" is a `Text` above the boxes and is tied to nothing. | 1.3.1 |

```dart
/// operated, so people and tests can confirm that it worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('f07-${widget.slug}-count'),
          identifier: 'f07-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The keyboard half of a custom control and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no state.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A box drawn by hand, with a tick when [checked]. It has no semantics of
/// its own.
class _DrawnBox extends StatelessWidget {
  const _DrawnBox({required this.checked});

  final bool checked;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Container(
      width: 24,
      height: 24,
      decoration: BoxDecoration(
        color: checked ? colors.primary : colors.surface,
        border: Border.all(color: colors.onSurface, width: 2),
      ),
      child: checked
          ? Icon(Icons.check, size: 18, color: colors.onPrimary)
          : null,
    );
  }
}

const _updates = 'Email me product updates';
```

```dart
/// A "Select all" checkbox over two others. With one of the two checked it
/// is neither checked nor unchecked: `tristate: true` and a null value say
/// so.
///
/// Flutter 3.47.5 passes the mixed state on to Android only, where TalkBack
/// does not speak it. On the web and on iOS it is exposed as not checked
/// (docs/flutter-limitations.md, FL-044).
class GoodMixed extends StatefulWidget {
  const GoodMixed({super.key});

  @override
  State<GoodMixed> createState() => _GoodMixedState();
}

class _GoodMixedState extends State<GoodMixed> {
  bool _email = true;
  bool _text = false;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-mixed',
      builder: (context, changed) => [
        TestId(
          'f07-good-mixed-all',
          child: CheckboxListTile(
            contentPadding: EdgeInsets.zero,
            controlAffinity: ListTileControlAffinity.leading,
            tristate: true,
            // true when both are checked, false when neither, null when one.
            value: _email == _text ? _email : null,
            onChanged: (_) {
              // From mixed or unchecked, check both; from checked, clear.
              final all = !(_email && _text);
              setState(() => _email = _text = all);
              changed();
            },
            title: const Text('Select all'),
          ),
        ),
        TestId(
          'f07-good-mixed-email',
          child: CheckboxListTile(
            contentPadding: const EdgeInsets.only(left: 32),
            controlAffinity: ListTileControlAffinity.leading,
            value: _email,
            onChanged: (value) {
              setState(() => _email = value!);
              changed();
            },
            title: const Text('Email'),
          ),
        ),
        TestId(
          'f07-good-mixed-text',
          child: CheckboxListTile(
            contentPadding: const EdgeInsets.only(left: 32),
            controlAffinity: ListTileControlAffinity.leading,
            value: _text,
            onChanged: (value) {
              setState(() => _text = value!);
              changed();
            },
            title: const Text('Text message'),
          ),
        ),
      ],
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Checkbox, not checked | `role="checkbox"`, `aria-checked="false"`, named by its label | `CheckBox`, checkable, not checked | switch, value 0 |
| Screen reader on it | "Email me product updates unchecked checkbox" | "Email me product updates", "Check box" (no state) | "Email me product updates Switch button off" |
| Checkbox, checked | `aria-checked="true"` | checked | switch, value 1 |
| Screen reader on it | "Email checked checkbox" | "checked", "Email", "Check box" | "Email Switch button on" |
| Checkbox, mixed | `aria-checked="false"` | `CHECKED_STATE_PARTIAL` | switch, value 0 |
| Screen reader on it | "Select all unchecked checkbox" | "Select all", "Check box" (no state) | "Select all Switch button off" |
| Group with a label | `role="group"` named "Contact me by" around the checkboxes | a `View` with the label whose children are the checkboxes | an element with the label, before the switches |
| Screen reader on it | "Contact me by group" before the boxes and "end of Contact me by group" after them | "Contact me by" | "Contact me by" |
| Box and text not joined | checkbox with no name, then text | `CheckBox` with no description, then a `View` | switch with no label, then text |
| Screen reader on it | "unchecked checkbox", then "Email me product updates" (Chromium). WebKit guesses the name from the text beside the box | "Check box", then "Email me product updates" | "Switch button off", then "Email me product updates" |

TalkBack's lines are what it said with focus moved to each node by the
test. The iOS test API returns the first 64 characters of an utterance. The
web lines are VoiceOver on macOS.

Things to know:

- **Use `CheckboxListTile`**, or build the same thing: one merged node for
  the box and its text, and a tap handler that covers the text.
- **`MergeSemantics` alone joins the name but not the target.** The text
  becomes part of the checkbox for a screen reader, and a tap on it still
  does nothing until something handles the tap (`good-cupertino`).
- **Give a custom checkbox `enabled: true`.** Without it VoiceOver on iOS
  reads the control as dimmed
  ([FL-033](../flutter-limitations.md#fl-033)).
- **On iOS a checkbox is a switch**
  ([FL-035](../flutter-limitations.md#fl-035)). UI tests find it with
  `app.switches`, and VoiceOver says "on" and "off".
- **The mixed state does not reach users yet**
  ([FL-044](../flutter-limitations.md#fl-044)). Write `tristate: true`
  anyway: it is correct, Android's node already carries it, and it will
  start working when the engines pass it on. Make sure the boxes under a
  "Select all" can each be reached and read, because today they are the
  only true account of what is selected.
- **On Android an unchecked box is read with no state**
  ([FL-045](../flutter-limitations.md#fl-045)). A native checkbox is read
  "not checked".
- **A group label is read in order.** On Android and iOS the question is
  an element before the boxes, and sounds the same as plain text above
  them would. On the web it is the name of a `group`, which VoiceOver
  announces going in and coming out.
- **Do not reword the state.** There is no way to do it that works
  ([FL-036](../flutter-limitations.md#fl-036)).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-044](../flutter-limitations.md#fl-044): a mixed checkbox is exposed as not checked on the web and as "off" on iOS, and TalkBack says no state for it. No workaround. `good-mixed` shows it, and its tests assert the wrong result so that they fail when Flutter fixes it.
- [FL-045](../flutter-limitations.md#fl-045): TalkBack says no state for a Flutter checkbox that is not checked, where it says "not checked" for a native one. No workaround.
- [FL-035](../flutter-limitations.md#fl-035): a checkbox is a switch for VoiceOver on iOS. No workaround.
- [FL-033](../flutter-limitations.md#fl-033): a checkbox with no `enabled` flag is read as dimmed on iOS. `good-custom` sets `enabled: true`.
- [FL-036](../flutter-limitations.md#fl-036): the words for the state cannot be changed.

## How it is tested

| Layer | Where | Run |
| --- | --- | --- |
| Widget tests | `test/techniques/f07_checkbox_test.dart` | `flutter test` |
| Web tree | `web_tests/f07_checkbox.spec.js` | `flutter build web`, then `npx playwright test f07_checkbox.spec.js` in `web_tests/` |
| Android tree | `android/app/src/androidTest/.../F07CheckboxTest.kt` | `flutter build apk --debug` once, then `./gradlew app:connectedDebugAndroidTest` in `android/` |
| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py F07` |
| iOS tree | `ios/RunnerUITests/F07CheckboxUITests.swift` | `xcodebuild test` on the `Runner` scheme |
| VoiceOver speech (iOS) | same test class, `testVoiceOverSpeech` | `python3 tool/voiceover_ios.py F07` |
| VoiceOver speech (web) | `web_tests/vo/f07_checkbox_vo.spec.js` | `python3 tool/voiceover_web.py F07`; needs Guidepup setup, takes over the screen |

The mixed state on Android is read with `AccessibilityNodeInfo.getChecked()`,
which needs Android 16 (API 36). On an older image, such as the API 35
one in CI, the test reads the two-state `isChecked` and expects a mixed box
to be not checked. The
TalkBack walk reads each checkbox, changes it, moves focus away and back,
and reads it again.
