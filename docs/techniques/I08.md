# I08 Dismiss and escape

Something shown over the screen for a while, such as a sheet, a popup, or
layers drawn by hand, closes on Escape, on Android's Back, and on a screen
reader's own dismiss command; and a part of the screen that keeps Tab
inside it can always be left from the keyboard.

Code: [`lib/techniques/i08_dismiss_and_escape/examples.dart`](../../lib/techniques/i08_dismiss_and_escape/examples.dart).
Spec: [`docs/specs/I08-dismiss-and-escape.md`](../specs/I08-dismiss-and-escape.md).
In the app: `/t/I08`, and each example at `/t/I08/<slug>`.

Where focus goes when something opens or closes is
[I03 Focus management](I03.md); the order Tab moves in is
[I02 Keyboard focus order](I02.md); keys in general are I04. What makes a
dialog modal, its role, its name, and what is out of reach behind it, is
C08, and the components themselves (bottom sheet, popover, tooltip, menu)
are C10 to C14, none built yet.

## Why it matters

A modal sheet or dialog keeps the keyboard inside it while it is open, so
that nothing behind it is reached by mistake. That is only safe if there
is a way out. Someone who uses a keyboard expects Escape to close it;
someone using TalkBack expects the Back gesture to; someone using
VoiceOver on iOS expects its escape gesture, a two-finger scrub. If none
of those works, and there is no button to press, a keyboard user is stuck:
Tab goes round the same controls for ever.

In Flutter these three requests reach the app by three different paths.
Escape is a key, turned into a `DismissIntent` and handled where keyboard
focus is. Android's Back, and VoiceOver's escape gesture when no element
takes it, ask the Navigator to pop the route on top. A screen reader's
dismiss action goes to a node in the semantics tree. A route, such as a
bottom sheet or a dialog, answers all three by itself, but answers Escape
only when its barrier can be dismissed. Anything drawn in the overlay
without a route answers none of them, and Back takes the user off the
screen underneath it.

## WCAG 2.2

- [2.1.2 No Keyboard Trap](https://www.w3.org/TR/WCAG22/#no-keyboard-trap): the layers take keyboard focus and keep Tab inside them, so a key must get the user out. As [Understanding 2.1.2](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) says, a modal with a standard way out, Escape, is not a trap. `bad-no-escape` fails it on every platform, and `bad-not-dismissible` on Android and iOS; on the web Tab leaves the page for the browser's own controls, which is a way out as the criterion is written.

## Good examples

Every example is a trail map with a button, Map layers, that shows two
switches over the screen (Contour lines and Campsites), and a count of the
times the layers have been closed. While they are shown, keyboard focus is
in them and Tab goes round the two switches.

| Example | How | Source |
| --- | --- | --- |
| `good-material` | `showModalBottomSheet`. Its route closes on Escape because the sheet can be dismissed (`isDismissible`, true by default), on Back and on VoiceOver's escape gesture, which pop the route on top, and through its barrier, "Scrim", which a screen reader can dismiss. | [APG: Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) (Escape closes the dialog; Tab stays in it), [HTML: close requests](https://html.spec.whatwg.org/multipage/interaction.html#close-requests) |
| `good-cupertino` | `showCupertinoModalPopup`, whose barrier can be dismissed by default, with `semanticsDismissible: true` so that the barrier is an element, "Dismiss", a screen reader can use. | [Understanding 2.1.2](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) (Escape as the standard exit) |
| `good-widgets` | The layers drawn in an `OverlayEntry`, with no route: a `ModalBarrier` behind them, a focus scope with `TraversalEdgeBehavior.closedLoop`, an action for `DismissIntent` around them for Escape, `Semantics(onDismiss:)` on them for the screen readers' dismiss commands, and a `PopScope` on the screen that closes them on Back. | [iOS: Escape Action](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/EscapeAction.md) (`.accessibilityAction(.escape)` on a custom dialog), [G21](https://www.w3.org/WAI/WCAG22/Techniques/general/G21) |

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-not-dismissible` | `good-material` with `isDismissible: false`. Escape does nothing, and the sheet has no button, so from a keyboard it cannot be closed. Back and the screen readers' gestures still close it. | 2.1.2 on Android and iOS |
| `bad-no-escape` | `good-widgets` without its action for Escape. Tab and Shift+Tab go round the two switches, and no key leaves them. | 2.1.2 |
| `bad-back-leaves` | `good-widgets` without its `PopScope`. On Android, Back and TalkBack's Back gesture take the user off the screen, with the layers still open, instead of closing them. Escape still closes them. | — (Back is not a keyboard key; the iOS reference's bad example has no criterion either) |

```dart
/// The layers every example's map can show: the last part of each switch's
/// identifier, and its name.
const _layers = [('contours', 'Contour lines'), ('campsites', 'Campsites')];

/// Shows the map's layers to choose from, and completes once they have
/// gone, however they were closed. Each example shows them its own way.
typedef _ShowLayers = Future<void> Function(
  BuildContext context,
  _MapState map,
);

/// A trail map with a button that shows its layers, a line saying which
/// layers are on, and a count of the times the layers have been closed, so
/// that people and tests can see that a key or a gesture closed them.
class _Map extends StatefulWidget {
  const _Map({required this.slug, required this.show});

  final String slug;
  final _ShowLayers show;

  @override
  State<_Map> createState() => _MapState();
}

class _MapState extends State<_Map> {
  /// The layers that are on; the switches read and change it.
  final ValueNotifier<Set<String>> on = ValueNotifier({'contours'});
  int _closed = 0;

  /// The test identifier of the part [part] of this example.
  String id(String part) => 'i08-${widget.slug}-$part';

  @override
  void dispose() {
    on.dispose();
    super.dispose();
  }

  Future<void> _show() async {
    await widget.show(context, this);
    if (mounted) setState(() => _closed++);
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 8,
      children: [
        Text('Trail map', style: Theme.of(context).textTheme.titleMedium),
        ListenableBuilder(
          listenable: on,
          builder: (context, _) {
            final names = [
              for (final (key, name) in _layers)
                if (on.value.contains(key)) name,
            ];
            return Text(
              'Showing: ${names.isEmpty ? 'no layers' : names.join(', ')}',
            );
          },
        ),
        TestId(
          id('open'),
          child: OutlinedButton(
            onPressed: _show,
            child: const Text('Map layers'),
          ),
        ),
        Semantics(
          key: ValueKey<String>(id('count')),
          identifier: id('count'),
          child: Text('Closed: $_closed'),
        ),
      ],
    );
  }
}

/// The two switches, Material ones, for the layers of [map].
Widget _materialSwitches(_MapState map) => ListenableBuilder(
  listenable: map.on,
  builder: (context, _) => Column(
    mainAxisSize: MainAxisSize.min,
    children: [
      for (final (key, name) in _layers)
        TestId(
          map.id(key),
          child: SwitchListTile(
            title: Text(name),
            value: map.on.value.contains(key),
            onChanged: (value) => map.on.value = value
                ? {...map.on.value, key}
                : ({...map.on.value}..remove(key)),
          ),
        ),
    ],
  ),
);

/// The layers' title and their two Material switches.
/// They scroll when large text makes them taller than the sheet.
Widget _layersPanel(BuildContext context, _MapState map) => SafeArea(
  child: SingleChildScrollView(
    padding: const EdgeInsets.symmetric(vertical: 16),
    child: Column(
      mainAxisSize: MainAxisSize.min,
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        Padding(
          padding: const EdgeInsets.symmetric(horizontal: 16),
          child: Text(
            'Map layers',
            style: Theme.of(context).textTheme.titleLarge,
          ),
        ),
        _materialSwitches(map),
      ],
    ),
  ),
);
```

### `good-material`

```dart
/// A modal bottom sheet, the Material place for a choice like this. Its
/// route closes it on Escape, because the sheet can be dismissed
/// (`isDismissible`, true by default); on Android's Back and on VoiceOver's
/// escape gesture, which pop the route on top; and through its barrier,
/// which a screen reader can dismiss. While it is open, Tab goes round its
/// two switches: a modal with a standard way out is not a trap.
class GoodMaterial extends StatelessWidget {
  const GoodMaterial({super.key});

  @override
  Widget build(BuildContext context) {
    return _Map(
      slug: 'good-material',
      show: (context, map) => showModalBottomSheet<void>(
        context: context,
        builder: (context) => _layersPanel(context, map),
      ),
    );
  }
}
```

```dart
/// A Cupertino modal popup. `barrierDismissible` is true by default, so
/// Escape closes it; `semanticsDismissible` makes its barrier one more
/// element a screen reader can use to close it.
class GoodCupertino extends StatelessWidget {
  const GoodCupertino({super.key});

  @override
  Widget build(BuildContext context) {
    return _Map(
      slug: 'good-cupertino',
      show: (context, map) => showCupertinoModalPopup<void>(
        context: context,
        semanticsDismissible: true,
        builder: (context) => CupertinoPopupSurface(
          child: SafeArea(
            top: false,
            child: ListenableBuilder(
              listenable: map.on,
              builder: (context, _) => CupertinoListSection(
                header: Text(
                  'Map layers',
                  style: TextStyle(
                    color: CupertinoColors.label.resolveFrom(context),

                ),
                children: [
                  for (final (key, name) in _layers)

                      map.id(key),

                              value: map.on.value.contains(key),
                              onChanged: (value) => map.on.value = value
                                  ? {...map.on.value, key}
                                  : ({...map.on.value}..remove(key)),
                            ),
                          ),
                        ),
                      ),
                    ),
                ],
              ),
            ),
          ),
        ),
      ),
```

### `good-widgets`

```dart
/// The layers drawn by hand in the app's overlay, with no route. Nothing
/// closes such an overlay by itself: Escape, Back, and the screen readers'
/// dismiss commands each need something of their own. [_Overlay] gives it
/// the dismiss action for screen readers and keeps Tab in it; this example
/// adds Escape and Back.
class GoodWidgets extends StatelessWidget {
  const GoodWidgets({super.key});

  @override
  Widget build(BuildContext context) =>
      const _Overlay(slug: 'good-widgets', escape: true, back: true);
}

/// A map whose layers are shown in an [OverlayEntry] over the screen,
/// behind a barrier that hides the screen from screen readers, as a route
/// does.
///
/// With [escape], Escape closes the layers: the app's default shortcuts
/// turn Escape into a `DismissIntent`, and an action for it is put around
/// the layers, where keyboard focus is. With [back], Android's Back and
/// VoiceOver's escape gesture close them: both ask the Navigator to pop
/// the route on top, which is the screen itself, and a `PopScope` stops
/// that while the layers are open and closes them instead.
class _Overlay extends StatefulWidget {
  const _Overlay({
    required this.slug,
    required this.escape,
    required this.back,
  });

  final String slug;
  final bool escape;
  final bool back;

  @override
  State<_Overlay> createState() => _OverlayState();
}

class _OverlayState extends State<_Overlay> {
  /// The layers' own focus scope. Tab and Shift+Tab go round inside it
  /// while the layers are open.
  final _scope = FocusScopeNode(
    debugLabel: 'Map layers',
    traversalEdgeBehavior: TraversalEdgeBehavior.closedLoop,
  );
  OverlayEntry? _entry;
  Completer<void>? _shown;
  FocusNode? _opener;

  @override
  void dispose() {
    _entry?.remove();
    _entry?.dispose();
    _scope.dispose();
    super.dispose();
  }

  Future<void> _show(BuildContext context, _MapState map) {
    _opener = FocusManager.instance.primaryFocus;
    _entry = OverlayEntry(builder: (context) => _layers(context, map));
    Overlay.of(context).insert(_entry!);
    setState(() {});
    _shown = Completer<void>();
    // Keyboard focus goes into the layers, to their first switch.
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (_entry != null) _scope.nextFocus();
    });
    return _shown!.future;
  }

  void _close() {
    final entry = _entry;
    if (entry == null) return;
    _entry = null;
    entry.remove();
    entry.dispose();
    if (mounted) setState(() {});
    // Keyboard focus goes back to the button that showed the layers.
    _opener?.requestFocus();
    _shown?.complete();
  }

  Widget _layers(BuildContext context, _MapState map) {
    Widget layers = Semantics(
      // For screen readers: TalkBack lists it as the Dismiss action, and
      // VoiceOver's escape gesture on any part of the layers performs it.
      onDismiss: _close,
      explicitChildNodes: true,
      child: FocusScope(
        node: _scope,
        child: Material(
          elevation: 8,
          borderRadius: const BorderRadius.vertical(top: Radius.circular(16)),
          child: _layersPanel(context, map),
        ),
      ),
    );
    if (widget.escape) {
      layers = Actions(
        actions: {
          DismissIntent: CallbackAction<DismissIntent>(
            onInvoke: (_) {
              _close();
              return null;
            },
          ),
        },
        child: layers,
      );
    }
    return Stack(
      children: [
        // Hides the screen from screen readers while the layers are open,
        // and closes them on a tap outside them.
        ModalBarrier(
          color: Colors.black54,
          onDismiss: _close,
          semanticsLabel: 'Close map layers',
        ),
        Align(alignment: Alignment.bottomCenter, child: layers),
      ],
    );
  }

  @override
  Widget build(BuildContext context) {
    final map = _Map(slug: widget.slug, show: _show);
    if (!widget.back) return map;
    return PopScope(
      canPop: _entry == null,
      onPopInvokedWithResult: (didPop, _) {
        if (!didPop) _close();
      },
      child: map,
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5, in the examples and in the
[probe](../evidence/probes/i08/README.md).

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Escape on a route whose barrier can be dismissed (`good-material`, `good-cupertino`) | closes it | closes it | closes it (sent as Command+period: XCUITest's Escape key never reached Flutter) |
| Escape on one that cannot (`bad-not-dismissible`) | nothing | nothing; it does not become Back | nothing |
| Escape on layers in the overlay | nothing, unless the app handles `DismissIntent` (`good-widgets` does, `bad-no-escape` does not) | the same | the same |
| Back | the browser's Back was not tried | the Back key and the global Back action (TalkBack's gesture) close a route, dismissible or not; in the overlay examples, only with the `PopScope`; without it the screen leaves (`bad-back-leaves`) | no Back key |
| A screen reader's dismiss command | none: VoiceOver's user presses Escape | TalkBack's Dismiss action on the barrier ("Scrim", "Dismiss", "Close map layers") or on the overlay's own node; none in `bad-not-dismissible` | VoiceOver's escape gesture: read in the source (the nearest element up with the dismiss action, else `popRoute`); not verified |
| Tab while the layers are shown | round the two switches in the overlay examples; in a sheet or popup route, out of the page past the last switch and back | round the two switches | round the two switches |

Things to know:

- **Leave the barrier dismissible.** Escape is the barrier's
  (`barrierDismissible`, `isDismissible`); turning the barrier off to stop
  stray taps also turns off the keyboard's way out
  ([FL-480](../flutter-limitations.md#fl-480)). If it must be off, give
  the sheet or dialog a button that closes it.
- **Know which dialogs are not dismissible by default.**
  `showCupertinoDialog`, `showGeneralDialog`, and `showCupertinoSheet`
  are not. A `CupertinoAlertDialog` shown with `showCupertinoDialog`'s
  defaults is a keyboard trap: its actions take no focus
  ([FL-440](../flutter-limitations.md#fl-440)).
- **Anything drawn in the overlay needs all three.** An action for
  `DismissIntent` around it, where keyboard focus is; a `PopScope` on the
  screen, so that Back closes it instead of leaving; and
  `Semantics(onDismiss:)` on it, for TalkBack's Dismiss action and
  VoiceOver's escape gesture ([FL-481](../flutter-limitations.md#fl-481)).
  Or show it as a route, which does the first two.
- **Put a barrier in an `OverlayEntry`, not an `OverlayPortal`.** In an
  `OverlayPortal` a `ModalBarrier` took the whole screen out of the
  semantics tree in a widget test, the layers too
  ([FL-483](../flutter-limitations.md#fl-483)).
- **Keeping Tab inside is fine; keeping it with no way out is not.**
  `Focus.onKeyEvent`, a `FocusTraversalPolicy`, and
  `TraversalEdgeBehavior.closedLoop` all keep Tab in; whichever is used,
  Escape has to be handled too.
- **Tooltips**: Escape hides one while keyboard focus is in the page;
  on the web, not while the page has no focus
  ([FL-482](../flutter-limitations.md#fl-482)).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-480](../flutter-limitations.md#fl-480): a route closes on Escape only when its barrier can be dismissed, and on Back and VoiceOver's escape gesture whether it can or not. `bad-not-dismissible` shows it.
- [FL-481](../flutter-limitations.md#fl-481): nothing closes an overlay that is not a route, and Back pops the screen under it. `good-widgets` handles all three; `bad-no-escape` and `bad-back-leaves` each leave one out.
- [FL-482](../flutter-limitations.md#fl-482): on the web, Escape does not hide a tooltip while the page has no keyboard focus.
- [FL-483](../flutter-limitations.md#fl-483): a `ModalBarrier` in an `OverlayPortal`'s overlay takes the whole screen out of the semantics tree. `good-widgets` uses an `OverlayEntry`.
- [FL-440](../flutter-limitations.md#fl-440): a `CupertinoAlertDialog`'s actions take no keyboard focus; with `showCupertinoDialog`'s barrier, which cannot be dismissed by default, no key gets out of it.

Every keyboard stop is named, never counted: by the node whose semantics
say it has focus in the widget tests and on Android, by
`document.activeElement` on the web, and on iOS by what Space does there
(it turns one switch). Every check that Escape does nothing sends it
alone, from each switch, reads the layers and the stop again a second
later, shows that Space still turns the switch, and then, in the same
launch, opens the good example the bad one is made from through the app's
own screens and shows the same Escape closing its layers. On iOS Escape is
sent as Command+period, which arrived in Flutter as Escape; XCUITest's own
Escape key never did ([probe](../evidence/probes/i08/README.md)). "The
screen left" is the technique's own screen, positively identified, with
the app still in front.

Not yet covered: VoiceOver's escape gesture on iOS (it cannot be made from
a test, so what it does is read in the engine's source and checked as the
messages it sends in the widget tests); the hardware Escape key on iOS;
Full Keyboard Access; a real Android keyboard; Switch Access and Switch
Control; VoiceOver in WebKit; the browser's Back on the web; a trap whose
way out is not standard and is told; and the dialogs, sheets, menus,
popovers, tooltips, and snack bars as components, which are C08 to C14.
