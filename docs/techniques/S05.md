# S05 Headings

Text that works as a heading is exposed to assistive technology as a heading,
with a level that matches its place in the page outline.

Code: [`lib/techniques/s05_headings/examples.dart`](../../lib/techniques/s05_headings/examples.dart).
Spec: [`docs/specs/S05-headings.md`](../specs/S05-headings.md).
In the app: `/t/S05`, and each example at `/t/S05/<slug>`.

## Why it matters

Sighted people skim a screen by its headings. Screen reader users do the same
with heading navigation: the VoiceOver rotor, TalkBack's reading controls, or
the H key in a desktop screen reader. That only works when headings are marked
as headings. Bold, large text that is not marked is just text, and the
structure of the screen is lost.

Levels matter on the web, where a screen reader announces "heading level 3"
and lets people jump by level. A skipped or wrong level describes a structure
the page does not have.

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): structure shown visually is available programmatically.
- [2.4.6 Headings and Labels](https://www.w3.org/TR/WCAG22/#headings-and-labels): headings describe their topic.

## Good examples

| Example | How | Source |

| `good-cupertino` | The `header` of a `CupertinoListSection` wrapped in the same `Semantics`. | [CVS Compose: Heading Semantics](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/content/HeadingSemantics.md), [CVS View: Heading Semantics](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/grouping/HeadingSemantics.md) |

Always set `headingLevel`. `header: true` on its own is not enough on any of
the three platforms; see the limitations below.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-visual-only` | Styled like a heading, but plain text to assistive technology. | 1.3.1 |
| `bad-fake-label` | The name is "Profile, heading". It sounds close, but it is not a heading and heading navigation cannot find it. | 1.3.1 |
| `bad-skipped-level` | A level 5 heading directly under a level 3 heading. | 1.3.1 |
| `bad-header-only` | `header: true` with no level (Flutter limitation). | 1.3.1 |
| `bad-emphasis-heading` | A sentence that introduces no section, marked as a heading to stand out. | 1.3.1, 2.4.6 |
| `bad-cupertino-section-header` | A `CupertinoListSection` header left as it is (Flutter limitation). | 1.3.1 |

### `good-levels`

```dart
/// A heading states that it is a heading and what level it is with
/// `Semantics(headingLevel:)`. Levels follow the page outline: the screen
/// title is level 1 and the "Example" section above is level 2, so this
/// content starts at level 3 and does not skip a level on the way down.
class GoodHeadingLevels extends StatelessWidget {
  const GoodHeadingLevels({super.key});

  @override
  Widget build(BuildContext context) {
    return const Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        Heading('Profile', level: 3),
        _Body('Your name and photo are shown to other members.'),
        Heading('Contact details', level: 4),
        _Body('We use these to reach you about your account.'),
        Heading('Email preferences', level: 4),
        _Body('Choose which messages you receive.'),
        Heading('Security', level: 3),
        _Body('Manage your password and sign-in methods.'),
      ],
    );
  }
}

/// Text exposed to assistive technology as a heading of [level].
class Heading extends StatelessWidget {
  const Heading(this.text, {super.key, required this.level});

  final String text;
  final int level;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.only(top: 8, bottom: 4),
      child: Semantics(
        header: true,
        headingLevel: level,
        child: Text(text, style: _headingStyle(context, level)),
      ),
    );
  }
}
```

### `good-cupertino`

```dart
/// The header of a Cupertino list section is not a heading on its own, so
/// it is given one.
class GoodCupertinoSectionHeading extends StatelessWidget {
  const GoodCupertinoSectionHeading({super.key});

  @override
  Widget build(BuildContext context) {
    return CupertinoListSection.insetGrouped(
      header: Semantics(
        header: true,
        headingLevel: 3,
        child: const Text('Notifications'),

      children: const [
        CupertinoListTile(title: Text('Order updates')),
        CupertinoListTile(title: Text('Offers')),
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `headingLevel: 3` | `<h3>` | `isHeading` true | header trait (not readable from XCUITest) |
| Screen reader | "heading level 3 Profile" (VoiceOver on macOS) | "Profile", "Heading" (TalkBack) | "Profile Heading" (VoiceOver) |
| Level exposed | yes | no, Android has one level | no level was spoken |
| `header: true` only | `<h2>` whatever the outline | not a heading | not announced as a heading |

Platform differences in the bad examples:

- `bad-skipped-level` can only be observed on web, where VoiceOver says
  "heading level 3 Profile" and then "heading level 5 Contact details". On
  Android and iOS both are simply headings.
- `bad-header-only` fails differently on each platform: not a heading on
  Android or for VoiceOver on iOS, and on web a level 2 heading that sits
  beside the "Example" section instead of under it.
- `bad-fake-label` is spoken as "Profile, heading" everywhere, which is why
  the defect is easy to miss by ear. The tree shows it is not a heading.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-003](../flutter-limitations.md#fl-003): `header: true` alone is not a
  heading for VoiceOver on iOS.
- [FL-004](../flutter-limitations.md#fl-004): `header: true` alone is always
  `<h2>` on web, including `AppBar` titles.
- [FL-005](../flutter-limitations.md#fl-005): `header: true` alone is not a
  heading on Android unless the node is a direct child of a scrolling list.
- [FL-014](../flutter-limitations.md#fl-014): `CupertinoListSection` does not
  expose its header as a heading.

The app shell follows its own advice: screen titles are wrapped in
`Semantics(headingLevel: 1)` and section headings set a level
(`lib/app/widgets.dart`).
