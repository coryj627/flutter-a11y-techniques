# S12 Hiding content from AT

Characters that only decorate, and text that only repeats what is said
beside it, are hidden from assistive technology, and content that is
closed or inactive, meant to be unavailable to everyone, is hidden from
everyone. Nothing a user needs, and no control, is hidden from a screen
reader while it is shown and can be operated. Content hidden from sight on
purpose for assistive technology alone, as in WCAG technique
[C7](https://www.w3.org/WAI/WCAG22/Techniques/css/C7), is a different case
and is not covered here.

Code: [`lib/techniques/s12_hiding_content/examples.dart`](../../lib/techniques/s12_hiding_content/examples.dart).
Spec: [`docs/specs/S12-hiding-content.md`](../specs/S12-hiding-content.md).
In the app: `/t/S12`, and each example at `/t/S12/<slug>`.

Platforms: all three apply. The good examples are Flutter's own
`ExcludeSemantics` and `Visibility` through their documented parameters,
and none is a custom solution
([custom-solutions.md](../custom-solutions.md#s12-hiding-content-from-at)).
What Flutter does not give, and the good examples do not need: a control
hidden from the screen reader keeps keyboard focus on every platform, with
no node, and on the web the page's focus stays on the element before it
([FL-350](../flutter-limitations.md#fl-350)). Hide only what has no control
in it.

## Why it matters

A screen reader reads what is in the semantics tree, one stop at a time.
An ornament left in it is a stop that says nothing a reader needs; a
badge's count beside the same words in text is heard twice. Hiding
those makes the screen shorter to hear and loses nothing. Hiding too much
is worse than hiding too little: a button hidden from the screen reader is
one its user cannot find or press, while someone using a keyboard can still
land on it and press it without the screen reader saying a word. And
content taken off the screen but left in the tree is read, and reached
with the keyboard, as if it were there.

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): what is shown must be determinable or in the text; hiding what only repeats or decorates loses nothing, and hiding what informs would.
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): a control hidden from the screen reader has no name or role that can be determined.

The sources: the iOS reference repository's
[Accessibility Hidden](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityHidden.md)
(hiding text is correct where "it is decorative or very short, such as a
badge number or a glyph, and the element around it already says what it
means"; "Don't use `.accessibilityHidden(true)` on any informative content
or UI controls"); WAI-ARIA 1.2's
[`aria-hidden`](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden), which
may hide "redundant or extraneous content" only where "identical or
equivalent meaning and functionality is exposed"; the
[fourth rule of ARIA use](https://www.w3.org/TR/using-aria/#fourth), never
`aria-hidden` on a focusable element; and the HTML Standard's
[`hidden`](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute),
"hidden from all presentations, including, for instance, screen readers",
and [`inert`](https://html.spec.whatwg.org/multipage/interaction.html#the-inert-attribute),
whose nodes "generally cannot be focused" and are not exposed "to
accessibility APIs or assistive technologies".

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-decoration` | A quote with a quotation mark "❝" before it and the ornament "✦ ✦ ✦" under it, each ornament in `ExcludeSemantics`: the screen reader reads the quote and who said it, nothing else. The ornaments are non-text content as WCAG defines it, pure decoration, and this meets 1.1.1's clause that such content "can be ignored by assistive technology" on all three platforms (1.1.1 is outside S12's list). | iOS Accessibility Hidden, WAI-ARIA aria-hidden |
| `good-badge` | A mail icon with a `Badge` "3" beside "Inbox: 3 unread": the badge in `ExcludeSemantics`, so the count is read once, in the words; the `Icon` has no `semanticLabel`, so it gives nothing. | iOS Accessibility Hidden ("a badge number") |
| `good-visibility` | A panel with a tracking number and a "Copy number" button, hidden until a switch shows it, with `Visibility(visible:, maintainState: true)`: while hidden it is not drawn, has no node, takes no tap, and the keyboard does not reach its button, because `Visibility` puts what it hides in an `ExcludeFocus`. | HTML Standard hidden, Visibility documentation |

What makes them work:

- **Hide only what has no control in it.** `ExcludeSemantics` drops the
  semantics of everything under it and does nothing to keyboard focus
  ([FL-350](../flutter-limitations.md#fl-350)).
- **Hide from everyone with `Visibility`**, which takes its child out of
  the tree and the keyboard's order together (probe p06 to p10; the
  keyboard tried on every platform for p07, p09, and p10). Not
  `Opacity` at 0 (`bad-opacity`) or `Offstage`
  ([FL-263](../flutter-limitations.md#fl-263)), which leave the keyboard's
  order alone, and not `Visibility.maintain` (`bad-maintain`), which keeps
  everything.
- **Not `Semantics(hidden: true)`**: it hides differently on each platform
  ([FL-351](../flutter-limitations.md#fl-351)).
- **Ornaments that are not hidden are still drawn in the text colour**, and
  the widget test checks their contrast itself: the contrast guideline
  reads the semantics tree and no longer sees them.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-decoration-read` | The ornaments are left as they are: each is a stop of its own, read as text | not a shown failure of a success criterion in this technique's list; shown for what the user hears. It fails 1.1.1, outside the list: "✦ ✦ ✦" and "❝" are non-text content (characters that express nothing in human language) and pure decoration, and VoiceOver stops on each on iOS and the web; on Android each is a node TalkBack reads when focused |
| `bad-hidden-control` | The ornament and a Share button in one `ExcludeSemantics`: no screen reader can find Share, and Tab still reaches it and Enter or Space runs it, with no node focused; on the web the page's focus stays on Back ([FL-350](../flutter-limitations.md#fl-350)) | 4.1.2, on every platform |
| `bad-opacity` | The panel hidden with `Opacity` at 0: not drawn and not in the tree, but its Copy button keeps keyboard focus, Enter and Space copy, and a tap where it is laid out copies (FL-350) | 4.1.2 on every platform; 2.4.7, measured in widget tests |
| `bad-maintain` | The panel hidden with `Visibility.maintain`: not drawn, but read by the screen reader, and its Copy button reached by Tab | none as written: not a shown failure of a success criterion in this technique's list; shown for what the user hears; 2.4.7 fails, measured in widget tests only, and is outside S12's list |

For 2.4.7 Focus Visible: while either panel is hidden, keyboard focus on
Copy draws nothing; the widget tests compare the screen's pixels with
focus on Copy and with no focus, and they are the same, while focus on the
shown Copy changes them. That was not measured on a device's screen.

### Shared code

Used by the examples below.

```dart
/// The quote the decoration examples show, and who said it.
const quoteText = 'Walk the ridge before the sun is up.';
const quoteSource = 'Trail guide';

/// The ornaments drawn round the quote: text that only decorates.
const quoteMark = '❝';
const ornament = '✦ ✦ ✦';

/// What the badge example's text says beside the badge.
const inboxText = 'Inbox: 3 unread';

/// The tracking number the panel examples hide and show.
const trackingText = 'Tracking number: 1Z 999';

/// A 2 pixel outline in the page's text colour while a Material button has
/// keyboard focus, through the button's own `style`, as in C18: Material's
/// own focus tint on a `TextButton` is under 3:1 against the page
/// (docs/flutter-limitations.md, FL-430).
ButtonStyle focusRing(ColorScheme colors) => ButtonStyle(
  side: WidgetStateProperty.resolveWith(
    (states) => states.contains(WidgetState.focused)
        ? BorderSide(color: colors.onSurface, width: 2)
        : null,
  ),
);

/// A count under an example, so that people and tests can confirm which
/// action ran: "Shares: 1". [id] is its test identifier.
class Count extends StatelessWidget {
  const Count({super.key, required this.id, required this.text});

  final String id;
  final String text;

  @override
  Widget build(BuildContext context) {
    return Semantics(
      key: ValueKey<String>(id),
      identifier: id,
      liveRegion: true,
      child: Text(text),
    );
  }
}

/// The quote between its ornaments. [hide] wraps each ornament: the good
/// example hides them, the bad one leaves them as they are.
class Quote extends StatelessWidget {
  const Quote({super.key, required this.hide});

  final Widget Function(Widget ornament) hide;

  @override
  Widget build(BuildContext context) {
    final text = Theme.of(context).textTheme;
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 8,
      children: [
        Row(
          crossAxisAlignment: CrossAxisAlignment.start,
          spacing: 8,
          children: [
            hide(Text(quoteMark, style: text.headlineMedium)),
            Expanded(child: Text(quoteText, style: text.titleMedium)),
          ],
        ),
        Text(quoteSource, style: text.bodyMedium),
        hide(Text(ornament, style: text.bodyLarge)),
      ],
    );
  }
}

/// A switch that shows the tracking number, the panel with the number and a
/// button that copies it, and a count of the copies. [hide] places the
/// panel and hides it while the switch is off: each panel example hides it
/// a different way.
class TrackingDemo extends StatefulWidget {
  const TrackingDemo({super.key, required this.slug, required this.hide});

  final String slug;
  final Widget Function(bool shown, Widget panel) hide;

  @override
  State<TrackingDemo> createState() => _TrackingDemoState();
}

class _TrackingDemoState extends State<TrackingDemo> {
  var _shown = false;
  var _copies = 0;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final slug = widget.slug;
    final panel = Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        const Text(trackingText),
        TestId(
          's12-$slug-copy',
          child: TextButton(
            style: focusRing(colors),
            onPressed: () => setState(() => _copies++),
            child: const Text('Copy number'),
          ),
        ),
      ],
    );
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 8,
      children: [
        TestId(
          's12-$slug-show',
          child: SwitchListTile(
            contentPadding: EdgeInsets.zero,
            title: const Text('Show tracking'),
            value: _shown,
            onChanged: (v) => setState(() => _shown = v),
          ),
        ),
        widget.hide(_shown, panel),
        Count(id: 's12-$slug-count', text: 'Copies: $_copies'),
      ],
    );
  }
}
```

### `good-decoration`

```dart
/// The quote's ornaments are characters that express nothing in human
/// language, which WCAG counts as non-text content, and they only decorate:
/// each is in `ExcludeSemantics`, so a screen reader reads the quote and who
/// said it, and nothing else, as 1.1.1 asks of pure decoration.
class GoodDecoration extends StatelessWidget {
  const GoodDecoration({super.key});

  @override
  Widget build(BuildContext context) {
    return Quote(hide: (ornament) => ExcludeSemantics(child: ornament));
  }
}
```

### `good-badge`

```dart
/// The badge's "3" repeats the "3 unread" beside it: the badge is in
/// `ExcludeSemantics`, so the count is read once, in the words beside it.
/// The mail icon has no `semanticLabel`, so `Icon` gives it no semantics.
class GoodBadge extends StatelessWidget {
  const GoodBadge({super.key});

  @override
  Widget build(BuildContext context) {
    return const Row(
      spacing: 16,
      children: [
        ExcludeSemantics(
          child: Badge(label: Text('3'), child: Icon(Icons.mail_outline)),
        ),
        Expanded(child: Text(inboxText)),
      ],
    );
  }
}
```

### `good-visibility`

```dart
/// While the switch is off the panel is hidden from everyone with
/// `Visibility`: it is not drawn, has no semantics, and, because
/// `Visibility` puts it in an `ExcludeFocus` while it is hidden, the
/// keyboard does not reach its button. `maintainState` keeps the panel's
/// state while it is hidden.
class GoodVisibility extends StatelessWidget {
  const GoodVisibility({super.key});

  @override
  Widget build(BuildContext context) {
    return TrackingDemo(
      slug: 'good-visibility',
      hide: (shown, panel) =>
          Visibility(visible: shown, maintainState: true, child: panel),
    );
  }
}
```

### `bad-decoration-read`

```dart
/// The ornaments are left as they are: a screen reader stops on each one,

/// It fails 1.1.1, outside that list: the ornaments are non-text content

class BadDecorationRead extends StatelessWidget {
  const BadDecorationRead({super.key});

  @override
  Widget build(BuildContext context) {
    return Quote(hide: (ornament) => ornament);
```

### `bad-hidden-control`

```dart
/// The ornament and the Share button are in one `ExcludeSemantics`: the
/// ornament is hidden, and so is the button. A screen reader cannot find it,
/// and the keyboard still reaches it.
class BadHiddenControl extends StatefulWidget {
  const BadHiddenControl({super.key});

  @override
  State<BadHiddenControl> createState() => _BadHiddenControlState();
}

class _BadHiddenControlState extends State<BadHiddenControl> {
  var _shares = 0;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 8,
      children: [
        Text(quoteText, style: Theme.of(context).textTheme.titleMedium),
        ExcludeSemantics(
          child: Wrap(
            spacing: 8,
            crossAxisAlignment: WrapCrossAlignment.center,
            children: [
              Text(ornament, style: Theme.of(context).textTheme.bodyLarge),
              TextButton(
                key: const ValueKey<String>('s12-bad-hidden-control-share'),
                style: focusRing(colors),
                onPressed: () => setState(() => _shares++),
                child: const Text('Share'),
              ),
            ],
          ),
        ),
        Count(id: 's12-bad-hidden-control-count', text: 'Shares: $_shares'),
      ],
    );
  }
}
```

### `bad-opacity`

```dart

/// not drawn and has no semantics, but its button keeps keyboard focus, and

class BadOpacity extends StatelessWidget {
  const BadOpacity({super.key});

  @override
  Widget build(BuildContext context) {

}
```

### `bad-maintain`

```dart
/// While the switch is off the panel is hidden with `Visibility.maintain`:
/// it is not drawn, but its semantics are kept, so a screen reader reads
/// the number and the button, and the keyboard reaches the button. This is
/// not a shown failure of a success criterion in this technique's list; shown for what the user hears; the 2.4.7 failure of its invisible focus was measured in
/// widget tests only and is outside S12's list.
class BadMaintain extends StatelessWidget {
  const BadMaintain({super.key});

  @override
  Widget build(BuildContext context) {
    return TrackingDemo(
      slug: 'bad-maintain',
      hide: (shown, panel) => Visibility.maintain(visible: shown, child: panel),
    );
  }
}
```

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-350](../flutter-limitations.md#fl-350) (new): a control hidden from the semantics tree keeps keyboard focus, and Enter and Space run it, with no node focused; on the web the page's focus stays on the element before it.
- [FL-351](../flutter-limitations.md#fl-351) (new, probe only): `Semantics(hidden: true)` hides a node and all under it on Android, only the node from VoiceOver's moving forward on iOS, and nothing on the web.
- [FL-263](../flutter-limitations.md#fl-263), extended: `Offstage`, and `Visibility` with `maintainFocusability`, do the same as FL-350; `Visibility(maintainState: true)` does not.
- [FL-421](../flutter-limitations.md#fl-421): on the web, Tab past Flutter's last control goes on into the page.
- [FL-430](../flutter-limitations.md#fl-430): Material's focus tint on a `TextButton` is under 3:1, so Copy and Share draw an outline through their own `style`.
