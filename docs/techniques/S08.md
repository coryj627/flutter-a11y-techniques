# S08 List semantics

Content shown as a list is exposed as a list, with each item an element of
its own, so that a screen reader says where the list starts and ends and,
where the platform has it, how many items it has. A list is never one block
of text, and a control that is a list item keeps its control's role.

Code: [`lib/techniques/s08_list_semantics/examples.dart`](../../lib/techniques/s08_list_semantics/examples.dart).
Spec: [`docs/specs/S08-list-semantics.md`](../specs/S08-list-semantics.md).
In the app: `/t/S08`, and each example at `/t/S08/<slug>`.

Platforms: iOS applies; Android and the web are limitations. Every good
example is Flutter's own widgets through their documented parameters, the
list roles of `SemanticsRole` given with `Semantics(role:)`; none is a
custom solution ([custom-solutions.md](../custom-solutions.md#s08-list-semantics)).
What Flutter does not give is recorded, not built:

- On Android a list made with the role says "In list" and "Out of list",
  but not its number of items or an item's place
  ([FL-311](../flutter-limitations.md#fl-311)), which a native list gives.
- A list that scrolls, Flutter's `ListView`, is not a list on the web
  ([FL-312](../flutter-limitations.md#fl-312)), says nothing of a list on
  Android ([FL-313](../flutter-limitations.md#fl-313)), and the role cannot
  be put round one ([FL-314](../flutter-limitations.md#fl-314)). So no
  long list here is a good example.
- A description list has no roles in Flutter
  ([FL-026](../flutter-limitations.md#fl-026)).
- Flutter gives a list nothing on iOS
  ([FL-310](../flutter-limitations.md#fl-310)): each item is an element of
  its own, which is what the iOS reference asks, and VoiceOver reads it by
  its text alone. VoiceOver does say "List start" and "1 of 3" for a web
  page's list in Safari; whether a native UIKit list gives the same was
  not measured, so iOS is recorded as applying.

## Why it matters

Someone who sees a list takes in at a glance that it is a list, how long it
is, and where it ends: three groceries, five steps, a column of settings. A
screen reader user gets that only if the list is exposed as a list. Then
the screen reader says that a list starts, on Android how many items it has
when the platform is told, and when it ends, so the user can tell the items
apart, skip the list, or know that what they hear next is no longer part of
it. A list written as lines of one text is read as one paragraph, and lines
that are not marked as a list are heard as loose text.

## WCAG 2.2

- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a list shown as a list, with its items, is a list to assistive technology where the platform has list semantics: the web's `ul`, `ol`, and `li` ([H48](https://www.w3.org/WAI/WCAG22/Techniques/html/H48)) and Android's collection information. For a native iOS view the iOS reference says there are none, and asks that each item be an element of its own.

The sources: the iOS reference repository's
[Lists](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/Lists.md)
(each item "individually focusable", never "one single paragraph"; iOS
"has no native list semantics"), the Android reference repositories'
[List Semantics (View)](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/grouping/ListSemantics.md),
[List Semantics (Compose)](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/content/ListSemantics.md),
and [ListItem Layouts](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/components/ListItemLayouts.md)
("In list", "Out of list", "1 of 3"), and HTML's
[`ul`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/ul),
[`ol`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/ol),
and [`dl`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dl).

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-bulleted` | `Semantics(role: SemanticsRole.list)` round a `Column`, and `Semantics(role: SemanticsRole.listItem)` round each line. The bullet is drawn, not text. A list of three items on the web; "In list" and "Out of list" on Android; three elements on iOS. | [Flutter: SemanticsRole](https://api.flutter.dev/flutter/dart-ui/SemanticsRole.html), MDN ul, Android View List Semantics |
| `good-numbered` | As `good-bulleted`, with each step's number in its text: Flutter has no ordered list. | MDN ol, iOS Lists |
| `good-material` | The roles round a `Column` of `ListTile(onTap:)`, each list item with `explicitChildNodes: true`, so that each tile is a button on every platform, inside its list item on the web and Android (XCUITest shows no hierarchy on iOS). | Android Compose ListItem Layouts, [Flutter: Semantics.explicitChildNodes](https://api.flutter.dev/flutter/widgets/Semantics/explicitChildNodes.html) |
| `good-cupertino` | The list role round a `CupertinoListSection(header:)`, which names the list by its header, and the list item role round each `CupertinoListTile`. The tiles do nothing: a `CupertinoListTile` with `onTap` takes no keyboard focus ([FL-400](../flutter-limitations.md#fl-400)). | [Flutter: CupertinoListSection](https://api.flutter.dev/flutter/cupertino/CupertinoListSection-class.html) |

What makes each of them work:

- **The list role directly round the widget that lays out the items**, and
  the list item role round each item, with nothing that makes a node in
  between. The framework checks that a list item's parent node is a list,
  and where it is not, a debug build sends no semantics for the screen at
  all ([FL-314](../flutter-limitations.md#fl-314)). So `TestId`, which is a
  node of its own, is not put round a list item.
- **`explicitChildNodes: true` on a list item that holds a control.**
  Without it the control is merged into the item, and on the web a node
  with a role is that role only: the tile is a list item and no button
  ([FL-262](../flutter-limitations.md#fl-262), `bad-tile-in-item`).
- **A short list, laid out whole.** A `ListView` is no list on the web and
  says nothing of a list on Android once it scrolls (`bad-lazy-list`).
- **Each number in its item's text** for an ordered list. HTML's `ol` gives
  a list marker; Flutter's list item has none.
- `good-material`'s keyboard focus is the tile's tint, under 3:1 against
  the page (FL-434: a change of background within the component, which
  1.4.11 as written leaves out), as C18's tappable card is.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-one-text` | The items are lines of one `Text`: one element, read as one paragraph | 1.3.1, on every platform |
| `bad-no-list` | Lines that look like a list, with no list role: nothing says they are a list | 1.3.1 on Android and the web; none on iOS, where a SwiftUI `List` gives no more (a native UIKit list was not measured) |
| `bad-tile-in-item` | `good-material` without `explicitChildNodes`: on the web each tile is a list item and not a button ([FL-262](../flutter-limitations.md#fl-262)) | 4.1.2 on the web; none on Android and iOS |
| `bad-lazy-list` | A long list in a `ListView.builder`: on Android and the web nothing says that it is a list ([FL-312](../flutter-limitations.md#fl-312), [FL-313](../flutter-limitations.md#fl-313)); it holds only the items near the view ([FL-011](../flutter-limitations.md#fl-011)) | 1.3.1 on Android and the web; none claimed on iOS |

`bad-lazy-list` is what the Flutter documentation gives for a long list:
its defect is Flutter's, not its author's, and there is no good example to
put beside it.

### Shared code

Used by the examples below.

```dart
/// The shopping list every unordered example shows.
const groceries = ['Milk', 'Eggs', 'Bread'];

/// The steps the ordered example shows, in order.
const steps = ['Fork the repository', 'Make the change', 'Open a pull request'];

/// A list: `SemanticsRole.list` round the widget that lays out its items.
/// Its items must be the nodes right under it: the framework checks that
/// every list item's parent node is a list.
Widget list(Widget child) => Semantics(role: SemanticsRole.list, child: child);

/// One item of a [list]: its texts are merged into the item's node.
Widget listItem(Widget child) =>
    Semantics(role: SemanticsRole.listItem, child: child);

/// The bullet drawn in front of an item. It is drawn, not text, so it adds
/// nothing to what assistive technology reads: the list's role says that
/// these are items, as a bullet does on the screen.
class Bullet extends StatelessWidget {
  const Bullet({super.key});

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.symmetric(horizontal: 8),
      child: DecoratedBox(
        decoration: BoxDecoration(
          color: Theme.of(context).colorScheme.onSurface,
          shape: BoxShape.circle,
        ),
        child: const SizedBox(width: 6, height: 6),
      ),
    );
  }
}

/// A bulleted line: the bullet, then [text].
class BulletLine extends StatelessWidget {
  const BulletLine(this.text, {super.key});

  final String text;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.symmetric(vertical: 4),
      child: Row(
        children: [
          const Bullet(),
          Flexible(child: Text(text)),
        ],
      ),
    );
  }
}

/// The line under a list of tiles that says which one was opened last:
/// "Chosen: Eggs". [id] is its test identifier.
class Chosen extends StatelessWidget {
  const Chosen({super.key, required this.id, required this.chosen});

  final String id;
  final String chosen;

  @override
  Widget build(BuildContext context) {
    return Padding(
      padding: const EdgeInsets.only(top: 8),
      child: Semantics(
        key: ValueKey<String>(id),
        identifier: id,
        liveRegion: true,
        child: Text('Chosen: $chosen'),
      ),
    );
  }
}
```

### `good-numbered`

```dart
/// A numbered list. Flutter has no ordered list, so each item's number is
/// part of its text, where it is read with the item.
class GoodNumbered extends StatelessWidget {
  const GoodNumbered({super.key});

  @override
  Widget build(BuildContext context) {
    return list(
      Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          for (final (i, step) in steps.indexed)
            listItem(
              Padding(
                padding: const EdgeInsets.symmetric(vertical: 4),
                child: Text('${i + 1}. $step'),
              ),
            ),
        ],
      ),
    );
  }
}
```

### `good-material`

```dart
/// A list of Material list tiles that each open something. Each tile is
/// kept a button of its own inside its list item with `explicitChildNodes`:
/// merged into the item, it would be a list item and no button on the web
/// (`bad-tile-in-item`).
class GoodMaterial extends StatefulWidget {
  const GoodMaterial({super.key});

  @override
  State<GoodMaterial> createState() => _GoodMaterialState();
}

class _GoodMaterialState extends State<GoodMaterial> {
  var _chosen = 'none';

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: [
        list(
          Column(
            children: [
              for (final g in groceries)
                Semantics(
                  role: SemanticsRole.listItem,
                  explicitChildNodes: true,
                  child: Semantics(
                    key: ValueKey<String>(
                      's08-good-material-${g.toLowerCase()}',
                    ),
                    identifier: 's08-good-material-${g.toLowerCase()}',
                    child: ListTile(
                      title: Text(g),
                      onTap: () => setState(() => _chosen = g),
                    ),
                  ),
                ),
            ],
          ),
        ),
        Chosen(id: 's08-good-material-chosen', chosen: _chosen),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// A Cupertino list section, named by its header: `SemanticsRole.list` round
/// the `CupertinoListSection`, which joins the header's text to the list,
/// and `SemanticsRole.listItem` round each `CupertinoListTile`. The tiles do
/// nothing when tapped: a `CupertinoListTile` with `onTap` takes no keyboard
/// focus and is not a button on Android and iOS (FL-400).
class GoodCupertino extends StatelessWidget {
  const GoodCupertino({super.key});

  @override
  Widget build(BuildContext context) {
    return list(
      CupertinoListSection(
        header: const Text('Groceries'),
        children: [
          for (final g in groceries)
            listItem(CupertinoListTile(title: Text(g))),
        ],
      ),
    );
  }
}
```

```dart
/// How many orders the long list holds.
const orderCount = 30;

class BadLazyList extends StatelessWidget {
  const BadLazyList({super.key});

  @override

      ),
    );
  }
```

## What each platform exposes

Measured on Flutter 3.47.5. Screen reader speech is from the transcripts
below; the rest from the tree tests and the probe
([evidence/probes/s08](../evidence/probes/s08/README.md)).

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A list made with the roles (`good-bulleted`) | a `list` holding three `listitem`s | an `android.widget.ListView` holding three `View`s; no collection information | three static texts; no element for the list |
| Screen reader on its items | not recorded yet (the first web VoiceOver recording is to come) | "Milk / In list", "Eggs", "Bread", with no number of items; "Out of list" on the line after a list (`good-material`; probe p03) | "Milk", "Eggs", "Bread"; no word about a list |
| A native list, for comparison | HTML `ul`: a `list` of `listitem`s with list markers | a native `ListView`: "Milk. 1 of 3. In list. 3 items" | the iOS reference: a SwiftUI `List` gives no list trait and no "1 of 6"; an HTML `ul` in Safari: "List start 1 of 3", "2 of 3", "3 of 3 List end" |
| Tiles in list items (`good-material`) | a `list`, each `listitem` holding a button | a `ListView`, each item holding a `Button` | three buttons |
| A tile merged into its item (`bad-tile-in-item`) | a focusable `listitem`, no button | a `ListView` of `Button`s | three buttons |
| A `ListView` that scrolls (`bad-lazy-list`) | no list; fewer than 30 items in the page (13 in the probe) | a `ScrollView` with 30 rows, not announced; rows wrong once scrolled | fewer than 30 items as elements (13 in the probe); VoiceOver stops once with no speech, then reads the 6 orders in view, and the screen ends there (in the probe it went on to the line after the list) |
| Tab | Back, then each tile | the same | the same (two Tabs reach the first tile) |

Things to know:

- **The count is Android's only.** A Flutter `ListView` laid out whole gives
  TalkBack "In list. 3 items", and with a height of its own and no need to
  scroll "1 of 3" as well (probe fixtures p06, p07), but it is no list on
  the web, and the roles cannot be added to it
  ([FL-312](../flutter-limitations.md#fl-312)). The good examples keep the
  web's list and give up Android's count.
- **A list named by a header**: the list role round a
  `CupertinoListSection` takes the header's text as the list's name: on
  the web `list "Groceries"`, on Android a focusable `ListView` read
  "Groceries / List", and its first item "In list Groceries" (probe
  fixture p25).
- **A nested list** (probe fixture p18) is a list inside a list item on
  the web, its items at level 2, and on Android "In list" and "Out of
  list" at the inner list; it was measured in the probe only.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-310](../flutter-limitations.md#fl-310): on iOS the list roles have no effect: VoiceOver says nothing about a list.
- [FL-311](../flutter-limitations.md#fl-311): on Android a list made with the role says "In list" and "Out of list", but not its size or an item's place.
- [FL-312](../flutter-limitations.md#fl-312): on the web a scrolling list is not a list, and the role cannot be put round one.
- [FL-313](../flutter-limitations.md#fl-313): on Android a list that scrolls says nothing about a list, and once scrolled its items report the wrong place.
- [FL-314](../flutter-limitations.md#fl-314): a list item whose parent is not a list fails the framework's check, and a debug build sends no semantics for the screen.
- [FL-011](../flutter-limitations.md#fl-011): a lazy list exposes only the items near the view, on every platform; on iOS, VoiceOver's moving forward leaves it after the items in view.
- [FL-262](../flutter-limitations.md#fl-262): on the web a node with a role is that role only; a tile merged into a list item is no button.
- [FL-026](../flutter-limitations.md#fl-026): no roles for a description list's terms and descriptions.
- [FL-400](../flutter-limitations.md#fl-400): a `CupertinoListTile` with `onTap` takes no keyboard focus, and is not a button on Android and iOS.
- [FL-434](../flutter-limitations.md#fl-434): Material's focus tint on a `ListTile`.
