# F06 Error identification and announcement

When a form is sent with a mistake, each field in error is marked invalid
and shows a message that says what is wrong and how to put it right. The
message is part of the field for assistive technology, the first error is
announced, and focus moves to the first field in error.

Code: [`lib/techniques/f06_error_identification/examples.dart`](../../lib/techniques/f06_error_identification/examples.dart).
Spec: [`docs/specs/F06-error-identification.md`](../specs/F06-error-identification.md).
In the app: `/t/F06`, and each example at `/t/F06/<slug>`.

Labels are [F01 Text fields and labels](F01.md). Announcements in general
are [I12 Announcements and live regions](I12.md).

## Why it matters

A sighted person who sends a form with a mistake sees the field turn red
and a line of text under it, and their eye goes there. A screen reader user
pressed a button and is still on it. Unless something tells them, they do
not know the form was refused, which field is wrong, or what it wants. A
red outline alone tells nobody who cannot see it, or cannot tell red from
grey, and a message such as "Invalid." tells nobody what to type instead.

So the error has to be in words, the words have to say how to put it
right, the field has to say it is in error when the user gets to it, the
first error has to be announced when the form is sent, and focus has to
go to the field so the user can fix it straight away.

## WCAG 2.2

- [3.3.1 Error Identification](https://www.w3.org/TR/WCAG22/#error-identification): the field in error is identified and the error is described in text.
- [3.3.3 Error Suggestion](https://www.w3.org/TR/WCAG22/#error-suggestion): where the app knows what would be right, the message says so.
- [4.1.3 Status Messages](https://www.w3.org/TR/WCAG22/#status-messages): an error that appears without taking focus is announced.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-color-only` | The validator returns an empty message. The field turns red and is marked invalid, and nothing says what is wrong. | 3.3.1 |
| `bad-vague-message` | The message is "Invalid.": it does not say what to enter, though the app knows. | 3.3.3 |
| `bad-not-announced` | `errorText` set with `setState`, outside a `Form`, with focus left on Send. On iOS and the web nothing announces it. | 4.1.3 on iOS and the web; none on Android, where the error text is a live region |
| `bad-merged-error` | `MergeSemantics` around the field takes in its error text. The error is part of the field's name and is read twice, and on Android the field becomes a live region. | none: noisy, but the error is still identified, described, and announced |

```dart
/// What each message says: what is wrong, and how to put it right.
const _nameError = 'Enter your name.';
const _emailError = 'Enter an email address with an @, like name@example.com.';

String? _validateName(String? value) =>
    (value == null || value.trim().isEmpty) ? _nameError : null;

String? _validateEmail(String? value) =>
    RegExp(r'^[^@\s]+@[^@\s]+\.[^@\s]+$').hasMatch(value ?? '')
    ? null
    : _emailError;

/// Lays out one example and counts the forms that were sent, so people and
/// tests can tell that a form with no errors goes through. The count is not
/// a live region: the only thing announced in these examples is an error.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback sent) builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('f06-${widget.slug}-count'),
          identifier: 'f06-${widget.slug}-count',
          child: Text('Sent: $_count'),
        ),
      ],
    );
  }
}

/// Moves focus to a field in error. Keyboard focus moves the cursor of
/// TalkBack and of VoiceOver on the web with it; VoiceOver on iOS stays
/// where it was, so the field is also sent a [FocusSemanticEvent], which
/// moves VoiceOver there.
void _focusField(FocusNode node) {
  node.requestFocus();
  WidgetsBinding.instance.addPostFrameCallback((_) {
    node.context?.findRenderObject()?.sendSemanticsEvent(
      const FocusSemanticEvent(),
    );
  });
}

/// The button that sends a form. A `TestId` is right here: the button is
/// one node either way. The fields are not wrapped in one (see good-form).
Widget _sendButton(String slug, VoidCallback onPressed) => TestId(
  'f06-$slug-send',
  child: FilledButton(onPressed: onPressed, child: const Text('Send')),
);
```

### `good-form`

```dart
/// A Material form. `TextFormField` shows the error under the field, puts
/// it in the field's hint, and marks the field invalid; `Form.validate()`
/// announces the first error where the platform supports announcements,
/// and on Android the error text is a live region. Focus then goes to the
/// first field in error, as both reference documents ask.
class GoodForm extends StatefulWidget {
  const GoodForm({super.key});

  @override
  State<GoodForm> createState() => _GoodFormState();
}

class _GoodFormState extends State<GoodForm> {
  final _form = GlobalKey<FormState>();
  final _name = GlobalKey<FormFieldState<String>>();
  final _email = GlobalKey<FormFieldState<String>>();
  final _nameFocus = FocusNode();
  final _emailFocus = FocusNode();

  @override
  void dispose() {
    _nameFocus.dispose();
    _emailFocus.dispose();
    super.dispose();
  }

  void _send(VoidCallback sent) {
    if (_form.currentState!.validate()) {
      sent();
      return;
    }
    for (final (field, focus) in [(_name, _nameFocus), (_email, _emailFocus)]) {
      if (field.currentState!.hasError) {
        _focusField(focus);
        return;
      }
    }
  }

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-form',
      builder: (context, sent) => [
        Form(
          key: _form,
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.stretch,
            spacing: 16,
            children: [
              // Semantics(identifier:) and not TestId: TestId's
              // MergeSemantics would pull the error text into the field's
              // name, so it would be read twice (see bad-merged-error).
              Semantics(
                identifier: 'f06-good-form-name',
                child: TextFormField(
                  key: _name,
                  focusNode: _nameFocus,
                  validator: _validateName,
                  textInputAction: TextInputAction.next,
                  decoration: const InputDecoration(
                    labelText: 'Name',
                    // Room for the whole message at 200% text on a narrow phone; the
                    // default is one line, cut off with an ellipsis.
                    errorMaxLines: 8,
                    border: OutlineInputBorder(),
                  ),
                ),
              ),
              Semantics(
                identifier: 'f06-good-form-email',
                child: TextFormField(
                  key: _email,
                  focusNode: _emailFocus,
                  validator: _validateEmail,
                  keyboardType: TextInputType.emailAddress,
                  decoration: const InputDecoration(
                    labelText: 'Email',
                    errorMaxLines: 8,
                    border: OutlineInputBorder(),
                  ),
                ),
              ),
            ],
          ),
        ),
        _sendButton('good-form', () => _send(sent)),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// A Cupertino form. The Cupertino library has no field that does all of
/// this, so each part is given as `InputDecorator` gives it: the field is
/// named, carries the error as its hint and its validation result, and the
/// visible error is a live region only where the platform cannot announce
/// (Android). `Form.validate()` announces the first error elsewhere.
class GoodCupertino extends StatefulWidget {
  const GoodCupertino({super.key});

  @override
  State<GoodCupertino> createState() => _GoodCupertinoState();
}

class _GoodCupertinoState extends State<GoodCupertino> {
  final _form = GlobalKey<FormState>();
  final _name = GlobalKey<FormFieldState<String>>();
  final _email = GlobalKey<FormFieldState<String>>();
  final _nameFocus = FocusNode();
  final _emailFocus = FocusNode();

  @override
  void dispose() {
    _nameFocus.dispose();
    _emailFocus.dispose();
    super.dispose();
  }

  void _send(VoidCallback sent) {
    if (_form.currentState!.validate()) {
      sent();
      return;
    }
    for (final (field, focus) in [(_name, _nameFocus), (_email, _emailFocus)]) {
      if (field.currentState!.hasError) {
        _focusField(focus);
        return;
      }
    }
  }

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-cupertino',
      builder: (context, sent) => [
        Form(
          key: _form,
          child: CupertinoFormSection.insetGrouped(
            margin: EdgeInsets.zero,
            children: [
              _CupertinoField(
                fieldKey: _name,
                id: 'f06-good-cupertino-name',
                label: 'Name',
                focusNode: _nameFocus,
                validator: _validateName,
              ),
              _CupertinoField(
                fieldKey: _email,
                id: 'f06-good-cupertino-email',
                label: 'Email',
                focusNode: _emailFocus,
                validator: _validateEmail,
                keyboardType: TextInputType.emailAddress,
              ),
            ],
          ),
        ),
        Align(
          alignment: Alignment.centerLeft,
          child: TestId(
            'f06-good-cupertino-send',
            child: CupertinoButton.filled(
              onPressed: () => _send(sent),
              child: const Text('Send'),
            ),
          ),
        ),
      ],
    );
  }
}

const _errorRed = CupertinoDynamicColor.withBrightness(
  color: Color(0xFFC4001A),
  darkColor: Color(0xFFFF8A80),
);

/// One Cupertino row: the label beside the field, the error under it.
class _CupertinoField extends StatelessWidget {
  const _CupertinoField({
    required this.fieldKey,
    required this.id,
    required this.label,
    required this.focusNode,
    required this.validator,
    this.keyboardType,
  });

  final GlobalKey<FormFieldState<String>> fieldKey;
  final String id;
  final String label;
  final FocusNode focusNode;
  final FormFieldValidator<String> validator;
  final TextInputType? keyboardType;

  @override
  Widget build(BuildContext context) {
    return FormField<String>(
      key: fieldKey,
      validator: validator,
      builder: (field) => CupertinoFormRow(
        // The field is named below; the visible label is not read twice.
        prefix: ExcludeSemantics(child: Text(label)),
        error: field.errorText == null
            ? null
            : Semantics(
                container: true,
                // As InputDecorator does: where announcements are not
                // supported, the error itself is announced when it appears.
                liveRegion: !MediaQuery.supportsAnnounceOf(context),
                child: Text(
                  field.errorText!,
                  // The row's default red is 3.5:1 on white; this is 4.5:1
                  // or more in light and dark.
                  style: TextStyle(color: _errorRed.resolveFrom(context)),
                ),
              ),
        child: Semantics(
          identifier: id,
          label: label,
          hint: field.errorText,
          validationResult: field.hasError
              ? SemanticsValidationResult.invalid
              : SemanticsValidationResult.valid,
          child: CupertinoTextField.borderless(
            focusNode: focusNode,
            keyboardType: keyboardType,
            onChanged: field.didChange,
          ),
        ),
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5, for `good-form` after Send with both fields
empty unless the row says otherwise.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Field in error | `<input>` named "Name", `aria-invalid="true"`, `aria-description` the error | `EditText`, hint text "Name, Enter your name."; no error, not content-invalid | text field labelled "Name"; the error is its hint |
| The visible error | text of its own after the field | a `View` of its own, a polite live region | a static text of its own |
| What is announced on Send | the first error, assertive, from `Form` | both errors (each a live region); Email's came first here, Name's first in `good-cupertino` | the first error, from `Form` |
| Where focus goes | DOM focus on Name, and VoiceOver with it | input and TalkBack focus on Name | keyboard focus on Name; VoiceOver moved by the `FocusSemanticEvent` |
| Screen reader after Send | "Name Enter your name. invalid data edit text", then "Enter your name." | "Enter an email address …", "Enter your name.", "Name, Enter your name. Editing. Edit box" | "Name Text field Is editing …", then "Enter your name." |
| Field in error with a value | not recorded | "abc, Edit box": no label and no error ([FL-180](../flutter-limitations.md#fl-180)) | not recorded; in the probe "Phone abc Text field Enter a phone number …" |
| Next element | not recorded | the error text, "Enter your name." | the error text, then "Email Text field Enter an email address …" |

TalkBack's lines are what it said with focus moved by the test, which
shows speech and not the order of a swipe. VoiceOver on iOS lines are the
first 64 characters of each utterance. The web lines are VoiceOver on
macOS in Chromium; Playwright's WebKit build passes no announcements to
VoiceOver (I12), so the web transcript is Chromium only.

In the bad examples:

- `bad-color-only`: every platform marks the field invalid where it can
  (`aria-invalid`, VoiceOver on the web "Email invalid data edit text") and
  says nothing about what is wrong. On Android and iOS nothing at all says
  it is wrong.
- `bad-vague-message`: "Invalid." is announced and read with the field.
- `bad-not-announced`: VoiceOver on the web and on iOS say nothing after
  Send, and the cursor stays on it. TalkBack announces the error, because
  on Android the error text is a live region whatever set it.
- `bad-merged-error`: the field is read with the error twice: "Email Enter
  an email address … Enter an email address … invalid data edit text" on
  the web, and the error is also in the iOS label. On Android it is in the
  hint text twice, and the field is a live region.

Things to know:

- **Use `Form` and `FormState.validate()`.** It is what announces an error
  on iOS and the web; an `errorText` set any other way is silent there
  ([FL-181](../flutter-limitations.md#fl-181)).
- **Move focus with both `requestFocus()` and a `FocusSemanticEvent`.**
  Keyboard focus moves TalkBack and the web; only the event moves
  VoiceOver on iOS ([FL-184](../flutter-limitations.md#fl-184)).
- **Do not wrap a field in `MergeSemantics`, or the project's `TestId`.**
  It takes in the error ([FL-183](../flutter-limitations.md#fl-183)). Use
  `Semantics(identifier:)`.
- **Do not add the error as a hint yourself.** `TextFormField` already
  does; a second one says it twice.
- **Set `errorMaxLines`.** The default cuts a message to one line.
- **Write the message as a fix**: what to enter, with an example when the
  format matters.
- **Build Cupertino forms by hand** until `CupertinoTextFormFieldRow`
  announces on Android ([FL-182](../flutter-limitations.md#fl-182)), and
  give the field a label ([FL-016](../flutter-limitations.md#fl-016)).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-180](../flutter-limitations.md#fl-180): Flutter gives a field no error state on Android. TalkBack never says "error", and reads a field in error that has a value as its value alone. No workaround; the message is the next element.
- [FL-015](../flutter-limitations.md#fl-015): the reason for that last part: TalkBack does not read a field's hint text once it has a value, and the error is in the hint text.
- [FL-181](../flutter-limitations.md#fl-181): an `errorText` is announced by itself on Android only. On iOS and the web only `Form.validate()` announces, and only the first error.
- [FL-182](../flutter-limitations.md#fl-182): `CupertinoTextFormFieldRow`'s error is never announced on Android. `good-cupertino` is built by hand instead.
- [FL-183](../flutter-limitations.md#fl-183): `MergeSemantics`, and so `TestId`, around a field takes in its error.
- [FL-184](../flutter-limitations.md#fl-184): keyboard focus moved to a field does not move VoiceOver on iOS. A `FocusSemanticEvent` does.
- [FL-016](../flutter-limitations.md#fl-016): a Cupertino text field has no label of its own.
- [FL-002](../flutter-limitations.md#fl-002): Enter does not press a `CupertinoButton` on the web; Space does.
