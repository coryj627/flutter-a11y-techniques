# F02 Input instructions

A field that needs a format or has rules shows them as text on the screen,
and the field carries the same words as its hint, so a screen reader reads
them with the field.

Code: [`lib/techniques/f02_input_instructions/examples.dart`](../../lib/techniques/f02_input_instructions/examples.dart).
Spec: [`docs/specs/F02-input-instructions.md`](../specs/F02-input-instructions.md).
In the app: `/t/F02`, and each example at `/t/F02/<slug>`.

A field's label is [F01](F01.md), and a hint on any control is
[S15 Hints](S15.md). Keyboard types, error messages, and required fields
are F03, F04, and F05.

## Why it matters

A sighted person sees "4 to 10 characters, no spaces." under a field before
they type. A screen reader user who moves to the field hears what the code
ties to it. If the instruction is only text near the field, they hear
"Username, edit box", type a name with a space in it, and find the rule
only when an error comes back, or when they happen to move on past the
field. If the instruction is only placeholder text, nobody can read it
once they start typing.

The words have to stay on the screen too. A hint can be turned off on
iOS, and on Android TalkBack stops reading a field's hint once the field
has a value. And text that is cut off at a large text size is not there
for the people who need the large text.

## WCAG 2.2

- [3.3.2 Labels or Instructions](https://www.w3.org/TR/WCAG22/#labels-or-instructions): a field that needs a format or follows rules says so, as text everyone can see, and the text stays available while the field is filled in.
- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): the instruction is drawn next to its field, and that relationship is in the code as well, so a screen reader reads it with the field.
- [1.4.4 Resize Text](https://www.w3.org/TR/WCAG22/#resize-text): the instruction can be read whole at 200% text.

The [Understanding document for 3.3.2](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)
decides two of the bad examples. It says 3.3.2 does not require an
instruction to be associated with its field (that is 1.3.1), so
`bad-helper-only`, whose instruction is on the screen the whole time,
fails 1.3.1 and not 3.3.2. It also says that authors "can choose to make
such instructions available to users only when the individual control has
focus", and, in the same section, that "when labels or instructions are
provided, they need to be persistently available to users". An
instruction shown whenever the field has focus meets both. A placeholder
does not: it is shown only while the field has focus and is empty, so it
is gone at the first character typed, with the field still focused, and
it comes back only if the value is deleted. That is why
`bad-placeholder-format` is said to fail 3.3.2. No documented failure
technique covers it (the one failure listed for 3.3.2 is F82, about phone
number fields); the outcome rests on that sentence of the Understanding
document, and the format is what sufficient technique
[G89](https://www.w3.org/WAI/WCAG22/Techniques/general/G89) asks to be
provided.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-helper-only` | `helperText` and no hint. The instruction is on the screen, but Flutter does not tie helper text to the field ([FL-140](../flutter-limitations.md#fl-140)): the field is read "Username, edit box", and the instruction is reached only as separate text after it. | 1.3.1 |
| `bad-placeholder-format` | The format "DD/MM/YYYY" is only the `hintText` of a field labelled "Date of birth". Material shows it only while the field is being edited and is empty ([FL-142](../flutter-limitations.md#fl-142)), so it is gone at the first character, for everyone. TalkBack and VoiceOver on iOS do not say it when they reach the field; VoiceOver on the web does, because moving onto the field focuses it. What is lost: the format, from the first character typed until the value is deleted, while the field is still being edited and after. | 3.3.2 (not persistently available; see above. [MDN: placeholder](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/placeholder)) |
| `bad-helper-cut-off` | `helperText` with the default `helperMaxLines`. At 200% text the instruction is cut to one line and ends in an ellipsis ([FL-141](../flutter-limitations.md#fl-141)). The field has it as its hint, so a screen reader reads it whole: the people who lose it are those who need large text. | 1.4.4 |

### Shared code

Used by the examples below.

```dart
/// Lays out one example and reports how many times its field changed, so
/// people and tests can confirm that typing reached it.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('f02-${widget.slug}-count'),
          identifier: 'f02-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

const _username = 'Username';
const _rule = '4 to 10 characters, no spaces.';
```

### `good-helper`

```dart
/// Material's place for an instruction is the helper text under the field.
/// On its own it is only text near the field, so the field is given the
/// same words as its hint: a screen reader reads them with the field. The
/// helper text stays on the screen and stays an element of its own.
///
/// The identifier is set with a plain `Semantics`, not `TestId`: the
/// `MergeSemantics` inside `TestId` would pull the helper text into the
/// field's name (docs/flutter-limitations.md, FL-140).
/// `helperMaxLines` lets the instruction wrap; by default it is cut to one
/// line (FL-141).
class GoodHelper extends StatelessWidget {
  const GoodHelper({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-helper',
      builder: (context, changed) => [
        Semantics(
          key: const ValueKey<String>('f02-good-helper-username'),
          identifier: 'f02-good-helper-username',
          hint: _rule,
          child: TextField(
            onChanged: (_) => changed(),
            decoration: const InputDecoration(
              labelText: _username,
              helperText: _rule,
              helperMaxLines: 4,
              border: OutlineInputBorder(),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `good-cupertino`

```dart
/// A Cupertino form row has a place for help text under the field. The
/// field has no label or hint of its own (FL-016), so it is given both, and
/// the visible label is left out of the semantics so it is not read twice.
class GoodCupertino extends StatelessWidget {
  const GoodCupertino({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-cupertino',
      builder: (context, changed) => [
        CupertinoFormSection.insetGrouped(
          margin: EdgeInsets.zero,
          children: [
            CupertinoFormRow(
              // Less padding than the default, so that the label and the
              // field fit side by side at 200% text on a narrow phone.
              padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 6),
              prefix: const ExcludeSemantics(child: Text(_username)),
              helper: const Text(_rule),
              child: TestId(
                'f02-good-cupertino-username',
                child: Semantics(
                  label: _username,
                  hint: _rule,
                  child: CupertinoTextField.borderless(
                    onChanged: (_) => changed(),
                  ),
                ),
              ),
            ),
          ],
        ),
      ],
    );
  }
}
```

### `good-before`

```dart

class GoodBefore extends StatelessWidget {

                    border: OutlineInputBorder(),
                  ),
                ),
              ),
            ),
          ],
        ),
      ],
    );
  }
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Field with `Semantics(hint:)` | `<input>` named by the label, `aria-description` the instruction | `EditText` with the hint text "Username, 4 to 10 characters, no spaces." | text field labelled "Username", with a hint XCUITest cannot read |
| Screen reader on it, empty | "Username 4 to 10 characters, no spaces. edit text" | "Username,", "4 to 10 characters, no spaces.", "Edit box" | "Username Text field 4 to 10 characters, no spaces. Double tap to…" |
| The same, with "abc" typed | "abc Insertion at end of text. Username 4 to 10 characters, no spaces. edit text" (Chromium; WebKit says "contents selected") | "Editing.", "abc", "Edit box": no name and no instruction ([FL-015](../flutter-limitations.md#fl-015)) | "Username abc Text field 4 to 10 characters, no spaces. Double ta…" |
| Helper text, or a form row's help text | text beside the `<input>` (inside the field's element for helper text) | a `View` with the text as its description | static text |
| Screen reader on it | "4 to 10 characters, no spaces." | "4 to 10 characters, no spaces." | "4 to 10 characters, no spaces." |
| Helper text and no hint | the `<input>` has no description | the hint text is "Username" | no hint |
| Screen reader on the field | "Username edit text" | "Username", "Edit box" | "Username Text field Double tap to edit." |
| Placeholder beside a label | `aria-label` gains "\nDD/MM/YYYY" and a `placeholder` while focused and empty | the hint text gains it while focused and empty | the label gains it while being edited and empty |
| Screen reader arriving on it | "Date of birth DD/MM/YYYY edit text" (WebKit): moving there focuses the field | "Date of birth", "Edit box" | "Date of birth Text field Double tap to edit." |

TalkBack's lines are what it said with focus moved to each node by the
test. The iOS test API returns the first 64 characters of an utterance.
The web lines are VoiceOver on macOS, the same in Chromium and WebKit
except where shown.

Things to know:

- **Give the field the instruction as its hint, in the same words as the
  text on the screen.** That is what ties them; helper text alone does not
  ([FL-140](../flutter-limitations.md#fl-140)).
- **Keep the visible instruction in the semantics.** It is read twice on
  iOS and the web, once with the field and once as text, as in the iOS
  reference. On Android it is the only way to reach the instruction once
  the field has a value: TalkBack then reads the field as "abc", "Edit
  box", and the helper text, the next stop, as "4 to 10 characters, no
  spaces." (the TalkBack transcript, `f02-good-helper-rule-filled`).
- **Do not wrap a field that has helper text in `MergeSemantics`** (or the
  project's `TestId`). The helper text becomes part of the field's name.
  Put an identifier on the same `Semantics` as the hint instead.
- **Set `helperMaxLines`** (or pass a `Text` as `helper:`). By default
  helper text is one line and is cut off with an ellipsis at large text
  sizes ([FL-141](../flutter-limitations.md#fl-141)).
- **Do not use placeholder text for a format.** With a label it is shown
  only while the field is being edited and is empty
  ([FL-142](../flutter-limitations.md#fl-142)).
- **A Cupertino field needs the label and the hint given to it**
  ([FL-016](../flutter-limitations.md#fl-016)); a `CupertinoFormRow`'s
  `helper` is the place for the visible text.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-140](../flutter-limitations.md#fl-140): Material helper text is not tied to its field, and inside `MergeSemantics` it joins the field's name. Workaround: the same words as the field's hint, with no `MergeSemantics`.
- [FL-141](../flutter-limitations.md#fl-141): helper text is cut to one line by default. Workaround: `helperMaxLines`.
- [FL-142](../flutter-limitations.md#fl-142): a placeholder beside a label is there only while the field is focused and empty, and is then part of the name.
- [FL-015](../flutter-limitations.md#fl-015): on Android TalkBack reads a field's label and hint only while it is empty, so the instruction on the field is lost once it has a value. The visible text, kept as an element, is how it is reached.
- [FL-016](../flutter-limitations.md#fl-016): Cupertino fields have no label or hint; `good-cupertino` gives them with `Semantics`.
- [FL-039](../flutter-limitations.md#fl-039) and [FL-041](../flutter-limitations.md#fl-041): on Android a field's hint is in its hint text with the label, and on the web it is `aria-description` on the `<input>`.
- [FL-042](../flutter-limitations.md#fl-042): a password field is a plain text field on iOS until it is edited (seen again in the F02 probe), which is why there is no password example here.

"abc" typed into the field: `good-helper` on all three, which is when
TalkBack drops the instruction, `bad-helper-only` with VoiceOver on iOS and
the web, and `bad-placeholder-format` with VoiceOver on the web. The
TalkBack walk types into one field only, at its end (see the spec).
