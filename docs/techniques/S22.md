# S22 Semantics identifiers for testing

An identifier lets a UI test find a control without depending on its text.
It is not read by a screen reader, so it never stands in for a name, and
adding one must not change what the control exposes.

Code: [`lib/techniques/s22_semantics_identifiers/examples.dart`](../../lib/techniques/s22_semantics_identifiers/examples.dart).
Spec: [`docs/specs/S22-semantics-identifiers.md`](../specs/S22-semantics-identifiers.md).
In the app: `/t/S22`, and each example at `/t/S22/<slug>`.

A control's name is [S01 Accessible names](S01.md). Every other technique
in this project finds its controls the way `good-merged` does, through the
`TestId` widget in [`lib/catalog/test_id.dart`](../../lib/catalog/test_id.dart).

## Custom solutions

What is built by hand:

- `good-custom`: A button drawn by hand: Semantics(button: true, label:,
  onTap:), with focus, keys, and a focus ring of its own.

The register of custom solutions, with the examples judged not to be one, is
[custom-solutions.md](../custom-solutions.md#s22-semantics-identifiers-for-testing).

## Why it matters

A test that finds a button by its text breaks when the text is translated
or reworded. An identifier is a second handle that only tests see:
`Semantics(identifier: 'save')` becomes the resource id on Android,
`accessibilityIdentifier` on iOS, and an attribute on the web.

Two things go wrong with it. The first is using it as a name. It is not
one: a screen reader never reads it, so an icon button with an identifier
and no label is still "Button". The second is specific to Flutter. Where
the `Semantics` widget goes decides which element gets the identifier, and
one of the obvious places, inside the button around its text, takes the
button's name away on Android and iOS. A change made only for tests has
then broken the control for the people the tests were meant to protect.

## WCAG 2.2

None applies to the technique: an identifier is for tests. Two of the bad
examples fail [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value)
as a side effect, because they leave a button with no name.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-merged` | `MergeSemantics(child: Semantics(identifier: 's22-good-merged-save', child: FilledButton(...)))`. The identifier is outside the button, and `MergeSemantics` folds it into the button's node: one element with the role, the name, and the identifier on every platform. | [iOS: Accessibility Identifier](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityIdentifier.md); [Apple: accessibilityIdentifier(_:)](https://developer.apple.com/documentation/swiftui/view/accessibilityidentifier(_:)); [Flutter: SemanticsProperties.identifier](https://api.flutter.dev/flutter/semantics/SemanticsProperties/identifier.html); [Flutter: MergeSemantics](https://api.flutter.dev/flutter/widgets/MergeSemantics-class.html) |
| `good-cupertino` (Custom solution, not vetted) | `TestId('s22-good-cupertino-save', child: CupertinoButton.filled(...))`. `TestId` is the same two widgets as `good-merged`. | iOS: Accessibility Identifier |
| `good-custom` (Custom solution, not vetted) | `TestId` around a button drawn by hand, outside both its focus handling and its `Semantics(button: true, label: ..., onTap: ...)`. | iOS: Accessibility Identifier |
| `good-field` | `TestId('s22-good-field-project', child: TextField(...))`. The field keeps its name, "Project name", from `labelText`. | iOS: Accessibility Identifier ("should not be used as a substitute for `.accessibilityLabel()`") |

How to choose and place an identifier:

- Put it outside the control and merge it. Never put it inside.
- Make it unique on the screen, and stable: do not build it from text that
  is translated.
- Give the control its name as you would without the identifier.

## Bad examples

Each has one defect, and the tests assert that the defect is present. Two
of the four change nothing for a user: this technique is about tests, and
their defect is what the test gets.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-inside` | The identifier is around the text inside a `FilledButton`. On Android and iOS the button loses its name: TalkBack and VoiceOver read "Button", then "Save draft" as separate text ([FL-007](../flutter-limitations.md#fl-007)). On the web the button keeps its name, and the identifier is on an element inside it that is not the button. | 4.1.2 on Android and iOS |
| `bad-wrapper` | The identifier is around a `FilledButton` with nothing to merge them. It ends up on an element of its own with no role, no name, and no action, around the button on web and Android and beside it on iOS ([FL-043](../flutter-limitations.md#fl-043)). Screen readers read the button as before. A test that finds the identifier has not found the button. | — |
| `bad-id-as-name` | An icon button with an identifier and no name. VoiceOver reads it as "button" and nothing else. TalkBack says "Button" and then guesses from the pixels ("Detected: Text, X"), which is not a name and is not the identifier. | 4.1.2 |
| `bad-duplicate` | Two buttons with the same identifier. Screen readers read both normally. A test that asks for the identifier gets two elements, or the first one without a warning. | — |

### Shared code

```dart
/// Lays out one example and reports how many times its control was
/// operated, so people and tests can confirm that it worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('s22-${widget.slug}-count'),
          identifier: 's22-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The keyboard half of a custom button and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no identifier.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}
```

### `good-merged`

```dart
/// A Material button with an identifier a UI test can find it by. The
/// identifier is outside the button, and `MergeSemantics` folds it into the
/// button's own node, so one node has the role, the name, and the
/// identifier on every platform. Screen readers do not read it.
///
/// This is what the project's `TestId` widget does
/// (lib/catalog/test_id.dart); the other examples use it.
class GoodMerged extends StatelessWidget {
  const GoodMerged({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-merged',
      builder: (context, changed) => [
        MergeSemantics(
          key: const ValueKey<String>('s22-good-merged-save'),
          child: Semantics(
            identifier: 's22-good-merged-save',
            child: FilledButton(
              onPressed: changed,
              child: const Text('Save draft'),
            ),
          ),
        ),
      ],
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Where the identifier is | the `flt-semantics-identifier` attribute | the node's resource id | `accessibilityIdentifier` |
| How a test finds it | `page.locator('[flt-semantics-identifier="x"]')` | `By.res("x")` | `app.buttons["x"]` |
| Merged around a Material button | `role="button"` named "Save draft", with the attribute | `Button`, description "Save draft", with the id | button "Save draft" with the identifier |
| Screen reader on it | "Save draft button" | "Save draft", "Button" | "Save draft Button" |
| Around a text field | on the element around the `<input>`, which is named "Project name" | `EditText` with the id, hint text "Project name" | text field "Project name" with the identifier |
| Screen reader on it | "Project name edit text" | "Project name", "Edit box" | "Project name Text field Double tap to edit." |
| Inside a Material button | on an element inside the button; the button is still named "Save draft" | `Button` with no description; a child `View` "Save draft" has the id | button with no label; a static text "Save draft" has the identifier |
| Screen reader on it | "Save draft button" | "Button", then "Save draft" as its own element | "Button", then "Save draft" |
| Around a Material button, not merged | on an element around the button, with no role | on a `View` whose child is the `Button` | on an `Other` element beside the button, with the same frame |
| Screen reader on it | "Save draft button" | "Save draft", "Button" | "Save draft Button" |
| Identifier and no name | button with no name | `Button` with no description | button with no label |
| Screen reader on it | "button" | "Button", then TalkBack's own guess from the picture: "Detected: Text, X" | "Button" |

TalkBack's lines are what it said with focus moved to each node by the
test. The web lines are VoiceOver on macOS, the same in Chromium and
WebKit. No identifier was heard anywhere, on any platform.

Things to know:

- **`MergeSemantics` around `Semantics(identifier:)` around the control**
  is the one form that gives a single element on all three platforms, for
  every control tried. Make it a widget, as `TestId` is.
- **Never put the identifier inside a control**
  ([FL-007](../flutter-limitations.md#fl-007)). It splits `FilledButton`,
  `OutlinedButton.icon`, `CupertinoButton`, and `ListTile` alike.
- **A plain wrapper works for some widgets and not others**
  ([FL-043](../flutter-limitations.md#fl-043)). It joins a
  `CupertinoButton`, `ListTile`, `TextField`, or `Text`, and misses every
  Material button. Merging removes the need to know which is which.
- **`MergeSemantics` merges everything under it.** It is safe around one
  control. Around a group it turns the group into one element, which
  changes what a screen reader user gets; put identifiers on the single
  controls.
- **On the web a text field's identifier and its name are on different
  elements.** Find the `<input>` inside the element with the attribute.
- **Nothing checks that identifiers are unique.** The widget tests here
  assert it for the good examples.
- **A `Key` is not an identifier.** `ValueKey` is for widget tests and
  never reaches a platform's accessibility tree. `TestId` sets both.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-007](../flutter-limitations.md#fl-007): an identifier inside a button takes the button's name away on Android and iOS. Workaround: identifier outside, merged. `bad-inside` shows what happens without it.
- [FL-043](../flutter-limitations.md#fl-043): an identifier around a Material button with no `MergeSemantics` stays on a node of its own, which is beside the button on iOS and around it elsewhere. Workaround: `MergeSemantics`. `bad-wrapper` shows what happens without it.
- [FL-002](../flutter-limitations.md#fl-002): `CupertinoButton` does not answer Enter on web; `good-cupertino` adds the action.

## How it is tested

| Layer | Where | Run |
| --- | --- | --- |
| Widget tests | `test/techniques/s22_semantics_identifiers_test.dart` | `flutter test` |
| Web tree | `web_tests/s22_semantics_identifiers.spec.js` | `flutter build web`, then `npx playwright test s22_semantics_identifiers.spec.js` in `web_tests/` |
| Android tree | `android/app/src/androidTest/.../S22SemanticsIdentifiersTest.kt` | `flutter build apk --debug` once, then `./gradlew app:connectedDebugAndroidTest` in `android/` |
| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py S22` |
| iOS tree | `ios/RunnerUITests/S22SemanticsIdentifiersUITests.swift` | `xcodebuild test` on the `Runner` scheme |
| VoiceOver speech (iOS) | same test class, `testVoiceOverSpeech` | `python3 tool/voiceover_ios.py S22` |
| VoiceOver speech (web) | `web_tests/vo/s22_semantics_identifiers_vo.spec.js` | `python3 tool/voiceover_web.py S22`; needs Guidepup setup, takes over the screen |

Each layer checks two things: that the element with the identifier is the
control, and that the identifier is in nothing a screen reader is given.
The second is checked in the tree (no label, value, description, or hint
contains it) and in speech (it is not heard).

Transcripts: [TalkBack](../evidence/S22/talkback-android.md),
[VoiceOver on iOS](../evidence/S22/voiceover-ios.md),
[VoiceOver on web](../evidence/S22/voiceover-web.md).

Not yet covered: Appium and Maestro, which read the same identifiers;
`find.bySemanticsIdentifier` in widget tests; and what `aria-controls` does
on the web when two elements share an identifier.
