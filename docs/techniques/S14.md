# S14 Values and state descriptions

A control that holds a value or a state says what it is now, in words, and
says so again whenever it changes.

Code: [`lib/techniques/s14_values_and_state_descriptions/examples.dart`](../../lib/techniques/s14_values_and_state_descriptions/examples.dart).
Spec: [`docs/specs/S14-values-and-state-descriptions.md`](../specs/S14-values-and-state-descriptions.md).
In the app: `/t/S14`, and each example at `/t/S14/<slug>`.

Which role a control has, and the on/off state that comes with the switch
role, is [S13 Roles and traits](S13.md). A control's name is
[S01 Accessible names](S01.md). The label of a tap action is left to I06
Action labels.

## Why it matters

Three filled stars out of five, the second of four circles filled in, a
repeat icon with a small "1" on it: each shows a value. A screen reader user
gets the control's name and role, and then needs the same fact in words:
"Rating, 3 out of 5", "Progress, step 2 of 4", "Repeat, one".

The SDK's controls do this themselves. A slider reads its position, a
switch reads on or off. A control drawn by hand reads nothing until
`Semantics` is given a `value`, and that value has to be rebuilt every time
the state changes, or the screen reader goes on reading the old one.

The value is kept apart from the name. The name says what the control is
and stays the same; the value says where it stands now.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the value and state of a control can be read by assistive technology, and so can a change to them.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-rating` | On web the rating has no accessible name ([FL-028](../flutter-limitations.md#fl-028)); its value is read there without it. `Semantics(label: 'Rating', value: '3 out of 5', increasedValue:, decreasedValue:, onIncrease:, onDecrease:)` around five stars that have no semantics of their own. A screen reader adjusts it with its own gesture; the arrow keys do the same. | [iOS: Accessibility Value](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/AccessibilityValue.md) (its star rating), [Apple: accessibilityValue](https://developer.apple.com/documentation/uikit/uiaccessibilityelement/accessibilityvalue), [MDN: aria-valuetext](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-valuetext) |
| `good-step` | `Semantics(label: 'Progress', value: 'Step 2 of 4')` around the circles, which are excluded. One element, read as the name and then the step. | iOS: Accessibility Value (its step indicator) |
| `good-button-value` | `Semantics(button: true, label: 'Repeat', value: 'Off')` on a button with three modes. It is not a switch, so the mode is a value. | iOS: Accessibility Value (a value on a custom control whose state is not otherwise exposed) |
| `good-slider-format` | On web the slider has no accessible name (FL-028), as for the rating. `Slider(semanticFormatterCallback: (v) => '${v.round()} minutes')`. A `Slider` reads a percentage by default; the callback replaces it with words that fit. | iOS: Accessibility Value (native controls give their own value); [Android Compose: Custom State Descriptions](https://github.com/cvs-health/android-compose-accessibility-techniques/blob/main/doc/interactions/CustomStateDescriptions.md) and [Android View: Custom State Descriptions](https://github.com/cvs-health/android-view-accessibility-techniques/blob/main/doc/dynamicbehaviors/CustomStateDescriptions.md) (rewording what a standard control says), [Android: View.setStateDescription](https://developer.android.com/reference/android/view/View#setStateDescription(java.lang.CharSequence)) |

`good-rating` and `good-slider-format` are the best that can be done on the
web with Flutter 3.47.5, not fully accessible there: the value is right and
the name is missing. No workaround was found in the SDK.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-rating-no-value` | The rating can be adjusted and has no value. A screen reader says "Rating, adjustable" and never how many stars. On the web the slider's range is also a single point; the arrow keys still change the rating, and whether a screen reader's adjust command can was not tested. | 4.1.2 |
| `bad-stale-value` | The value is fixed text, not built from the rating. The stars change and the value stays "3 out of 5". | 4.1.2 |
| `bad-step-no-value` | The circles are read as "1", "2", "3", "4", one element each. Nothing says which step is current. | 4.1.2, 1.3.1 |
| `bad-button-no-value` | The mode is shown by an icon only. The button is "Repeat, button" in all three modes. | 4.1.2 |
| `bad-value-on-switch` | `value` is used to reword a switch's state as "Activated" and "Deactivated", as the two Android reference documents do with a state description. Flutter has no state description. TalkBack reads both wordings, VoiceOver on iOS ignores the value, and on the web it becomes part of the switch's name. | — |

```dart
/// Lays out one example and reports how many times its controls were
/// operated, so people and tests can confirm that they worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('s14-${widget.slug}-count'),
          identifier: 's14-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

class _StepIntent extends Intent {
  const _StepIntent(this.by);

  final int by;
}

/// The keyboard half of a custom control and its focus ring. [onActivate]
/// answers Enter and Space; [onStep] answers the arrow keys. It gives the
/// control no role, no value, and no semantics action.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({this.onActivate, this.onStep, required this.child});

  final VoidCallback? onActivate;
  final ValueChanged<int>? onStep;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    final activate = widget.onActivate;
    final step = widget.onStep;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      shortcuts: {
        if (step != null) ...const {
          SingleActivator(LogicalKeyboardKey.arrowRight): _StepIntent(1),
          SingleActivator(LogicalKeyboardKey.arrowUp): _StepIntent(1),
          SingleActivator(LogicalKeyboardKey.arrowLeft): _StepIntent(-1),
          SingleActivator(LogicalKeyboardKey.arrowDown): _StepIntent(-1),
        },
      },
      actions: {
        if (activate != null) ...{
          ActivateIntent: CallbackAction<ActivateIntent>(
            onInvoke: (_) => activate(),
          ),
          ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
            onInvoke: (_) => activate(),
          ),
        },
        if (step != null)
          _StepIntent: CallbackAction<_StepIntent>(
            onInvoke: (intent) => step(intent.by),
          ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// Five stars, [rating] of them filled. A tap on a star sets the rating.
/// The picture has no semantics: each example says what it exposes.
class _Stars extends StatelessWidget {
  const _Stars({required this.rating, required this.onRate});

  final int rating;
  final ValueChanged<int> onRate;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return ExcludeSemantics(
      child: Row(
        mainAxisSize: MainAxisSize.min,
        children: [
          for (var star = 1; star <= 5; star++)
            GestureDetector(
              behavior: HitTestBehavior.opaque,
              onTap: () => onRate(star),
              child: SizedBox(
                width: 48,
                height: 48,
                child: Icon(
                  star <= rating ? Icons.star : Icons.star_border,
                  color: colors.onSurface,
                  size: 32,
                ),
              ),
            ),
        ],
      ),
    );
  }
}

/// Four numbered circles; the one for [step] is filled. No semantics.
class _StepDots extends StatelessWidget {
  const _StepDots({required this.step});

  final int step;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Row(
      mainAxisSize: MainAxisSize.min,
      spacing: 8,
      children: [
        for (var n = 1; n <= 4; n++)
          Container(
            width: 36,
            height: 36,
            alignment: Alignment.center,
            decoration: BoxDecoration(
              color: n == step ? colors.onSurface : colors.surface,
              border: Border.all(color: colors.onSurface, width: 2),
            ),
            child: Text(
              '$n',
              style: TextStyle(
                color: n == step ? colors.surface : colors.onSurface,
              ),
            ),
          ),
      ],
    );
  }
}

const _repeatModes = ['Off', 'All', 'One'];
const _repeatIcons = [Icons.arrow_forward, Icons.repeat, Icons.repeat_one];

/// What the repeat button looks like in each of its three modes.
class _RepeatFace extends StatelessWidget {
  const _RepeatFace({required this.mode});

  final int mode;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Container(
      width: 56,
      height: 48,
      decoration: BoxDecoration(
        border: Border.all(color: colors.onSurface, width: mode == 0 ? 1 : 3),
      ),
      child: Icon(_repeatIcons[mode], color: colors.onSurface),
    );
  }
}

/// The picture of a switch: its text, and a thumb at the left (off) or the
/// right (on) of a track. No semantics of its own.
class _SwitchFace extends StatelessWidget {
  const _SwitchFace({required this.text, required this.on});

  final String text;
  final bool on;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return Container(
      constraints: const BoxConstraints(minHeight: 48),
      padding: const EdgeInsets.symmetric(horizontal: 12, vertical: 8),
      child: Row(
        mainAxisSize: MainAxisSize.min,
        spacing: 12,
        children: [
          Flexible(
            child: Text(text, style: TextStyle(color: colors.onSurface)),
          ),
          Container(
            width: 56,
            height: 30,
            alignment: on ? Alignment.centerRight : Alignment.centerLeft,
            decoration: BoxDecoration(
              border: Border.all(color: colors.onSurface, width: 2),
            ),
            child: Container(
              width: 26,
              height: 26,
              color: colors.onSurface,
              child: Icon(
                on ? Icons.check : Icons.close,
                size: 18,
                color: colors.surface,
              ),
            ),
          ),
        ],
      ),
    );
  }
}
```

### `good-rating`

```dart
/// A star rating drawn by hand. `label` is its name and `value` is the
/// rating in words. `onIncrease` and `onDecrease` let a screen reader change
/// it, and `increasedValue` and `decreasedValue` say what it would become.
class GoodRating extends StatefulWidget {
  const GoodRating({super.key});

  @override
  State<GoodRating> createState() => _GoodRatingState();
}

class _GoodRatingState extends State<GoodRating> {
  int _rating = 3;

  String _words(int rating) => '${rating.clamp(0, 5)} out of 5';

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-rating',
      builder: (context, changed) {
        void rate(int rating) {
          final next = rating.clamp(0, 5);
          if (next == _rating) return;
          setState(() => _rating = next);
          changed();
        }

        return [
          TestId(
            's14-good-rating-rating',
            child: _KeyboardOperable(
              onStep: (by) => rate(_rating + by),
              child: Semantics(
                label: 'Rating',
                value: _words(_rating),
                increasedValue: _words(_rating + 1),
                decreasedValue: _words(_rating - 1),
                onIncrease: () => rate(_rating + 1),
                onDecrease: () => rate(_rating - 1),
                child: _Stars(rating: _rating, onRate: rate),
              ),
            ),
          ),
        ];
      },
    );
  }
}
```

```dart
/// Defect: `value` is used to reword a switch's "on" and "off" as

          setState(() => _on = !_on);

              ),
            ),
          ),

    );
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| `label` and `value` on text | the text "Progress Step 2 of 4" | description "Step 2 of 4, Progress" | label "Progress", value "Step 2 of 4" |
| Screen reader on it | "Progress Step 2 of 4" | "Step 2 of 4", "Progress" | "Progress Step 2 of 4" |
| `button` with `label` and `value` | `role="button"` named "Repeat Off" | `Button`, description "Off, Repeat" | button "Repeat", value "Off" |
| Screen reader on it | "Repeat Off button" | "Off", "Repeat", "Button" | "Repeat Off Button" |
| `label`, `value`, `onIncrease`, `onDecrease` | `<input type="range">` with `aria-valuetext="3 out of 5"`; the name is on the element around it | `SeekBar`, description "3 out of 5, Rating" | label "Rating", value "3 out of 5", adjustable |
| Screen reader on it | "Rating group", then "3 out of 5 dimmed slider" (Chromium) | "3 out of 5", "Rating", "Slider", "Swipe up or swipe down to adjust" | "Rating 3 out of 5 adjustable Swipe up or down with one finger to…" |
| The same with no `value` | `aria-valuetext=""`, minimum and maximum the same | `SeekBar`, description "Rating" | label "Rating", no value |
| Screen reader on it | "Rating group", then "1 dimmed slider" (Chromium) | "Rating", "Slider" | "Rating adjustable…" |
| `Slider` with `semanticFormatterCallback` | `aria-valuetext="15 minutes"` | `SeekBar`, "15 minutes, Timer" | "Timer", value "15 minutes" |
| Screen reader on it | "Timer group", then "15 minutes dimmed slider" (Chromium) | "15 minutes", "Timer", "Slider" | "Timer 15 minutes adjustable…" |
| `toggled` with a `value` | `role="switch"` named "Home alarm Deactivated" | `Switch`, not checked, description "Deactivated, Home alarm" | switch "Home alarm", value 0 |
| Screen reader on it | "Home alarm Deactivated off switch" | "off", "Deactivated", "Home alarm", "Switch" | "Home alarm Switch button off" |

TalkBack's lines are what it said with focus moved to each node by the test.
The iOS test API returns the first 64 characters of an utterance, so the
adjust hint is cut short. The web lines are VoiceOver on macOS; the slider
lines are from Chromium, where the name is read as a group before the
slider and not as the slider's name. "Dimmed" is as in S01
([FL-028](../flutter-limitations.md#fl-028)).

Things to know:

- **Build the value from the state.** A value written once is worse than
  none: it is read with confidence and is wrong.
- **Give `increasedValue` and `decreasedValue` with the adjust actions.** On
  Android they are read as the new value straight after an adjustment
  ([FL-038](../flutter-limitations.md#fl-038)), and on the web a slider
  without them has a range of one point.
- **Each platform puts the value somewhere else.** iOS keeps it apart from
  the label. Android puts it in front of the label in one description. The
  web appends it to the name ([FL-037](../flutter-limitations.md#fl-037)),
  so a test that finds a button by its name has to include the value.
- **Anything adjustable is a slider**, on all three platforms. On the web
  it then has no name ([FL-028](../flutter-limitations.md#fl-028)).
- **Do not put a `value` on a switch or checkbox.** It does not replace "on"
  and "off" anywhere ([FL-036](../flutter-limitations.md#fl-036)).
- **Use the role's own state where there is one.** On or off is `toggled`,
  ticked is `checked`, the chosen one is `selected` ([S13](S13.md)). `value`
  is for what no role carries.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-036](../flutter-limitations.md#fl-036): there is no way to reword the state of a switch or checkbox, and a `value` on one is handled differently on each platform. No workaround; `bad-value-on-switch` shows what happens.
- [FL-037](../flutter-limitations.md#fl-037): on web a `value` is appended to the accessible name.
- [FL-038](../flutter-limitations.md#fl-038): on Android an adjustable node shows `increasedValue` as its value straight after the action. Workaround: keep both neighbouring values right, as `good-rating` does.
- [FL-028](../flutter-limitations.md#fl-028): a slider has no accessible name on web. This affects both adjustable good examples, `good-rating` and `good-slider-format`, and has no workaround.

## How it is tested

| Layer | Where | Run |
| --- | --- | --- |
| Widget tests | `test/techniques/s14_values_and_state_descriptions_test.dart` | `flutter test` |
| Web tree | `web_tests/s14_values_and_state_descriptions.spec.js` | `flutter build web`, then `npx playwright test s14_values_and_state_descriptions.spec.js` in `web_tests/` |
| Android tree | `android/app/src/androidTest/.../S14ValuesAndStateDescriptionsTest.kt` | `flutter build apk --debug` once, then `./gradlew app:connectedDebugAndroidTest` in `android/` |
| TalkBack speech | same test class, `talkBackWalk` | `python3 tool/talkback.py S14` |
| iOS tree | `ios/RunnerUITests/S14ValuesAndStateDescriptionsUITests.swift` | `xcodebuild test` on the `Runner` scheme |
| VoiceOver speech (iOS) | same test class, `testVoiceOverSpeech` | `python3 tool/voiceover_ios.py S14` |
| VoiceOver speech (web) | `web_tests/vo/s14_values_and_state_descriptions_vo.spec.js` | `python3 tool/voiceover_web.py S14`; needs Guidepup setup, takes over the screen |

Every tree test reads the value, changes the control, and reads it again.
The TalkBack walk does the same: it focuses a control, moves focus to the
change count, changes the control, and focuses it a second time, so the
transcript has a "changed" line for it. The count is a live region, which
is why its announcements end the first line.
