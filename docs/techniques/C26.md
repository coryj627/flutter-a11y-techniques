# C26 Progress indicator

A progress indicator has a name that says what is in progress; a
determinate one has its value; and how the task is going, and that it has
ended, are status messages that a screen reader is given without focus
moving. Flutter announces no indicator's change by itself: a line of text
in a live region tells the status.

Code: [`lib/techniques/c26_progress_indicator/examples.dart`](../../lib/techniques/c26_progress_indicator/examples.dart).
Spec: [`docs/specs/C26-progress-indicator.md`](../specs/C26-progress-indicator.md).
In the app: `/t/C26`, and each example at `/t/C26/<slug>`.

Platforms: Android, iOS, and the web apply, each with limitations of the
framework's indicators that have no workaround in the SDK. On every
platform a change of an indicator's value is not announced
([FL-254](../flutter-limitations.md#fl-254)); the good examples tell the
status in a live region, which every platform announces. A spinner has no
role on any platform, and on iOS no indicator has one
([FL-256](../flutter-limitations.md#fl-256)): if an indicator counts as a
user interface component, as ARIA's `progressbar` does, that fails 4.1.2's
role for both spinners everywhere and for the bar on iOS. Whether that
makes those platforms a limitation, and whether the spinners are still
called good, awaits the owner's decision (the spec, section 8); until
then the platforms say "applies" with a note. The examples are good with
that qualification, not a recommendation.

Every example is Flutter's own indicator, configured only through its own
parameters (the owner's rule of 2026-11-21); nothing is built to fill what
it cannot do. No example is a custom solution
([custom-solutions.md](../custom-solutions.md#c26-progress-indicator)).

## Why it matters

A spinner or a bar is a picture of waiting. People who cannot see it need
it named ("Report upload", "Loading inbox"), the bar's value when they look
for it, and, above all, to be told when the task starts, how it is going,
and when it ends, without having to keep moving back to the indicator to
check. Otherwise they wait in silence, or move on before the content they
asked for has arrived.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the indicator's name, role, and value. The criterion covers user interface components, "perceived by users as a single control"; an indicator takes no input. This technique reads it as a component, as [WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/#progressbar) does (`progressbar` is a widget role, name required), and its 4.1.2 verdicts hold under that reading.
- [4.1.3 Status Messages](https://www.w3.org/TR/WCAG22/#status-messages): that a task has started, is under way, and has ended are status messages. [Understanding 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) gives a progress bar whose progress is announced "intermittently"; [ARIA25](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA25) does it with a live region beside the bar, because a `progressbar` is not one.

HTML's own indicator is the [`progress` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/progress):
role `progressbar`, indeterminate with no value, and labelled. The iOS
reference repository's [Progress Indicators](https://github.com/cvs-health/ios-swiftui-accessibility-techniques/blob/main/iOSswiftUIa11yTechniques/Documentation/ProgressIndicators.md)
asks for a label that matches the visible text, the value spoken, and an
announcement of a page's loading indicator. The Android reference
repositories have no entry.

## Good examples

| Example | How | Source |
| --- | --- | --- |
| `good-linear` | `LinearProgressIndicator(value:, semanticsLabel: 'Report upload')`, the same words shown above it in `ExcludeSemantics` so that they are read once, and its value the default, the percentage as a number. A status line in `Semantics(liveRegion: true)` says "Upload started", "Half uploaded", "Upload complete". | [Flutter: LinearProgressIndicator](https://api.flutter.dev/flutter/material/LinearProgressIndicator-class.html), [ARIA25](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA25) |
| `good-circular` | `CircularProgressIndicator(semanticsLabel: 'Loading inbox')`, shown while loading, with no value; the status line says "Loading started" and "Inbox loaded". | [Flutter: CircularProgressIndicator](https://api.flutter.dev/flutter/material/CircularProgressIndicator-class.html), [Flutter: semanticsLabel](https://api.flutter.dev/flutter/material/ProgressIndicator/semanticsLabel.html) |
| `good-cupertino` | `Semantics(label: 'Loading inbox')` round a `CupertinoActivityIndicator`, which has no name of its own ([FL-255](../flutter-limitations.md#fl-255)); the same status line. | [Flutter: CupertinoActivityIndicator](https://api.flutter.dev/flutter/cupertino/CupertinoActivityIndicator-class.html), [Flutter: Semantics.liveRegion](https://api.flutter.dev/flutter/widgets/Semantics/liveRegion.html) |

What makes them work:

- **A name for the indicator**, the words shown beside it.
- **A status line in a live region**, which changes at the start, halfway,
  and the end only. A line that changes at every step is spoken behind
  time (TalkBack, in the probe), and the indicator's own changes are never
  spoken ([FL-254](../flutter-limitations.md#fl-254)).
- **A bar determinate from the start**, at 0 before the task. A bar that
  starts indeterminate changes its role when it starts, which on the web
  loses its test identifier ([FL-259](../flutter-limitations.md#fl-259)).

What none of them gets: a role for a spinner, on any platform, or for any
indicator on iOS ([FL-256](../flutter-limitations.md#fl-256)); and a
well-read value. The bar keeps the framework's default value, the
percentage as a number, which keeps Android's range (the principal's
decision, the spec, section 8). As measured: TalkBack reads it twice,
"0.0.", "0,", "Report upload", "Progress bar"; VoiceOver on iOS reads the
bare number, "Report upload 0"; VoiceOver on the web reads it twice,
"Report upload 0 0% progress indicator", the name holding the value
([FL-037](../flutter-limitations.md#fl-037)) and then a percentage
([FL-027](../flutter-limitations.md#fl-027)). A percent sign in
`semanticsValue` reads once on Android and iOS and loses Android's
range.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-no-label` | `good-linear`'s bar with no `semanticsLabel`. The words above it are plain text: a screen reader reads them, then the bar as its value with no name: "0" on iOS, "0.0.", "0", "Progress bar" with TalkBack, "0 0% progress indicator" with VoiceOver on the web. | 4.1.2 (name), on all three |
| `bad-silent-end` | `good-linear` with its status line no live region. "Upload complete" appears and nothing announces it, nor the bar's changes ([FL-254](../flutter-limitations.md#fl-254)). | 4.1.3, on all three |
| `bad-adaptive` | `CircularProgressIndicator.adaptive(semanticsLabel:)`. On iOS, and in a browser on a Mac, it is Cupertino's spinner and drops the label: a screen reader finds nothing ([FL-257](../flutter-limitations.md#fl-257)). | 4.1.2 (name) on iOS and the web on a Mac; none on Android |
| `bad-cupertino-bar` | `CupertinoLinearActivityIndicator` as it comes: no name, role, or value ([FL-255](../flutter-limitations.md#fl-255)). | 4.1.2 (name and value), on all three |

The 4.1.2 verdicts hold under the reading above. `bad-adaptive` and
`bad-cupertino-bar` keep their status lines, so the status is still told:
what they fail is the indicator's own name.

### Shared code

Used by the examples below.

```dart
/// A task that runs for four steps of one second once started: [progress]
/// goes 0, 0.25, 0.5, 0.75, 1, and [done] is true at the end. It stands in
/// for an upload or a load, so that people and tests can watch it run.
class _Task extends ChangeNotifier {
  static const step = Duration(seconds: 1);

  double progress = 0;
  bool running = false;
  bool done = false;
  Timer? _timer;

  void start() {
    _timer?.cancel();
    progress = 0;
    running = true;
    done = false;
    notifyListeners();
    _timer = Timer.periodic(step, (timer) {
      progress = (progress + 0.25).clamp(0, 1);
      if (progress >= 1) {
        timer.cancel();
        running = false;
        done = true;
      }
      notifyListeners();
    });
  }

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }
}

/// Lays out one example: a button that starts the task, what [indicator]
/// draws for it, and a line of text, [status], that says how it is going.
/// With [live] the line is a live region, which a screen reader announces
/// when its text changes.
class _Demo extends StatefulWidget {
  const _Demo({
    required this.slug,
    required this.action,
    required this.indicator,
    required this.status,
    this.live = true,
  });

  final String slug;
  final String action;
  final Widget Function(BuildContext context, _Task task) indicator;
  final String Function(_Task task) status;
  final bool live;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  final _task = _Task();

  @override
  void dispose() {
    _task.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final slug = widget.slug;
    final colors = Theme.of(context).colorScheme;
    return ListenableBuilder(
      listenable: _task,
      builder: (context, _) => Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        spacing: 12,
        children: [
          TestId(
            'c26-$slug-start',
            child: OutlinedButton(
              onPressed: _task.start,
              // A 2 pixel outline in the page's text colour while the
              // button has keyboard focus, through its own style.
              style: ButtonStyle(
                side: WidgetStateProperty.resolveWith(
                  (states) => states.contains(WidgetState.focused)
                      ? BorderSide(color: colors.onSurface, width: 2)
                      : null,
                ),
              ),
              child: Text(widget.action),
            ),
          ),
          widget.indicator(context, _task),
          Semantics(
            key: ValueKey<String>('c26-$slug-status'),
            identifier: 'c26-$slug-status',
            liveRegion: widget.live,
            child: Text(widget.status(_task)),
          ),
        ],
      ),
    );
  }
}

/// What an upload's status line says: before, when it starts, halfway,
/// and at the end. It changes at those points only, so that a screen
/// reader is told how it is going now and then, and not at every step.
String _uploadStatus(_Task task) => task.done
    ? 'Upload complete'
    : task.running && task.progress >= 0.5
    ? 'Half uploaded'
    : task.running
    ? 'Upload started'
    : 'Not started';

/// What a load's status line says: before, during, and at the end.
String _loadStatus(_Task task) => task.done
    ? 'Inbox loaded'
    : task.running
    ? 'Loading started'
    : 'Inbox not loaded';

/// The visible name of an upload's bar, above it.
const _uploadName = 'Report upload';

/// The name of a load's spinner.
const _loadName = 'Loading inbox';

/// Room for a spinner, so that the line under it stays in place.
const _spinnerBox = Size.square(40);
```

### `good-linear`

```dart
/// A bar that shows how far an upload has gone. `semanticsLabel` names it
/// with the words shown above it, which are left out of the semantics so
/// that they are read once; its value is the indicator's own, the percentage
/// as a number. The status line under it, a live region, says that it has
/// started, when it is half done, and that it has finished: the bar's own value
/// changes are not announced (FL-254).
class GoodLinear extends StatelessWidget {
  const GoodLinear({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-linear',
      action: 'Upload report',
      status: _uploadStatus,
      indicator: (context, task) => Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        spacing: 8,
        children: [
          const ExcludeSemantics(child: Text(_uploadName)),
          TestId(
            'c26-good-linear-bar',
            child: LinearProgressIndicator(
              value: task.progress,
              semanticsLabel: _uploadName,
            ),
          ),
        ],
      ),
    );
  }
}
```

### `good-circular`

```dart
/// A spinner shown while the inbox loads, named by `semanticsLabel`. It has
/// no value: how long is left is not known. The status line, a live region,
/// says that loading has started and that it has ended, when the spinner
/// goes.
class GoodCircular extends StatelessWidget {
  const GoodCircular({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-circular',
      action: 'Load inbox',
      status: _loadStatus,
      indicator: (context, task) => SizedBox.fromSize(
        size: _spinnerBox,
        child: task.running
            ? const TestId(
                'c26-good-circular-spinner',
                child: CircularProgressIndicator(semanticsLabel: _loadName),
              )
            : null,
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5, in the tree tests and the probe
([evidence/probes/c26](../evidence/probes/c26/README.md)); speech from
the probe and the transcripts below.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| A named bar (`good-linear`) | `progressbar`, `aria-label` "Report upload 0", `aria-valuenow` 0 to 100; VoiceOver "Report upload 0 0% progress indicator" | `ProgressBar`, "0, Report upload", a range 0 to 100; TalkBack "0.0.", "0,", "Report upload", "Progress bar" | static text, label "Report upload", value "0"; VoiceOver "Report upload 0" |
| A named spinner (`good-circular`) | no role, `aria-label` "Loading inbox" | a `View` named "Loading inbox"; TalkBack says the name alone | static text "Loading inbox" |
| Cupertino's spinner, named (`good-cupertino`) | the text "Loading inbox", no role | a `View` named "Loading inbox" | static text "Loading inbox" |
| A bar with no name (`bad-no-label`) | `progressbar` named "0"; VoiceOver "0 0% progress indicator" | `ProgressBar` named "0" | an element with value "0" and no label |
| Cupertino's bar, and the adaptive spinner on Apple platforms | nothing | nothing (the adaptive one is Material's, named) | nothing; VoiceOver passes over it |
| The value changing | `aria-valuenow` changes; nothing announced | the range changes; nothing said | the value changes; nothing said |
| A status line in a live region | announced | announced | announced |

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-254](../flutter-limitations.md#fl-254): a change of an indicator's value is not announced.
- [FL-255](../flutter-limitations.md#fl-255): Cupertino's activity indicators give no semantics.
- [FL-256](../flutter-limitations.md#fl-256): a spinner has no role on any platform, and on iOS no indicator has one.
- [FL-257](../flutter-limitations.md#fl-257): `CircularProgressIndicator.adaptive` drops its label on iOS and in a browser on a Mac.
- [FL-258](../flutter-limitations.md#fl-258): a value in words fails the framework's check, and the default value is a number, not the documented percentage.
- [FL-259](../flutter-limitations.md#fl-259): on the web a node whose role changes loses its test identifier.
- [FL-027](../flutter-limitations.md#fl-027): a percent sign in the value loses Android's range; the default is read twice by TalkBack and by VoiceOver on the web, and as a bare number on iOS.
- [FL-037](../flutter-limitations.md#fl-037): on the web the bar's value is part of its name, and VoiceOver then reads the value again as a percentage.
- [FL-002](../flutter-limitations.md#fl-002): why `good-cupertino`'s button is Material's.
