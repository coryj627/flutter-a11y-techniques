# V12 Detecting accessibility settings

An app reads the user's settings through `MediaQuery`, which rebuilds it
when one changes, and does not count on a flag that a platform never sets.

Code: [`lib/techniques/v12_accessibility_settings/examples.dart`](../../lib/techniques/v12_accessibility_settings/examples.dart).
Spec: [`docs/specs/V12-accessibility-settings.md`](../specs/V12-accessibility-settings.md).
In the app: `/t/V12`, and each example at `/t/V12/<slug>`.

Platforms: Android and iOS apply; the web is a limitation, the
principal's decision (the spec, section 5), citing FL-500 and FL-501. On
Android a change of Bold text or of the contrast level starts the app
again (FL-504; the contrast level reaches the running app first); on iOS Reduce Motion needs the second flag (FL-502). Neither good example
is a custom solution. What Flutter does not tell an app is recorded, not
built:

- On the web `accessibleNavigation` says whether the app's semantics are
  on, not whether a screen reader is running, and an app that turns them
  on at start, as Flutter's web guide says to, is told one always is
  ([FL-500](../flutter-limitations.md#fl-500)). `highContrast` comes from
  forced colours only, and `boldText`, `invertColors`, and
  `onOffSwitchLabels` are never set
  ([FL-501](../flutter-limitations.md#fl-501)).
- On iOS Reduce Motion sets only `AccessibilityFeatures.reduceMotion`,
  which `MediaQueryData` does not carry; `disableAnimations` is never set
  ([FL-502](../flutter-limitations.md#fl-502), `bad-animations-only`).
  `good-motion` reads both.
- On Android `accessibleNavigation` turns on for any accessibility service
  that reads the app, and is off in a screen's first frame even with
  TalkBack on ([FL-503](../flutter-limitations.md#fl-503)); `highContrast`
  follows the contrast level, not "High contrast text"; a change of the
  contrast level reaches the running app and then starts it again, and
  Bold text reaches it only by starting it again
  ([FL-504](../flutter-limitations.md#fl-504)).
- Many iOS settings have no Flutter flag at all: Reduce Transparency,
  Button Shapes, Differentiate Without Color, and others
  ([FL-025](../flutter-limitations.md#fl-025), extended).

## Why it matters

Someone who turns on bold text, more contrast, less motion, or a screen
reader expects apps to follow. An app can only follow what the framework
tells it, and only while it is told: a setting read once and kept is wrong
as soon as the user changes it, and a flag that a platform never sets
looks like "off" to every user of that platform. The techniques that adapt
(high contrast, text size, reduced motion) all start here.

## WCAG 2.2

None of its own: V12 is an enabler. It serves the criteria of the
techniques that adapt to a setting: 1.4.3 and 1.4.6 (V02), 1.4.4 (V05),
2.2.2 and 2.3.3 (V09), and 2.2.1 where a time limit changes for a screen
reader user (C13). No example here passes or fails a criterion.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-read-once` | The same lines, read once from the platform dispatcher as the screen is first built: a setting changed while it is open is not shown. So TalkBack and VoiceOver read it "Accessible navigation: off": VoiceOver on iOS because it was turned on after the screen opened; TalkBack, on before, because on Android the first frame is told it is off ([FL-503](../flutter-limitations.md#fl-503)); on the web the first frame comes before the app's semantics are on ([FL-500](../flutter-limitations.md#fl-500)) | none (an enabler) |
| `bad-animations-only` | "Reduce motion" from `disableAnimations` alone: on iOS Reduce Motion never sets it, so the line stays off; on Android and the web it follows | none (an enabler) |

### Shared code

Used by the examples below.

```dart
/// "on" or "off".
String onOff(bool on) => on ? 'on' : 'off';

/// The settings the settings examples show, as the app was told them.
typedef Settings = ({
  bool accessibleNavigation,
  bool boldText,
  bool highContrast,
  bool invertColors,
  bool disableAnimations,
  bool onOffSwitchLabels,
  bool dark,
  int textScale,
});

/// One line of an example, one node, with the test identifier [id].
class SettingLine extends StatelessWidget {
  const SettingLine({super.key, required this.id, required this.text});

  final String id;
  final String text;

  @override
  Widget build(BuildContext context) {
    return Semantics(
      key: ValueKey<String>(id),
      container: true,
      identifier: id,
      child: Padding(
        padding: const EdgeInsets.symmetric(vertical: 4),
        child: Text(text),
      ),
    );
  }
}

/// The settings [settings] as one line each, identified
/// `v12-<slug>-<key>`, in this order.
class SettingLines extends StatelessWidget {
  const SettingLines({super.key, required this.slug, required this.settings});

  final String slug;
  final Settings settings;

  /// Each line's key and text.
  static List<(String, String)> lines(Settings s) => [
    ('navigation', 'Accessible navigation: ${onOff(s.accessibleNavigation)}'),
    ('bold', 'Bold text: ${onOff(s.boldText)}'),
    ('contrast', 'High contrast: ${onOff(s.highContrast)}'),
    ('invert', 'Invert colours: ${onOff(s.invertColors)}'),
    ('animations', 'Disable animations: ${onOff(s.disableAnimations)}'),
    ('labels', 'Switch labels: ${onOff(s.onOffSwitchLabels)}'),
    ('dark', 'Dark mode: ${onOff(s.dark)}'),
    ('scale', 'Text scale: ${s.textScale}%'),
  ];

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        for (final (key, text) in lines(settings))
          SettingLine(id: 'v12-$slug-$key', text: text),
      ],
    );
  }
}
```

### `good-media-query`

```dart
/// Each setting read with `MediaQuery`'s method for it. The widget depends
/// on each of those settings and is rebuilt when one of them changes, so
/// the lines say what is on now. The text scale is the scale for text of
/// 14 pixels, the body text's size: on Android 14 and later a text scaler
/// can scale large text less than small text.
class GoodMediaQuery extends StatelessWidget {
  const GoodMediaQuery({super.key});

  @override
  Widget build(BuildContext context) {
    final Settings settings = (
      accessibleNavigation: MediaQuery.accessibleNavigationOf(context),
      boldText: MediaQuery.boldTextOf(context),
      highContrast: MediaQuery.highContrastOf(context),
      invertColors: MediaQuery.invertColorsOf(context),
      disableAnimations: MediaQuery.disableAnimationsOf(context),
      onOffSwitchLabels: MediaQuery.onOffSwitchLabelsOf(context),
      dark: MediaQuery.platformBrightnessOf(context) == Brightness.dark,
      textScale: (MediaQuery.textScalerOf(context).scale(14) / 14 * 100)
          .round(),
    );
    return SettingLines(slug: 'good-media-query', settings: settings);
  }
}
```

### `good-motion`

```dart
/// Whether to reduce motion. Android's "Remove animations" and the web's
/// `prefers-reduced-motion` set `disableAnimations`; iOS's Reduce Motion
/// sets only `AccessibilityFeatures.reduceMotion`, which `MediaQueryData`
/// does not carry. So both are read, as the framework's own
/// `CupertinoMenuAnchor` reads both, and a `WidgetsBindingObserver` rebuilds
/// the line when the platform's features change.
class GoodMotion extends StatefulWidget {
  const GoodMotion({super.key});

  @override
  State<GoodMotion> createState() => _GoodMotionState();
}

class _GoodMotionState extends State<GoodMotion> with WidgetsBindingObserver {
  @override
  void initState() {
    super.initState();
    WidgetsBinding.instance.addObserver(this);
  }

  @override
  void didChangeAccessibilityFeatures() => setState(() {});

  @override
  void dispose() {
    WidgetsBinding.instance.removeObserver(this);
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final features = View.of(context).platformDispatcher.accessibilityFeatures;
    final reduce =
        MediaQuery.disableAnimationsOf(context) || features.reduceMotion;
    return SettingLine(
      id: 'v12-good-motion-motion',
      text: 'Reduce motion: ${onOff(reduce)}',
    );
  }
}
```

### `bad-read-once`

```dart
/// The same settings, read once when the screen opens, from the platform
/// dispatcher, and kept. Nothing rebuilds the lines, so a setting changed
/// while the screen is open is never shown.
class BadReadOnce extends StatefulWidget {
  const BadReadOnce({super.key});

  @override
  State<BadReadOnce> createState() => _BadReadOnceState();
}

class _BadReadOnceState extends State<BadReadOnce> {
  late final Settings _settings;

  @override
  void initState() {
    super.initState();
    final platform = WidgetsBinding.instance.platformDispatcher;
    final f = platform.accessibilityFeatures;
    _settings = (
      accessibleNavigation: f.accessibleNavigation,
      boldText: f.boldText,
      highContrast: f.highContrast,
      invertColors: f.invertColors,
      disableAnimations: f.disableAnimations,
      onOffSwitchLabels: f.onOffSwitchLabels,
      dark: platform.platformBrightness == Brightness.dark,
      textScale: (platform.textScaleFactor * 100).round(),
    );
  }

  @override
  Widget build(BuildContext context) {
    return SettingLines(slug: 'bad-read-once', settings: _settings);
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5: Android 17 emulator, iOS 27.0 simulator,
Chromium and WebKit through Playwright (the probe,
[evidence/probes/v12](../evidence/probes/v12/README.md)). "While running"
means the flag changed with the app open and nothing else happened.

| Flag | Android | iOS | Web |
| --- | --- | --- | --- |
| `accessibleNavigation` | TalkBack, while running; also any service that reads the app's nodes, such as UI Automator; off in a screen's first frame even with TalkBack on ([FL-503](../flutter-limitations.md#fl-503)) | VoiceOver, while running | whether the app's semantics are on: always, in this app, with no screen reader ([FL-500](../flutter-limitations.md#fl-500)) |
| `boldText` | Bold text, only when the app has started again, which the change causes ([FL-504](../flutter-limitations.md#fl-504)) | Bold Text, only when the app starts: on this simulator a native app was not told of a change while running either (`docs/evidence/probes/v12/ios-round3.txt`) | never ([FL-501](../flutter-limitations.md#fl-501)) |
| `highContrast` | the contrast level, while running, and then the app starts again; not "High contrast text" ([FL-504](../flutter-limitations.md#fl-504)) | Increase Contrast, while running | `forced-colors: active`, while running; not `prefers-contrast: more` ([FL-501](../flutter-limitations.md#fl-501)) |
| `invertColors` | Colour inversion, while running (the API documentation says iOS only) | Smart Invert, while running | never ([FL-501](../flutter-limitations.md#fl-501)) |
| `disableAnimations` | Remove animations (the transition animation scale), while running | never ([FL-502](../flutter-limitations.md#fl-502)) | `prefers-reduced-motion`, while running |
| `reduceMotion` (not in `MediaQueryData`) | never | Reduce Motion, while running | `prefers-reduced-motion`, with `disableAnimations` |
| `onOffSwitchLabels` | never | On/Off Labels, only when the app starts, as a native app (`ios-round3.txt`) | never |
| `platformBrightness` | Dark theme, while running | not measured: neither `XCUIDevice.appearance` nor `simctl ui appearance` changed the appearance of a native UIKit app on this simulator either | `prefers-color-scheme`, while running |
| `textScaler` | Font size, while running, on a curve (at 1.5, text of 14 drawn at 22, and of 100 at 100) | Larger Text (`simctl ui content_size`), while running: the largest size gave `scale(100)` 312 | the root font size, while running |
| `supportsAnnounce` | always false ([FL-018](../flutter-limitations.md#fl-018), I12) | true | true |
| `autoPlayAnimatedImages`, `autoPlayVideos`, `deterministicCursor` | never set | Auto-Play Animated Images, while running; Auto-Play Video Previews and Prefer Non-Blinking Cursor only when the app starts, as a native app (`ios-round3.txt`) | never set |

`MaterialApp` drew its `darkTheme` and `highContrastTheme` when the flags
changed, where they did. The settings the iOS reference lists that Flutter
has no flag for at all are in
[FL-025](../flutter-limitations.md#fl-025).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-500](../flutter-limitations.md#fl-500): on the web `accessibleNavigation` is whether semantics are on.
- [FL-501](../flutter-limitations.md#fl-501): on the web `highContrast` from forced colours only; bold, inverted colours, switch labels never set.
- [FL-502](../flutter-limitations.md#fl-502): on iOS Reduce Motion sets only `reduceMotion`, not `disableAnimations`.
- [FL-503](../flutter-limitations.md#fl-503): on Android `accessibleNavigation` for any service, and off in the first frame.
- [FL-504](../flutter-limitations.md#fl-504): on Android `highContrast` is the contrast level, which reaches the app and then starts it again; Bold text reaches it only by a new start.
- [FL-025](../flutter-limitations.md#fl-025), extended: the iOS settings with no Flutter flag.
- [FL-018](../flutter-limitations.md#fl-018): `supportsAnnounce` is false on Android (I12's).
