# F09 Switch

A switch and its label are one control with a name that does not change,
the switch role, and a state that is on or off. Switches that answer one
question are grouped under that question.

Code: [`lib/techniques/f09_switch/examples.dart`](../../lib/techniques/f09_switch/examples.dart).
Spec: [`docs/specs/F09-switch.md`](../specs/F09-switch.md).
In the app: `/t/F09`, and each example at `/t/F09/<slug>`.

A checkbox is [F07](F07.md) and radio buttons are [F08](F08.md). A
control's name is [S01 Accessible names](S01.md), its role is
[S13 Roles and traits](S13.md), and rewording a state is
[S14 Values and state descriptions](S14.md).

## Why it matters

A switch is a track with a thumb that sits at one end or the other, and a
word beside it. Sighted people read the word, see which end the thumb is
at, and tap anywhere on the row. A screen reader user gets only what the
code says: if the word and the switch are not joined, they hear "switch,
off" with no idea what it switches, and then a word on its own. If the
row is a button that happens to contain a switch, they hear a button that
never says whether anything is on.

The name has to stay put, too. A label such as "Bluetooth off" that turns
into "Bluetooth on" makes the state part of the name. The state is then
said twice, and someone who uses voice control, or who learned the
control by its name, finds a different name each time.

## WCAG 2.2

- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the name and role of a switch can be programmatically determined, and its state is available to assistive technology and kept up to date.
- [1.3.1 Info and Relationships](https://www.w3.org/TR/WCAG22/#info-and-relationships): a label belongs to its switch, and a question belongs to the switches under it. Those relationships are in the code, not only in the layout.

| `good-group` | `Semantics(container: true, explicitChildNodes: true, label: 'Notify me about', child: ...)` around the switches, with the visible question inside `ExcludeSemantics` so it is read once. | APG: Switch (a group of switches with a visible label is a `group` with a label) |

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unlabelled` | A `Switch` with a `Text` beside it in a `Row`. The switch has no name, the text is read as a separate element, and a tap on the text does nothing. | 4.1.2, 1.3.1 |
| `bad-tile-not-merged` | A `ListTile` with `onTap` and a `Switch` as `trailing`, not merged. The row is a button named "Bluetooth" with no state. The switch inside it has no name: a second stop on Android and iOS, and never reached by VoiceOver on the web. | 4.1.2, 1.3.1 |
| `bad-label-changes` | `SwitchListTile` whose title is "Bluetooth off" or "Bluetooth on". The name changes every time the switch does, and the state is heard twice. | 4.1.2 |
| `bad-no-state` | A hand-drawn switch exposed with `Semantics(button: true)`. It is read as a button, and nothing says whether it is on, before or after it is used. | 4.1.2 |

/// Lays out one example and reports how many times its control was
/// operated, so people and tests can confirm that it worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback changed)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('f09-${widget.slug}-count'),
          identifier: 'f09-${widget.slug}-count',
          liveRegion: true,
          child: Text('Changes: $_count'),
        ),
      ],
    );
  }
}

/// The keyboard half of a custom control and its focus ring: Enter and Space
/// call [onActivate]. It gives the control no role, no name, and no state.
class _KeyboardOperable extends StatefulWidget {
  const _KeyboardOperable({required this.onActivate, required this.child});

  final VoidCallback onActivate;
  final Widget child;

  @override
  State<_KeyboardOperable> createState() => _KeyboardOperableState();
}

class _KeyboardOperableState extends State<_KeyboardOperable> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: (_) => widget.onActivate(),
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: DecoratedBox(
        position: DecorationPosition.foreground,
        decoration: BoxDecoration(
          border: Border.all(
            color: _focused ? colors.onSurface : colors.surface,
            width: 3,
          ),
        ),
        child: Padding(padding: const EdgeInsets.all(5), child: widget.child),
      ),
    );
  }
}

/// A switch drawn by hand, with its text: a track with the thumb at the
/// right and a tick when [on], at the left and a cross when off. It has no
/// semantics of its own.
class _DrawnSwitch extends StatelessWidget {
  const _DrawnSwitch({required this.text, required this.on});

  final String text;
  final bool on;

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return ConstrainedBox(
      constraints: const BoxConstraints(minHeight: 48),
      child: Row(
        mainAxisSize: MainAxisSize.min,
        spacing: 12,
        children: [
          Flexible(child: Text(text)),
          Container(
            width: 56,
            height: 30,
            alignment: on ? Alignment.centerRight : Alignment.centerLeft,
            decoration: BoxDecoration(
              color: on ? colors.primary : colors.surface,
              border: Border.all(color: colors.onSurface, width: 2),
            ),
            child: Container(
              width: 26,
              height: 26,
              color: on ? colors.onPrimary : colors.onSurface,
              child: Icon(
                on ? Icons.check : Icons.close,
                size: 18,
                color: on ? colors.primary : colors.surface,
              ),
            ),
          ),
        ],
      ),
    );
  }
}

const _bluetooth = 'Bluetooth';

### `good-cupertino`

```dart
/// A Cupertino switch at the end of a list tile, as the `CupertinoSwitch`
/// documentation shows it. `CupertinoListTile` does not merge its parts, so
/// `MergeSemantics` makes the title and the switch one control, and the
/// tile's `onTap` makes the title part of the target.
class GoodCupertino extends StatefulWidget {
  const GoodCupertino({super.key});

  @override
  State<GoodCupertino> createState() => _GoodCupertinoState();
}

class _GoodCupertinoState extends State<GoodCupertino> {
  bool _on = false;

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-cupertino',
      builder: (context, changed) {
        void toggle() {
          setState(() => _on = !_on);
          changed();
        }

        return [
          TestId(
            'f09-good-cupertino-bluetooth',
            child: MergeSemantics(
              // A list tile is 44 high; the row is kept at 48, the size of
              // a touch target on Android.
              child: ConstrainedBox(
                constraints: const BoxConstraints(minHeight: 48),
                child: CupertinoListTile(
                  padding: EdgeInsets.zero,
                  title: const Text(_bluetooth),
                  trailing: CupertinoSwitch(
                    value: _on,
                    onChanged: (_) => toggle(),
                  ),
                  onTap: toggle,
                ),
              ),
            ),
          ),
        ];
      },
    );
  }
}
```

          setState(() => _on = !_on);
          changed();
        }

        return [
          TestId(
            'f09-good-custom-bluetooth',
            child: _KeyboardOperable(
              onActivate: toggle,
              child: Semantics(
                toggled: _on,
                enabled: true,
                label: _bluetooth,

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Switch, off | `role="switch"`, `aria-checked="false"`, named by its label | `Switch`, checkable, not checked | switch, value 0 |
| Screen reader on it | "Bluetooth off switch" | "off.", "Bluetooth", "Switch" | "Bluetooth Switch button off" |
| Switch, on | `aria-checked="true"` | checked | switch, value 1 |
| Screen reader on it | not recorded (the walks read each switch off) | "checked. on.", "Bluetooth", "Switch" | not recorded |
| Group with a label | `role="group"` named "Notify me about" around the switches | a `View` with the label whose children are the switches | an element with the label, before the switches |
| Screen reader on it | "Notify me about group" before the switches and "end of Notify me about group" after them | "Notify me about" | "Notify me about" |
| Switch and text not joined | text, then a switch with no name | a `View`, then a `Switch` with no description | static text, then a switch with no label |
| Screen reader on it | "Bluetooth", then "off switch" | "Bluetooth", then "off. Switch" | "Bluetooth", then "Switch button off" |
| `ListTile` with a trailing `Switch` | `role="button"` named "Bluetooth" with a switch with no name inside | `Button` with the name, around a `Switch` with no description | a button with the name, then a switch with no label |
| Screen reader on it | "Bluetooth button" (Chromium: "Bluetooth button, group"); the switch is never reached | "Bluetooth", "Button", then "off. Switch" | "Bluetooth Button", then "Switch button off" |

TalkBack's lines are what it said with focus moved to each node by the
test. The iOS test API returns the first 64 characters of an utterance. The
web lines are VoiceOver on macOS, the same in Chromium and WebKit except
where shown.

Things to know:

- **Use `SwitchListTile`**, or build the same thing: one merged node for
  the switch and its text, and a tap handler that covers the text.
- **Merge a `CupertinoListTile` that holds a switch.** It does not merge
  its parts by itself; the `CupertinoSwitch` documentation shows
  `MergeSemantics` around it, and `good-cupertino` does the same.
- **Do not put a `Switch` at the end of a plain `ListTile`.** With
  `onTap` the row becomes a button that says nothing about the state, and
  on the web the switch inside it cannot be reached by VoiceOver at all.
- **Give a custom switch `toggled` and `enabled: true`.** `toggled` gives
  the role and the state together; without `enabled` VoiceOver on iOS
  reads the switch as dimmed
  ([FL-033](../flutter-limitations.md#fl-033)).
- **Keep the state out of the label.** The switch already says on or off;
  "Bluetooth off" in the label says it twice and changes the name.
- **On Android a switch that is on is read "checked. on."**
  ([FL-100](../flutter-limitations.md#fl-100)). A native switch is read
  "on". There is nothing to change in the app.
- **On the web Enter does not toggle a `CupertinoSwitch`**
  ([FL-002](../flutter-limitations.md#fl-002)). Space does, which is what
  the APG pattern requires; Enter is optional there.
- **Do not reword the state.** There is no way to do it that works
  ([FL-036](../flutter-limitations.md#fl-036)).

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-100](../flutter-limitations.md#fl-100): TalkBack says "checked" as well as "on" for a Flutter switch that is on, where it says "on" for a native one. No workaround; the state is right.
- [FL-033](../flutter-limitations.md#fl-033): a switch with no `enabled` flag is read as dimmed on iOS. `good-custom` sets `enabled: true`.
- [FL-002](../flutter-limitations.md#fl-002): Enter does not toggle a `CupertinoSwitch` on the web. Space does.
- [FL-036](../flutter-limitations.md#fl-036): the words for the state cannot be changed.
