# S04 Functional images

An image or icon that is a control has a name that says what the control
does, and the name is on the control, not on the image.

Code: [`lib/techniques/s04_functional_images/examples.dart`](../../lib/techniques/s04_functional_images/examples.dart).
Spec: [`docs/specs/S04-functional-images.md`](../specs/S04-functional-images.md).
In the app: `/t/S04`, and each example at `/t/S04/<slug>`.

Images that only tell people something are covered by
[S02 Informative images](S02.md), images that add nothing by
[S03 Decorative images](S03.md), and what makes a button a button by
[C01 Button](C01.md). Image links are left to C03 Stand-alone link.

## Custom solutions

**Custom solution: not vetted by a real-world example.** `good-cupertino`,
`good-custom` and `good-image-regions` are custom solutions. Each is tested
here in isolation, with screen-reader transcripts, but has not been built
into a real app and tested in a user journey. Do not treat them as vetted
techniques.

What is built by hand:

- `good-cupertino`: An Actions built by hand round a CupertinoButton so that
  Enter works on the web, which the button does not handle (FL-002).
- `good-custom`: A picture made a button by hand from Semantics(button:
  true, label:), FocusableActionDetector, and a GestureDetector.
- `good-image-regions`: An image map built by hand: two named
  Semantics(button: true) regions with InkWells over an excluded Image, each
  with a focus ring; Flutter has no image map.

The register of custom solutions, with the examples judged not to be one, is
[custom-solutions.md](../custom-solutions.md#s04-functional-images).

## Why it matters

A magnifying glass, a printer, a small photo of a trail: a sighted person
sees the picture and knows what pressing it will do. A screen reader user
gets only what the control is named. With no name they hear "button" and
have to press it to find out. With a name that describes the picture
("magnifying glass") they have to work out what a magnifying glass does
here. The name has to be the action: "Search".

In Flutter there is a second trap, and it is `Image` again. The obvious way
to name a picture button is to give the picture a `semanticLabel`. That
works on the web and fails on Android and iOS: a labelled `Image` is always
an element of its own, so the button is read as "Button" with no name, and
the picture as a separate image. The name belongs on the button, and the
`Image` inside it is excluded. An `Icon` does not have this problem.

## WCAG 2.2

- [1.1.1 Non-text Content](https://www.w3.org/TR/WCAG22/#non-text-content): non-text content that is a control has a name that describes its purpose. An image button with no alternative is failure [F65](https://www.w3.org/WAI/WCAG22/Techniques/failures/F65); an alternative that does not serve the purpose is failure [F30](https://www.w3.org/WAI/WCAG22/Techniques/failures/F30).
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): the control has a name and the button role that assistive technology can read.

Where the name goes:

| The control | Its name |
| --- | --- |
| `IconButton` with an `Image` | `tooltip`, and `excludeFromSemantics: true` on the image |
| `IconButton` with an `Icon` | `tooltip`, or the icon's `semanticLabel` |
| `CupertinoButton` with an `Icon` | The icon's `semanticLabel` |
| Any button with text and a picture | The text. No label on the icon; `excludeFromSemantics: true` on an `Image` |
| A control you build yourself | `Semantics(button: true, label:)`, and `excludeFromSemantics: true` on the image |

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-no-name` | The picture button has no `tooltip` and the picture has no label. A screen reader says "button" and nothing else. | 1.1.1 (F65), 4.1.2 |
| `bad-label-on-image` | The name is the picture's `semanticLabel`. On Android and iOS the button has no name, and the picture is read as a second element: "Button", then "Open trail guide, Image". On the web the browser takes the button's name from the picture, so the defect cannot be heard there. | 4.1.2 on Android and iOS |
| `bad-tap-gesture` | A labelled `Image` in a `GestureDetector`. It is read as an image, not a button, and the keyboard cannot reach it. | 4.1.2, 2.1.1 |
| `bad-describes-picture` | The search button is named "Magnifying glass". The name says what the icon looks like, not what the button does. | 1.1.1 (F30) |
| `bad-image-not-excluded` | The picture beside the button's text is not excluded. VoiceOver on iOS reads "Trail guide, Button, Image", and on Android the button's class is `ImageView`. The web is not affected. | — |
| `bad-redundant-label` | The icon beside the text has a label too, so the button is named "Printer Print". | — |

```dart
/// The example photo at the size of a small picture button. `sunrisePng` is
/// the small PNG from S02 (`example_image.dart`).
Widget _picture({bool excludeFromSemantics = false, String? semanticLabel}) {
  return Image.memory(
    sunrisePng,
    width: 72,
    height: 48,
    fit: BoxFit.cover,
    filterQuality: FilterQuality.none,
    excludeFromSemantics: excludeFromSemantics,
    semanticLabel: semanticLabel,
  );
}

/// Lays out one example and reports how many times its controls were
/// activated, so people and tests can confirm that activation worked.
class _Demo extends StatefulWidget {
  const _Demo({required this.slug, required this.builder});

  final String slug;
  final List<Widget> Function(BuildContext context, VoidCallback activate)
  builder;

  @override
  State<_Demo> createState() => _DemoState();
}

class _DemoState extends State<_Demo> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 16,
      children: [
        ...widget.builder(context, () => setState(() => _count++)),
        Semantics(
          key: ValueKey<String>('s04-${widget.slug}-count'),
          identifier: 's04-${widget.slug}-count',
          liveRegion: true,
          child: Text('Activations: $_count'),
        ),
      ],
    );
  }
}
```

### `good-custom`

_Custom solution: not vetted by a real-world example. See "Custom solutions" near the top of this page._

```dart
/// A picture made into a button from the widgets layer. `Semantics` gives it
/// the button role and its name; the picture is excluded.
class GoodCustomImageButton extends StatelessWidget {
  const GoodCustomImageButton({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-custom',
      builder: (context, activate) => [
        TestId(
          's04-good-custom-guide',
          child: PictureButton(label: 'Open trail guide', onPressed: activate),
        ),
      ],
    );
  }
}

class PictureButton extends StatefulWidget {
  const PictureButton({
    super.key,
    required this.label,
    required this.onPressed,
  });

  final String label;
  final VoidCallback onPressed;

  @override
  State<PictureButton> createState() => _PictureButtonState();
}

class _PictureButtonState extends State<PictureButton> {
  bool _focused = false;

  Object? _activate(Intent intent) {
    widget.onPressed();
    return null;
  }

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      // Enter and Space reach the button as these intents through the
      // default shortcuts of WidgetsApp.
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(onInvoke: _activate),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: _activate,
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: Semantics(
        button: true,
        enabled: true,
        label: widget.label,
        child: GestureDetector(
          onTap: widget.onPressed,
          child: Container(
            padding: const EdgeInsets.all(4),
            decoration: BoxDecoration(
              border: Border.all(
                color: _focused ? colors.onSurface : colors.surface,
                width: 3,
              ),
            ),
            child: _picture(excludeFromSemantics: true),
          ),
        ),
      ),
    );
  }
}
```

```dart
/// One picture with two regions that each do something, like an HTML image
/// map. Each region is a button of its own with its own name; the picture
/// behind them is excluded.
class GoodImageRegions extends StatelessWidget {
  const GoodImageRegions({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-image-regions',
      builder: (context, activate) => [
        SizedBox(
          width: 240,
          height: 80,
          child: Stack(
            children: [
              Positioned.fill(
                child: Image.memory(
                  sunrisePng,
                  fit: BoxFit.cover,
                  filterQuality: FilterQuality.none,
                  excludeFromSemantics: true,
                ),
              ),
              Positioned(
                left: 0,
                top: 0,
                width: 120,
                height: 80,
                child: _Region(
                  id: 's04-good-image-regions-west',
                  label: 'West trail',
                  onPressed: activate,
                ),
              ),
              Positioned(
                left: 120,
                top: 0,
                width: 120,
                height: 80,
                child: _Region(
                  id: 's04-good-image-regions-east',
                  label: 'East trail',
                  onPressed: activate,
                ),
              ),
            ],
          ),
        ),
      ],
    );
  }
}

/// One region of the picture: a named button with nothing drawn in it until
/// it has keyboard focus.
class _Region extends StatefulWidget {
  const _Region({
    required this.id,
    required this.label,
    required this.onPressed,
  });

  final String id;
  final String label;
  final VoidCallback onPressed;

  @override
  State<_Region> createState() => _RegionState();
}

class _RegionState extends State<_Region> {
  bool _focused = false;

  @override
  Widget build(BuildContext context) {
    return TestId(
      widget.id,
      child: Semantics(
        button: true,
        label: widget.label,
        // An InkWell paints on the nearest Material. Without one above the
        // picture, its focus highlight would be painted under the picture.
        child: Material(
          type: MaterialType.transparency,
          child: InkWell(
            onTap: widget.onPressed,
            onFocusChange: (value) => setState(() => _focused = value),
            child: _focused
                // A black ring around a white one, so that the focused
                // region can be seen on any part of the picture.
                ? DecoratedBox(
                    key: ValueKey<String>('${widget.id}-focus'),
                    decoration: BoxDecoration(border: Border.all(width: 3)),
                    child: Padding(
                      padding: const EdgeInsets.all(3),
                      child: DecoratedBox(
                        decoration: BoxDecoration(
                          border: Border.all(
                            color: const Color(0xFFFFFFFF),
                            width: 3,
                          ),
                        ),
                        child: const SizedBox.expand(),
                      ),
                    ),
                  )
                : const SizedBox.expand(),
          ),
        ),
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Button named by `tooltip`, text, or `Semantics(label:)`, image excluded | `role="button"` with the name | `Button` with the description | button with the label |
| Screen reader on it | "Open trail guide button" | "Open trail guide", "Button" | "Open trail guide Button" |
| `IconButton` with `Icon(semanticLabel:)` | `role="button"` "Search" | `Button` "Search" | button "Search" |
| `IconButton` with `Image(semanticLabel:)` | `role="button"` with no `aria-label`, containing `role="img"` with the label | `Button` with no description, containing an `ImageView` with the label | button with no label, and an image with the label |
| Screen reader on it | "Open trail guide button", one stop | "Button", then "Open trail guide", "Image" | "Button", then "Open trail guide Image" |
| Button with an unlabelled `Image` that is not excluded, and text | `role="button"` "Trail guide" | `ImageView` "Trail guide" that can be clicked | button "Trail guide" |
| Screen reader on it | "Trail guide button" | "Trail guide", "Button" | "Trail guide Button Image" |
| `IconButton` with an unlabelled `Image` and no `tooltip` | `role="button"`, no name | `ImageView` with no description that can be clicked | button with no label |
| Screen reader on it | "button" | "Button" | "Button Image" |
| `GestureDetector` around `Image(semanticLabel:)` | `role="img"` with the label, no `tabindex` | a clickable `View` with no description, containing an `ImageView` with the label | an image with the label |
| Screen reader on it | "Open trail guide image" | "Button" or nothing on the first node (it differed between recordings); "Open trail guide", "Image" on the second | a stop with no speech, then "Open trail guide Image" |

TalkBack's lines are what it said with focus moved to each node by the test.

Things to know:

- **Name the button, not the `Image`.** `Image(semanticLabel:)` inside a
  button is read correctly on the web and leaves the button with no name on
  Android and iOS ([FL-030](../flutter-limitations.md#fl-030)). A test on the
  web alone will not find it.
- **`Icon` and `Image` behave differently.** `Icon(semanticLabel:)` names the
  button around it on all three platforms. `Image(semanticLabel:)` does not.
- **Exclude every `Image` inside a control.** One that is merely left
  without a label still marks the button as an image on Android and iOS
  ([FL-031](../flutter-limitations.md#fl-031)).
- **A tap handler on a picture is not a button.** It has no role, no
  keyboard access, and on Android and iOS the element that takes the tap
  is separate from the picture and has no name.
- **A wrong name passes every automated check.** `bad-describes-picture` is
  a button with a name. Only a person can tell that "Magnifying glass" is
  the wrong one.

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md). Both have a workaround in the
SDK, which the good examples use.

- [FL-030](../flutter-limitations.md#fl-030): a label on an `Image` inside a button does not name the button on Android and iOS.
- [FL-031](../flutter-limitations.md#fl-031): an `Image` left in a button's semantics makes the button an image as well on Android and iOS.
- [FL-002](../flutter-limitations.md#fl-002): Enter does not activate a `CupertinoButton` on web. `good-cupertino` adds the missing action, as C01 does.

Controls are found by their `TestId`. `bad-label-on-image` and
`bad-tap-gesture` have none, because `TestId` merges what it wraps and would
join the picture to the control; their elements are found by role, name, and
structure. Both VoiceOver tests compare the whole list of what is spoken
between the "Example" heading and the activation count, which is the last
element of every example, so they also show what is not spoken. On iOS a
move at which VoiceOver says nothing is kept in the list as "(no speech)",
but only after one move back has read the element before it and the move
forward again was silent too. The API reports silence as a timeout, which on
its own does not show that the cursor moved.
