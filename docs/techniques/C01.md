# C01 Button

A button exposes a name that describes its function, the button role, and its
enabled or disabled state, and can be operated by touch, keyboard, and
assistive technology.

Code: [`lib/techniques/c01_button/examples.dart`](../../lib/techniques/c01_button/examples.dart).
Spec: [`docs/specs/C01-button.md`](../specs/C01-button.md).
In the app: `/t/C01`, and each example at `/t/C01/<slug>`.

## Why it matters

A screen reader user hears a button as its name, its role, and its state, for
example "Save, button" or "Submit, dimmed, button". If the name is missing they
hear only "button". If the role is missing they hear text with no sign that it
can be activated. If the state is missing they cannot tell why activating it
does nothing. A keyboard or switch user needs to reach the button and activate
it without touch.

## WCAG 2.2

- [2.1.1 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard): reachable and operable from the keyboard.
- [2.4.6 Headings and Labels](https://www.w3.org/TR/WCAG22/#headings-and-labels): the name describes the purpose.
- [2.5.2 Pointer Cancellation](https://www.w3.org/TR/WCAG22/#pointer-cancellation): activates on release.
- [2.5.3 Label in Name](https://www.w3.org/TR/WCAG22/#label-in-name): the name contains the visible text.
- [4.1.2 Name, Role, Value](https://www.w3.org/TR/WCAG22/#name-role-value): name, role, and state are exposed.

## Bad examples

Each has one defect, and the tests assert that the defect is present.

| Example | Defect | Fails |
| --- | --- | --- |
| `bad-unlabelled-icon` | `IconButton` with no `tooltip`: a button with no name. | 4.1.2 |
| `bad-gesture-only` | A styled `Container` in a `GestureDetector`: no button role, no keyboard access. | 4.1.2, 2.1.1 |
| `bad-role-in-name` | The name is "Close button". | 2.4.6 |
| `bad-duplicate-names` | Three buttons all named "Edit". | 2.4.6 |
| `bad-name-mismatch` | Visible text "Edit", accessible name "Change username". | 2.5.3 |
| `bad-fake-disabled` | Looks disabled, still enabled and reported as enabled. | 4.1.2 |
| `bad-cupertino-disabled` | A disabled `CupertinoButton` reports no disabled state (Flutter limitation). | 4.1.2 |

### `good-cupertino`

```dart
/// Cupertino buttons expose their name and role. The disabled state and
/// Enter activation on web have to be added.
class GoodCupertinoButtons extends StatelessWidget {
  const GoodCupertinoButtons({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-cupertino',
      builder: (context, activate) => [
        TestId(
          'c01-good-cupertino-save',
          // Flutter 3.47.5: on web Enter is ButtonActivateIntent, which
          // CupertinoButton does not handle, so Enter would do nothing
          // (docs/flutter-limitations.md, FL-002). This adds the missing
          // action; Space already works.
          child: Actions(
            actions: {
              ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
                onInvoke: (_) {
                  activate();
                  return null;
                },
              ),
            },
            child: CupertinoButton.filled(
              onPressed: activate,
              child: const Text('Save'),
            ),
          ),
        ),
        // Flutter 3.47.5: CupertinoButton does not report its own disabled
        // state, so it is stated with Semantics(enabled: false). See
        // bad-cupertino-disabled for the button without it.
        TestId(
          'c01-good-cupertino-delete',
          child: Semantics(
            enabled: false,
            child: const CupertinoButton.filled(
              onPressed: null,
              child: Text('Delete'),
            ),
          ),
        ),
      ],
    );
  }
}
```

### `good-custom`

```dart
/// A custom-drawn button built from the widgets layer: it states its role
/// and state, takes keyboard focus, and activates from Enter and Space.
class GoodCustomButton extends StatelessWidget {
  const GoodCustomButton({super.key});

  @override
  Widget build(BuildContext context) {
    return _Demo(
      slug: 'good-custom',
      builder: (context, activate) => [
        TestId(
          'c01-good-custom-save',
          child: CustomButton(label: 'Save', onPressed: activate),
        ),
      ],
    );
  }
}

class CustomButton extends StatefulWidget {
  const CustomButton({super.key, required this.label, required this.onPressed});

  final String label;
  final VoidCallback onPressed;

  @override
  State<CustomButton> createState() => _CustomButtonState();
}

class _CustomButtonState extends State<CustomButton> {
  bool _focused = false;

  Object? _activate(Intent intent) {
    widget.onPressed();
    return null;
  }

  @override
  Widget build(BuildContext context) {
    final colors = Theme.of(context).colorScheme;
    return FocusableActionDetector(
      mouseCursor: SystemMouseCursors.click,
      // Enter and Space reach the button as these intents through the
      // default shortcuts of WidgetsApp.
      actions: {
        ActivateIntent: CallbackAction<ActivateIntent>(onInvoke: _activate),
        ButtonActivateIntent: CallbackAction<ButtonActivateIntent>(
          onInvoke: _activate,
        ),
      },
      onShowFocusHighlight: (value) => setState(() => _focused = value),
      child: Semantics(
        button: true,
        enabled: true,
        child: GestureDetector(
          onTap: widget.onPressed,
          child: Container(
            constraints: const BoxConstraints(minWidth: 48, minHeight: 48),
            padding: const EdgeInsets.symmetric(horizontal: 24, vertical: 12),
            decoration: BoxDecoration(
              color: colors.primary,
              borderRadius: BorderRadius.circular(8),
              border: Border.all(
                color: _focused ? colors.onSurface : colors.primary,
                width: 3,
              ),
            ),
            child: Text(
              widget.label,
              style: TextStyle(color: colors.onPrimary),
            ),
          ),
        ),
      ),
    );
  }
}
```

## What each platform exposes

Measured on Flutter 3.47.5.

| | Web | Android | iOS |
| --- | --- | --- | --- |
| Role | `role="button"` | class `android.widget.Button` | element type button |
| Name | text content of the node | content description | label |
| Disabled | `aria-disabled="true"`, not in the Tab order | `isEnabled` false | not enabled |
| Screen reader, enabled | "Save button" (VoiceOver on macOS) | "Save", "Button", "Double-tap to activate" (TalkBack) | "Save Button" (VoiceOver) |
| Screen reader, disabled | "Submit dimmed button" (VoiceOver on macOS) | "Submit", "Button. disabled" | "Submit dimmed Button" |

Platform differences in the bad examples:

- `bad-gesture-only`: Android and iOS expose it with no button role. Flutter web
  gives every tappable node `role="button"`, so on web VoiceOver says "Save
  button" and the defect is that it has no `tabindex` and cannot be reached
  with Tab.
- `bad-role-in-name`: TalkBack says "Close button. Button" and VoiceOver on
  web says "Close button button". VoiceOver on iOS says "Close Button" once,
  because it does not repeat a role the name already ends with. The defect is
  still in the tree on iOS (label "Close button").
- `good-icon`: in Chromium, VoiceOver reads the button ("Close button") and
  then finds a second item, "Close", and an empty one. WebKit, TalkBack, and
  VoiceOver on iOS read the button once. Cause not investigated; it looks like
  the tooltip being exposed as separate content on Chromium.
- `bad-unlabelled-icon`: VoiceOver says only "Button". TalkBack says "Button"
  and may add its own guess from the icon ("Detected: Text, X").

## Flutter limitations

Found on Flutter 3.47.5. Full detail is in the
[limitations log](../flutter-limitations.md).

- [FL-001](../flutter-limitations.md#fl-001): a disabled `CupertinoButton`
  reports no disabled state. `good-cupertino` adds it with
  `Semantics(enabled: false)`; `bad-cupertino-disabled` shows the widget
  without it.
- [FL-002](../flutter-limitations.md#fl-002): on web, Enter does not activate a
  plain `CupertinoButton`. `good-cupertino` adds an `Actions` entry for
  `ButtonActivateIntent` so Enter works there.
- [FL-006](../flutter-limitations.md#fl-006): on web any tappable node has the
  button role, which changes what `bad-gesture-only` shows there.
- [FL-008](../flutter-limitations.md#fl-008): in Chromium, VoiceOver reads an
  `IconButton`'s tooltip as a second item.
